# 유아·초등 학습 UX (만 4~9세 전후)

> 글을 아직 못 읽거나 막 읽기 시작한 아동용 학습 앱의 UX 원칙을 다룬다. 발달 관련 수치는 공식 지침으로 확인한 것만 적고, 나머지는 [가정]으로 표시한다.

## 핵심 요약

- 이 연령대는 **사용자(아동)와 구매·동의자(보호자)가 다르다.** 화면은 아동용, 결제·설정·외부 링크는 보호자용으로 나누고 그 사이에 **보호자 게이트**를 둔다.
- Apple 키즈 카테고리는 연령대(5세 이하, 6~8세, 9~11세)를 고르게 하고, 외부 링크·구매는 보호자 게이트 뒤에만 두게 하며, 제3자 분석·광고를 원칙적으로 금지한다. 글을 모르는 아동용이면 보호자를 부르라는 **음성 안내**를 권한다 (https://developer.apple.com/app-store/kids-apps/ ; https://developer.apple.com/app-store/review/guidelines/ 1.3, 5.1.4). [verified 2026-10-12]
- Google Play 가족 정책은 대상 연령 선언, 아동 전용 앱의 광고 ID(AAID) 전송·위치 권한 금지, 승인되지 않은 SDK 금지, 혼합 대상 앱의 중립적 연령 확인을 요구한다 (https://support.google.com/googleplay/android-developer/answer/9893335). [verified 2026-10-12]
- 스크린 타임: WHO는 1세 미만은 스크린 없음, 1세는 권장하지 않음, 2~4세는 앉아서 보는 스크린 시간을 하루 1시간 이하(적을수록 좋음)로 권고한다 (WHO 2019, https://www.who.int/publications/i/item/9789241550536). AAP는 2~5세에 하루 1시간의 양질 프로그램과 보호자 함께 보기를 권고한다 (2016 정책, 2차 출처 https://sites.gsu.edu/bestpractices/2016/10/26/american-academy-of-pediatrics-announces-new-recommendations-for-childrens-media-use). [verified 2026-10-12: WHO / AAP는 최신 개정 여부 확인 필요]
- 6~9세 대상의 공식 분 단위 권고는 확인하지 못했다 [확인 필요]. 세션 길이는 자체 데이터와 보호자 설정으로 정한다.

## 상세

### 프리리더(글을 아직 못 읽는 아동)

- **오디오 우선**: 모든 지시를 음성으로, 다시 듣기 버튼을 항상 같은 위치에. 텍스트는 보조.
- **아이콘·그림 중심**: 의미가 분명한 그림, 한 화면에 선택지 2~4개 [가정].
- 오류 피드백도 음성과 애니메이션으로, 실패를 벌처럼 보이게 하지 않는다.
- 아동이 글을 배우는 중이면 텍스트를 소리와 함께 하이라이트한다 ([[domain/레벨드리딩과영어독서]]).

### 터치와 운동 능력

- 접근성 최소 기준은 WCAG 2.2 SC 2.5.8 (목표 크기 최소 24×24 CSS px 또는 충분한 간격, AA) ([[domain/접근성]]). 아동은 소근육 조작이 서툴러 이보다 훨씬 크게 잡는 것이 일반적이다 [가정].
- 드래그·핀치·길게 누르기 같은 복잡한 제스처를 핵심 과제에 쓰지 않고, 탭 위주로.
- 실수 탭을 견디는 설계: 화면 가장자리에 중요한 버튼을 두지 않고, 되돌리기 제공.

### 주의 집중과 세션 길이

- 짧은 활동 단위(한 활동 몇 분 이내)와 명확한 끝 화면 [가정: 연령별 근거로 조정].
- 자동 재생으로 다음 콘텐츠를 계속 이어 붙이지 않는다. 끝을 보여 주고 보호자 설정 시간에 맞춰 쉬기 안내.
- 빠른 장면 전환·번쩍임·큰 소리는 피한다 (AAP 권고 취지, 위 출처).

### 보호자 게이트와 보호자 참여

- 게이트 대상: 결제, 외부 링크, 설정 변경, 개인정보 입력, 알림 수신 동의. 아동이 풀기 어려운 과제(문장형 질문, 계산 등)를 쓴다 (Apple 예시).
- Apple은 보호자 게이트가 개인정보 처리를 위한 **법정대리인 동의와 같은 것이 아니라고** 명시한다 (5.1.4). 동의는 별도로 받는다 ([[domain/아동개인정보보호]]).
- **함께 하기(co-play)**: 보호자와 같이 하는 활동, 보호자에게 오늘 배운 것 요약과 대화 질문 제공. AAP의 함께 보기 권고와 맞닿는다.
- 보호자 대시보드는 비교·순위 대신 아이 개인의 변화와 다음 할 일 ([[domain/수강생대시보드]]).

### 보상과 동기 (조작 없이)

- 권장: 활동 완료 축하, 수집형 스티커처럼 잃지 않는 보상, 자기 작품 모음.
- 피할 것: 끊기면 사라지는 스트릭, 무작위 보상 상자, 시간 제한 압박, 결제 유도 화면, 떠나려 할 때 죄책감을 주는 문구. 이런 패턴은 아동에게 특히 조작적이다 ([[domain/동기설계]]).
- 앱 내 구매는 보호자 게이트 뒤, 아동 화면에 가격 노출 최소화.

### 접근성

- 자막·음성 속도 조절, 색만으로 정보 전달 금지, 감각 자극 줄이기 옵션, 보조기기 호환 ([[domain/접근성]]).
- 발달 특성이 다양한 아동을 고려해 시간 제한 끄기 옵션.

### 아동 개인정보 보호 설계

- 계정 없이 시작 가능하게, 아동 이름 대신 닉네임·아바타, 사진·음성 업로드 최소화, 자유 채팅 금지 또는 사전 정의 문구만.
- 분석 도구는 제1자·익명 집계 위주. 키즈 카테고리·가족 정책상 제3자 SDK 제한을 B01 기술 선택 전에 확인한다.
- 만 14세 미만 동의, AI 기능 사용 시 고영향 여부 ([[domain/아동개인정보보호]]).

## 핵심 비즈니스 로직

- 결제자는 보호자, 사용자는 아동. 무료 체험 → 보호자 리포트로 가치 증명 → 구독 전환 흐름이 일반적이다 [가정].
- 형제 프로필, 가족 요금제, 기관(유치원·학원) 라이선스로 확장 ([[domain/세그먼트별의사결정구조]]).
- "For Kids" 같은 표현은 Apple 키즈 카테고리 앱만 메타데이터에 쓸 수 있다 (가이드라인 2.3.8, 5.1.4 인용). [verified 2026-10-12]

## 주요 화면·기능

- 아동: 프로필 선택(그림), 오늘의 활동, 활동 화면(큰 버튼·음성 안내), 끝 화면, 내 스티커·작품.
- 보호자(게이트 뒤): 리포트, 시간 설정, 콘텐츠 설정, 결제·구독, 개인정보·삭제 요청.

## 지표

| 구분 | 지표 |
|------|------|
| 학습 | 활동 숙달률, 반복 시도 후 성공, 보호자 관찰 체크 |
| 참여 | 주간 활동 일수, 세션 길이 분포(과다 사용 상위 구간 가드레일), 보호자 리포트 열람 |
| 품질 | 오탭률, 다시 듣기 사용, 활동 중도 이탈 지점 |
| 안전 | 보호자 게이트 우회 신고, 제3자 데이터 전송 0건 점검 |

## 규제·리스크

- 앱 마켓 정책 위반 시 심사 거절·삭제. 키즈 카테고리는 이후 업데이트에서도 기준을 계속 지켜야 한다 (Apple 1.3).
- 국내 법정대리인 동의, COPPA·GDPR 제8조(해외 출시) ([[domain/아동개인정보보호]]).
- 과다 사용 유도 설계는 평판·규제 리스크. 세션 길이를 가드레일 지표로 둔다.

## 에듀테크 PM 적용

**체크리스트**

- [ ] 아동 화면과 보호자 화면을 분리하고 게이트 대상 목록을 정한다 (E10)
- [ ] 모든 지시에 음성 안내와 다시 듣기를 둔다 (E08, E10)
- [ ] 터치 목표 크기·제스처 기준을 디자인 시스템에 넣는다 (B05)
- [ ] 스트릭·무작위 보상·이탈 방해 문구를 금지 패턴으로 명시한다 (E08)
- [ ] 키즈 카테고리·가족 정책 SDK 제한을 기술 선택 전에 확인한다 (B01, E13)
- [ ] 보호자 동의와 보호자 게이트를 별도로 구현한다 (E13)
- [ ] 세션 길이 분포를 가드레일 지표로 둔다 (E07)

**관련 산출물·유형**: AT07 + AT05. E07, E08, E10, E13, B01, B05, B06, P05, F01~F04, N01~N03(유아용 신규 앱).

## 흔한 오해

- "보호자 게이트가 있으면 부모 동의도 받은 것" — Apple도 둘이 다르다고 명시한다.
- "아이들은 게임처럼 보상이 많을수록 좋아한다" — 조작적 보상은 아동에게 더 해롭고 마켓 정책 위험도 있다.
- "어른 앱 버튼을 키우면 아이 앱" — 글 없이 이해되는 흐름과 보호자 분리가 핵심이다.
