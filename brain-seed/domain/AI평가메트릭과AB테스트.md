# AI 평가 메트릭과 A/B 테스트

> A06 AI평가결과보고서, F03 실험·출시계획서, E16 검증계획서를 쓸 때 참고. AI 평가는 세 층이다: **오프라인 평가**(출시 전, 평가셋), **온라인 실험**(출시 중, 실제 사용자), **학습 효과 검증**(기간을 두고, 학습 결과).

## 핵심 요약

- 오프라인 평가의 기반은 **골든셋**(질문-기대 답), **시나리오셋**(멀티턴), **E14 교육적 평가세트**(교수법 행동)와 **루브릭**이다. `ai_eval.py`가 이 세 파일을 실행·채점한다.
- **LLM 판정(LLM-as-judge)**은 사람 평가를 대신하는 것이 아니라 **사람 평가와 맞춰 본(보정한) 뒤에** 확장 수단으로 쓴다. Zheng et al. 2023은 강한 LLM 판정자가 사람 선호와 80% 넘게 일치했지만 위치·장황함·자기 선호 편향이 있다고 보고했다 (https://arxiv.org/abs/2306.05685, verified: 2026-10-12).
- 방식마다 지표가 다르다: 분류는 **정밀도·재현율·F1**, 검색은 **recall@k·MRR**, 생성은 **근거 충실도·도움 정도·교수법 루브릭**, 공통으로 **안전 위반률·지연 p95·원가**.
- 온라인은 **A/B 테스트**, 순위 비교는 **인터리빙**, 장기 효과는 **홀드아웃**. 참여 지표(사용 시간)와 **학습 결과 지표**(숙달·사후 검사)를 구분한다.
- 미성년 대상 실험은 **위험 최소화, 고지·동의 정책, 가드레일 지표 중단 기준**을 먼저 정한다.

## 상세

### 오프라인 평가 구성

| 요소 | 내용 |
|------|------|
| 골든셋 | 질문, 기대 답(또는 필수 포함 요소), 정답 근거 청크 ID, 난이도·학년·과목 태그 |
| 시나리오셋 | 사전조건(학습자 상태), 멀티턴 대화, 기대 행동(힌트 단계 준수, 교사 연결) |
| 안전셋 | 탈옥 시도, 개인정보 유도, 위기 신호, 연령 부적합 요청, 정답 조르기 |
| 루브릭 | 항목별 1~4점과 기준 문장, 합격선 |
| 출처 | 실제 학생 표현(가명화)으로 구성, few-shot 예시와 겹치지 않게 |

- 평가셋은 버전을 매기고, 운영에서 나온 실패 사례를 계속 추가한다 ([[domain/MLOps와LLMOps]]).

### 사람 평가와 평가자 일치도

- 루브릭 채점자 2명 이상이 같은 표본을 채점하고 **일치도**(Cohen's kappa 등)를 본다. 일치도가 낮으면 모델이 아니라 **루브릭이 모호한 것**이다.
- 교수법 항목(정답을 바로 줬는가, 오개념을 짚었는가)은 교사·교과 전문가가 채점한다 ([[domain/형성평가와피드백]]).

### LLM 판정 보정

1. 사람이 채점한 표본(예: 100건 [가정])을 만든다.
2. LLM 판정자로 같은 표본을 채점하고 사람 점수와 일치도를 잰다.
3. 불일치 사례를 보고 판정 프롬프트·루브릭을 고친다. 위치 편향은 비교 순서를 바꿔 두 번 판정해 줄인다.
4. 일치도 목표를 넘으면 확장 사용. 이후에도 정기적으로 표본 재보정.
- 안전 판정은 LLM 판정만으로 합격 처리하지 않는다. 안전 실패 의심 건은 사람이 본다.

### 방식별 지표

| 방식 | 지표 |
|------|------|
| M1 규칙 | 테스트 케이스 통과율, 오탐·미탐 사례 |
| M2 분류 | 클래스별 정밀도·재현율·F1, 혼동 행렬 ([[domain/고전NLP와정형응답]]) |
| M3·M4 검색 | recall@k, MRR ([[domain/RAG설계]]) |
| M4~M7 생성 | 근거 충실도, 답변 관련성, 도움 정도, 교수법 루브릭, 학년 적합성 |
| M5 과업 모델 | 과업별 지표(발음 점수와 전문가 점수 상관 등) |
| 공통 | 안전 위반률, 거절률(과잉 거절 포함), 지연 p50·p95, 요청당 원가 |

- 결과는 기능별로 "합격선 대비"로 보고한다. 평균만 보지 말고 **학년·과목·난이도별**로 나눠 약한 구간을 찾는다.

### 온라인 실험

| 방법 | 쓰임 | 주의 |
|------|------|------|
| A/B 테스트 | 새 프롬프트·모델·기능을 무작위 집단에 | 무작위 단위: 학생·반·학교. 같은 반 안에서 섞이면 오염 → 반·학교 단위 무작위 |
| 인터리빙 | 두 검색·추천 결과를 섞어 보여 주고 선택 비교 | 순위형 기능에 적합, 적은 표본으로 민감 |
| 홀드아웃 | 일부를 장기간 기능 미적용으로 유지 | 누적 효과·학습 결과 측정 |
| 단계 출시 | 비율을 늘려 가며 지표 확인 | 실험 대체가 아니라 위험 관리 |

### 학습 결과 vs 참여

- 참여 지표(세션 수, 대화 턴 수, 사용 시간)는 **학습 지표가 아니다**. 정답을 바로 주는 튜터는 참여와 연습 성과를 올리고 학습은 해칠 수 있다 ([[domain/AI튜터설계]]).
- 학습 결과: 사전·사후 검사, 지연 검사, 도움 없이 푼 문제 정답률, 숙달 도달 ([[domain/학습분석지표]], [[domain/효과크기와증거수준]]).

### 가드레일 지표 (실험 중단 기준)

- 안전 신고·차단률, 교사 신고, 학생 이탈·수신 거부, 지연 p95, 원가. 사전에 **중단 임계값**을 정하고 매일 본다.

### 표본 크기 기초

- 필요한 표본은 **기대 효과 크기, 결과 변수의 분산, 유의수준, 검정력**으로 정한다. 흔히 쓰는 근사: 집단당 n ≈ 16 × (표준편차/탐지할 차이)², 유의수준 5%·검정력 80% 기준 [가정: 근사식, 통계 검토 권장].
- 반·학교 단위 무작위는 집단 내 상관 때문에 학생 수보다 실질 표본이 작다 (설계 효과). 학교 실험은 통계 전문가 검토를 받는다.

### 미성년 대상 실험 윤리

- 한 집단에게 명백히 불리한 조건(안전 장치 제거)을 주지 않는다. 기존 수업을 대체하는 실험은 교사·학교 동의를 받는다.
- 고지·동의 범위는 학교·보호자 정책과 개인정보 처리 근거에 맞춘다 [확인 필요: 기관 IRB·교육청 절차] ([[domain/아동개인정보보호]]).
- 실험 데이터 최소 수집, 결과 공유 범위(학교에 개별 학생 점수 노출 금지 등)를 정한다.

## 에듀테크 맥락

- **K-12**: 반·학교 단위 무작위, 학사일정(시험·방학)에 따른 기간 설계 ([[domain/학사일정]]).
- **교사 승인**: 교사 평가를 루브릭 채점과 온라인 품질 신호로 함께 쓴다.
- **학습 효과 주장**: 마케팅·제안서의 효과 주장은 E17·E19 근거만 쓴다.

## 방식별 차이

위 "방식별 지표" 표 참조. 결정적 방식(M1·M2)은 정답 비교(`--judge exact`)로, 생성 방식은 루브릭·LLM 판정(`--judge llm`)으로 평가한다.

## 에듀테크 PM 적용

**체크리스트**

- [ ] 골든셋·시나리오셋·안전셋·루브릭과 합격선을 정하고 버전을 매긴다 (A06)
- [ ] LLM 판정 보정 결과(사람 대비 일치도)를 A06에 남긴다
- [ ] 방식별 지표와 학년·과목별 분할 결과를 보고한다
- [ ] 온라인 실험 설계(무작위 단위, 기간, 1차 지표, 가드레일 지표, 중단 기준)를 F03·E16에 적는다
- [ ] 학습 결과 지표와 참여 지표를 분리하고, 미성년 윤리 항목을 E13과 맞춘다

**관련 산출물**: A06(주), E14, E16, E17, F03, A11, A13.

## 흔한 오해

- "LLM 판정 점수가 올랐으니 좋아졌다" — 판정자 편향일 수 있다. 사람 표본으로 확인한다.
- "사용 시간이 늘었으니 효과가 있다" — 학습 결과로 확인해야 한다.
- "학생 단위로 무작위하면 된다" — 같은 반 안의 오염을 고려한다.
