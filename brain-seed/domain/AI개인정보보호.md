# AI 개인정보 보호 (LLM 호출 중심)

> **법률 자문이 아니다.** 일반 학습 데이터 쟁점(고용주 접근, 보존·파기, 학습자 권리)은 [[domain/학습데이터프라이버시]], 만 14세 미만·학교 선정 기준은 [[domain/아동개인정보보호]]에 있다. 이 페이지는 **AI 기능 때문에 새로 생기는 쟁점**만 다룬다.

## 핵심 요약

- AI 기능의 개인정보 위험은 대부분 **프롬프트 입력**에서 생긴다. 학생 이름, 글, 음성, 상담성 대화가 외부 모델로 그대로 전송되는 구조를 먼저 끊는다: 입력 최소화 → 개인정보 마스킹 → 전송 경로·업체 약관 확인.
- 해외 LLM API로 개인정보를 보내면 **국외 이전**(제공·처리위탁·보관) 요건을 검토한다. 허용 근거는 별도 동의, 법률·조약 특례, 계약 이행에 필요한 처리위탁·보관으로서 처리방침 공개 등, 이전받는 자의 인증, 보호 수준 동등성 인정이다 (개인정보 보호법 제28조의8 제1항, https://casenote.kr/법령/개인정보_보호법/제28조의8). [verified 2026-10-12]
- 완전 자동화된 결정이 권리·의무에 중대한 영향을 미치면 정보주체는 **거부·설명**을 요구할 수 있고, 처리자는 기준·절차를 공개해야 한다 (제37조의2, https://casenote.kr/법령/개인정보_보호법/제37조의2). [verified 2026-10-12] 조문 페이지에 "개정 2026. 9. 8." 표시가 있어 최신 개정 내용은 [확인 필요].
- 개인정보보호위원회는 2025.8.6. **「생성형 인공지능(AI) 개발·활용을 위한 개인정보 처리 안내서」**를 배포했다. 생애주기를 목적 설정 → 전략 수립 → 학습·개발 → 적용·관리 4단계로 나누고, 입출력 필터링·RAG 안전조치·이용 정책 공개·신고 창구·권리 보장과 CPO 중심 거버넌스를 권고한다 (신&김 뉴스레터 https://shinkim.com/kor/media/newsletter/2941 ; 바이라인네트워크 https://byline.network/2025/08/6-277/). [verified 2026-10-12: 2차 자료 기준] 원문 세부는 개인정보위 누리집(https://www.pipc.go.kr)에서 [확인 필요].

## 상세

### 입력 최소화와 마스킹

| 단계 | 통제 | 예 |
|------|------|----|
| 수집 | 기능에 필요한 필드만 프롬프트에 넣음 | 튜터에 실명·학교명 불필요 |
| 치환 | 이름·연락처·학번을 토큰으로 치환 후 응답에서 복원 | "학생A", "[이메일]" |
| 탐지 | 정규식(전화·주민번호·이메일) + 개체명 인식 | 자유 입력란 |
| 차단 | 민감정보(건강, 가족사 등)가 감지되면 외부 전송 중단 또는 로컬 경로 | 상담성 발화 |
| 로그 | 원문 로그 보존 최소화, 마스킹본 저장 | 디버깅 로그 |

- 마스킹은 완벽하지 않다. 오탐·미탐을 평가세트로 측정한다 (A14).

### 가명정보 (제28조의2)

- 통계 작성, 과학적 연구, 공익적 기록보존 등을 위해 정보주체 동의 없이 가명정보를 처리할 수 있고(①), 제3자 제공 시 특정 개인을 알아볼 수 있는 정보를 넣으면 안 된다(②) (https://casenote.kr/법령/개인정보_보호법/제28조의2). [verified 2026-10-12]
- 대화 로그로 자체 모델을 개선하려 할 때 "과학적 연구" 해당성은 사안별 판단이다 [확인 필요]. 상업 서비스 개선 목적이 자동으로 포함된다고 단정하지 않는다.

### 업체 데이터 이용 조건 (일반 점검 항목)

| 항목 | 질문 |
|------|------|
| 학습 이용 | API·기업 요금제 입력이 업체 모델 학습에 쓰이는가, 기본값과 옵트아웃 방법은? |
| 보존 | 남용 모니터링 목적 보존 기간, 무보존(zero retention) 옵션 유무 |
| 처리 지역 | 리전 선택, 하위 처리자 목록과 변경 통지 |
| 계약 | 데이터 처리 부속서(DPA), 위탁 계약 항목 |
| 소비자용 vs 기업용 | 교사 개인이 소비자용 챗봇에 학생 정보를 붙여넣는 경로 차단 |

- 업체별 약관은 수시로 바뀐다. 특정 업체의 "학습에 쓰지 않음" 주장은 계약 시점의 약관·DPA 원문으로 확인하고 E13에 날짜와 함께 기록한다 [확인 필요: 업체별].

### 국외 이전 정리 (제28조의8)

- 동의 근거로 할 때 미리 알릴 사항: 이전 항목, 국가·시기·방법, 이전받는 자(법인 명칭·연락처), 이용목적·보유기간, 거부 방법·절차·효과 (제2항). [verified 2026-10-12]
- 해외 리전 LLM을 처리위탁으로 쓰는 경우 계약 이행 필요성과 처리방침 공개 요건(제1항 제3호)을 검토한다. 학교·교육청 고객은 계약상 국외 이전 자체를 금지하는 경우가 있다 [가정: 계약별 확인].

### 자동화된 결정 (제37조의2)

- 해당 가능성: AI 레벨 테스트로 반 배정, 자동 채점으로 수료·환급 판정, 부정행위 자동 판정.
- 대응: 사람 재처리 경로, 결정 기준·절차 공개 화면, 설명 요청 접수 → 처리 흐름. 같은 기능이 AI 기본법 고영향(학생 평가)에도 걸리는지 함께 본다 ([[domain/AI윤리정책]]).

## 에듀테크 맥락

- **미성년**: 만 14세 미만은 법정대리인 동의 구조 위에서 AI 처리 목적을 별도로 고지한다. 아동이 자유 입력란에 주소·전화번호를 쓰는 일이 잦으므로 입력 탐지가 필수다 [가정].
- **학생 평가**: 학생 글·답안이 외부 모델 학습에 쓰이지 않음을 계약·설정으로 보장하고 교사·보호자에게 설명할 수 있어야 한다.
- **고객 요구**: 학교는 학습지원 소프트웨어 선정 기준(최소 수집, 목적·항목·보유기간 명시)을, 교육청은 국내 처리·보안 인증을, 기업은 사내 문서·임직원 데이터의 외부 전송 금지를 요구하는 경우가 많다 [가정: 개별 확인].

## 방식별 차이

| 방식 | 개인정보 특성 |
|------|---------------|
| 규칙·NLP | 내부 처리, 국외 이전 없음 |
| RAG | 검색 색인에 개인정보가 들어가면 다른 사용자에게 노출될 위험. 권한별 색인 분리 |
| 로컬 LLM | 외부 전송·국외 이전 문제를 크게 줄임. 서버 보안·접근 통제·로그 관리는 남음 |
| 클라우드 LLM | 국외 이전·업체 약관·보존 기간 점검 필요. 마스킹 후 전송 |

## 에듀테크 PM 적용

- [ ] 기능별 프롬프트 입력 필드 목록과 개인정보 여부를 E12·E13에 적는다
- [ ] 마스킹·차단 규칙과 오탐·미탐 기준을 A14에 둔다
- [ ] 업체 5개 점검 항목을 계약 시점 날짜와 함께 E13에 기록한다
- [ ] 국외 이전 근거와 처리방침 문구를 정한다 (P07)
- [ ] 자동화된 결정 해당 기능에 거부·설명·사람 재처리 흐름을 둔다 (P07, P05)
- [ ] 민감 대화는 로컬 모델 또는 비AI 경로로 라우팅할지 정한다 (A10, A11)
- [ ] 교사·직원이 소비자용 AI에 학생 정보를 넣지 않도록 내부 지침을 둔다
- [ ] 개인정보위 안내서 4단계 체크 항목과 대조한다 [확인 필요: 원문 체크리스트]

**관련 산출물**: P07(주), E13, A14, A10, A11, A04, A13(로그 보존), P09(장애 시 대체 경로가 다른 국가 리전으로 넘어가지 않게), E12.

## 흔한 오해

- "API 입력은 학습에 안 쓰이니 문제없다" — 학습 이용과 국외 이전·보존은 별개 쟁점이다.
- "이름만 지우면 익명" — 학교·학년·사건 서술로 재식별될 수 있다. 가명정보와 익명정보는 다르다.
- "로컬 LLM이면 개인정보 의무가 없다" — 처리 자체는 그대로이며 안전조치·보존·권리 보장 의무가 남는다.
