# MLOps와 LLMOps

> A13 AI운영(MLOps·LLMOps)설계서를 쓸 때 참고. AI 기능은 출시 후에 품질이 변한다. 학생 행동·교육과정·모델·데이터가 바뀌기 때문이다. **바뀐 것을 알아채고, 되돌리고, 고치는 체계**가 운영이다.

## 핵심 요약

- **고전 MLOps**(M2·M5, A09 같은 예측 모델): 데이터·특징·모델 **버전 관리**, 학습 파이프라인, **드리프트 감시**, 재학습.
- **LLMOps**(M4·M6·M7): **프롬프트·모델·지식베이스 버전 레지스트리**, CI에서의 평가 자동화, 요청 단위 **트레이싱**, 사용자 피드백 순환, **비용 감시**.
- 배포는 **단계 출시 + 즉시 롤백**이 기본. 무엇을 바꿨는지(프롬프트 v3, 모델 버전, 색인 날짜)가 모든 응답 로그에 남아야 롤백 판단이 가능하다.
- 관측 지표 5묶음: **품질, 안전, 지연, 비용, 사용량**.
- 아동 대상 서비스는 **사람 검토 대기열**(안전 신고, 저신뢰 응답, 교사 신고)이 운영의 중심이다.
- 작은 팀은 도구를 많이 들이기보다 **저장소 + 평가 스크립트 + 로그 테이블 + 주간 점검**으로 시작한다.

## 상세

### 고전 MLOps vs LLMOps

| 항목 | 고전 MLOps (M2·M5·예측) | LLMOps (M4·M6·M7) |
|------|------|------|
| 바뀌는 것 | 학습 데이터, 특징, 모델 가중치 | 프롬프트, 모델 버전(공급사 교체 포함), 지식베이스, 가드레일 규칙 |
| 버전 관리 | 데이터 스냅샷·특징 정의·모델 파일 | 프롬프트 파일·모델 식별자·색인 버전·임베딩 모델 |
| 평가 | 홀드아웃 지표(F1, AUC, precision@K) | 골든셋·시나리오셋 합격률, 루브릭, 안전 위반률 |
| 감시 | 입력 분포·예측 분포 드리프트, 성능 저하 | 응답 품질 표본, 근거 충실도, 거절률, 비용·지연 |
| 개선 | 재학습 | 프롬프트 수정, 지식베이스 갱신, 라우팅 변경, 모델 교체 |

### 고전 모델 운영 (A09형 예측 모델 등)

- **데이터·특징 버전**: 특징 SQL과 이벤트 정의를 저장소에 두고, 학습에 쓴 데이터 기간·스냅샷을 모델과 함께 기록 ([[domain/학습이탈예측]]).
- **학습 파이프라인**: 데이터 추출 → 검증(결측·분포) → 학습 → 평가 → 기준선 대비 비교 → 승인 → 배포. 수동이어도 절차를 문서화한다.
- **드리프트**: 학기·방학 계절성, 교육과정 개정, 서비스 UI 변경으로 입력 분포가 바뀐다. 월별 분포와 성능을 비교하고, 기준을 넘으면 재학습한다 ([[domain/학사일정]]).
- **재학습 주기**: 정기(학기마다) + 사건 기반(지표 하락). 개입이 행동을 바꾸면 모델 자체가 분포를 바꾸므로 대조군을 유지한다.

### LLMOps 구성

| 구성 | 최소 구현 [가정] |
|------|------------------|
| 레지스트리 | 저장소에 `prompts/`, `models.yaml`(기능별 모델 식별자), 지식베이스 색인 버전 기록 |
| CI 평가 | 프롬프트·모델·가드레일 변경 PR마다 `ai_eval.py`로 골든셋·안전셋 실행, 안전 실패 시 병합 차단 |
| 트레이싱 | 요청 ID별 입력(가명), 라우팅 경로, 검색 청크 ID, 프롬프트 버전, 모델, 토큰, 지연, 가드레일 판정, 출력 |
| 피드백 | 학생 엄지 평가, 교사 신고, 오류 신고 → 분류 → 평가셋에 추가 |
| 비용 감시 | 기능·기관·사용자별 일 원가, 예산 알림 ([[domain/LLM비용과토큰과금]]) |

- 트레이스에는 **학생 식별 정보를 남기지 않거나 가명 처리**하고 보존 기간을 정한다 ([[domain/학습데이터프라이버시]]).

### 배포와 롤백

1. 오프라인 평가 통과 → 2. 내부·교사 시범 → 3. 일부 트래픽(기관 단위 또는 비율) → 4. 전체.
- 기능 플래그로 프롬프트·모델·라우팅을 코드 배포 없이 전환하고, **이전 설정으로 즉시 되돌릴 수 있게** 한다 (F03 롤백 기준과 연결).
- 로컬 모델(M6)은 기관별 설치본 버전이 갈라지기 쉽다. 설치본 목록과 갱신 일정을 관리한다 ([[domain/로컬LLM과온프레미스]]).

### 관측 지표

| 묶음 | 지표 예 |
|------|---------|
| 품질 | 표본 루브릭 점수, 근거 충실도, 거절률, 재질문률, 학생·교사 평가 |
| 안전 | 가드레일 차단률, 안전 신고 수, 위기 신호 감지·연결 건수 ([[domain/AI가드레일설계]]) |
| 지연 | p50·p95·p99, 시간 초과율 |
| 비용 | 요청당·학습자당·기관당 원가, 캐시 적중률 |
| 사용량 | 기능별 요청 수, 라우팅 경로 비율, FAQ 해결률 |

### 사고 대응

- 사고 등급 예: **S1** 아동 안전·개인정보 노출·대규모 오답(즉시 기능 중단), **S2** 특정 기능 품질 급락(롤백), **S3** 지연·비용 이상(라우팅 조정) [가정].
- 절차: 감지 → 기능 중단 또는 롤백 → 영향 범위(어떤 학생·기관·기간) 파악 → 필요 시 기관·보호자 안내 → 원인 분석 → 평가셋에 재발 방지 케이스 추가. 개인정보 유출이면 법정 신고 절차를 확인한다 [확인 필요: 신고 기한·대상, [[domain/아동개인정보보호]]].

### 사람 검토 대기열

- 들어오는 것: 가드레일 저신뢰 판정, 안전 신고, 교사 신고, 자동 채점 애매 구간, 표본 품질 검토.
- 정할 것: 담당(운영자·교사·상담 인력), 처리 기한, 판정 기준, 판정 결과의 재사용(평가셋·규칙 보강). 검토자도 학생 데이터 접근 권한을 최소화한다.

### 작은 팀의 실용 구성

- 주 1회: 표본 50건 [가정] 사람 검토, 지표 대시보드 점검, 피드백 분류.
- 변경마다: CI 평가, 변경 이력 기록, 롤백 경로 확인.
- 학기 전: 전체 회귀 평가, 부하 시험, 지원 종료 예정 모델 확인 ([[domain/모델선택과라우팅]]).

## 에듀테크 맥락

- **K-12 학생 데이터**: 로그는 가장 큰 개인정보 저장소가 된다. 수집 최소화·가명화·보존 기간·접근 권한을 먼저 정한다.
- **학교망·수업 시간**: 수업 시간대 부하 집중, 학기 초 급증. 시험 기간 변경 동결.
- **교사 승인**: 교사 신고가 가장 가치 있는 품질 신호다. 신고 버튼과 처리 결과 회신을 만든다 ([[domain/교사참여설계]]).
- **학습 효과**: 운영 지표가 좋아도 학습 효과는 별도 평가가 필요하다 ([[domain/AI평가메트릭과AB테스트]]).

## 방식별 차이

| 방식 | 운영 핵심 |
|------|-----------|
| M1 | 규칙 테스트·변경 이력 |
| M2·M5 | 데이터·모델 버전, 드리프트, 재학습 |
| M3·M4 | 지식베이스 갱신, 색인 버전, 검색 지표 |
| M6 | 서빙 인프라, GPU, 설치본 버전 |
| M7 | 공급사 버전·지원 종료, 비용, 장애 대체 |

## 에듀테크 PM 적용

**체크리스트 (A13)**

- [ ] 버전 관리 대상(데이터·특징·모델·프롬프트·색인·가드레일)과 저장 위치를 정한다
- [ ] CI 평가 범위와 병합 차단 조건(안전 실패 0)을 정한다
- [ ] 트레이스 필드·가명화·보존 기간을 E13과 맞춘다
- [ ] 관측 지표·알림 임계값·사고 등급·롤백 절차를 적고 P08·P09와 연결한다
- [ ] 사람 검토 대기열의 담당·기한·기준을 정한다

**관련 산출물**: A13(주), A09, A06, A11, A12, A14, E13, F03, P08, P09.

## 흔한 오해

- "LLM은 학습을 안 하니 운영할 게 없다" — 프롬프트·모델·지식베이스가 계속 바뀐다.
- "로그는 많을수록 좋다" — 학생 데이터는 최소한만.
- "롤백은 코드 배포로" — 설정 전환으로 분 단위 롤백이 필요하다.
