# AI 화면 설계 5원칙 (에듀테크용)

## 핵심 요약

- 이 페이지는 AI 기능 화면을 검토할 때 쓰는 **5원칙**을 정의한다: ① 투명성, ② 통제권, ③ 기대치 관리, ④ 피드백 경로, ⑤ 안전한 실패. 공개 가이드라인(Microsoft HAX 18개, Google PAIR Guidebook)을 에듀테크 화면 검토용으로 압축한 이 Brain의 기준이다 [가정: 5개 구분은 자체 정리].
- 원칙마다 **학생·교사·보호자 화면 예**와 **안티 패턴**을 짝지어 둔다. E10 검토, 와이어프레임 리뷰, `/edpm-doc review` 패널 질문으로 쓴다.
- 에듀테크에서 다섯 원칙의 우선순위는 대상에 따라 달라진다: 미성년 학습자 화면은 ⑤ 안전한 실패와 ① 투명성이, 교사 도구는 ② 통제권이 가장 중요하다 [가정].

## 상세

### 5원칙 정의와 공개 가이드라인 대응

| 원칙 | 정의 | 대응하는 HAX 가이드라인 | PAIR 장 |
|------|------|------------------------|---------|
| ① 투명성 | AI가 만든 것임을 알리고, 왜 그런 결과인지 근거를 보여 준다 | G1 할 수 있는 일 알리기, G11 왜 그렇게 했는지 알리기 | Explainability + Trust |
| ② 통제권 | 사용자가 결과를 편집·중단·재생성·거부할 수 있다 | G7 쉽게 부르기, G8 쉽게 무시하기, G9 쉽게 고치기, G17 전체 설정 | Feedback + Control |
| ③ 기대치 관리 | 한계와 불확실성을 미리, 그리고 결과 옆에 표시한다 | G2 얼마나 잘하는지 알리기, G10 확신 없을 때 범위 좁히기, G18 변경 알리기 | Mental Models |
| ④ 피드백 경로 | 결과에 대해 평가·신고·정정할 수 있고, 반영 여부를 알 수 있다 | G15 세분화된 피드백, G13 사용자 행동에서 배우기 | Feedback + Control |
| ⑤ 안전한 실패 | 거절·오류·장애 때도 다음 행동이 있고, 해를 끼치지 않는다 | G10 범위 좁히기, G6 사회적 편향 줄이기, G5 사회 규범 맞추기 | Errors + Graceful Failure |

### ① 투명성

| 대상 | 좋은 예 | 안티 패턴 |
|------|---------|-----------|
| 학생 | 튜터 첫 화면 "나는 AI 도우미예요. 틀릴 수 있어요", 답변 아래 "교과서 42쪽 근거" | AI 캐릭터를 사람 선생님처럼 소개 |
| 교사 | 생성 문항마다 "AI 생성" 배지, 성취기준 근거 링크 | 생성물과 교사 작성 자료를 구분 없이 섞음 |
| 보호자 | 가정 통신문·앱 설정에 AI 사용 범위 안내 | 약관 깊은 곳에만 고지 |

- 고영향·생성형 AI 서비스는 AI 사용 사전 고지와 생성물 표시가 법적 의무다 (AI 기본법 제31조). 화면 원칙이면서 규제 요구다.

### ② 통제권

| 대상 | 좋은 예 | 안티 패턴 |
|------|---------|-----------|
| 학생 | 생성 중 정지 버튼, "다른 설명 보기", 힌트 단계 직접 선택 | 긴 답변이 끝날 때까지 기다려야 함 |
| 교사 | 채점 초안 일부 채택·수정, 반 단위 AI 끄기 | AI 결과를 그대로 반영하고 수정 불가 |
| 관리자 | 기관 단위 기능 켜기/끄기, 데이터 보관 설정 | 기능 끄기가 고객센터 요청으로만 가능 |

### ③ 기대치 관리

| 대상 | 좋은 예 | 안티 패턴 |
|------|---------|-----------|
| 학생 | "수학 풀이는 잘 도와주지만 그림 문제는 아직 서툴러요" 사전 안내 | 모든 질문에 같은 자신감 있는 어조 |
| 교사 | 서술형 채점 초안에 "확신 낮음" 표시 학생 분리 | 신뢰도 숫자(0.73)만 노출해 해석 불가 |
| 모두 | 모델 변경 시 "설명 방식이 바뀌었어요" 공지 | 예고 없이 답변 스타일 변경 |

### ④ 피드백 경로

| 대상 | 좋은 예 | 안티 패턴 |
|------|---------|-----------|
| 학생 | 답변마다 "도움됐어요/헷갈려요" 2버튼, 신고 | 별점 5단계 + 서술 의무 |
| 교사 | 수정 내용이 자동으로 품질 신호가 됨, "신고한 오류가 고쳐졌어요" 알림 | 신고해도 아무 회신 없음 |

- 상세는 [[domain/AI생성결과피드백UI]].

### ⑤ 안전한 실패

| 대상 | 좋은 예 | 안티 패턴 |
|------|---------|-----------|
| 학생 | 정답만 요구하면 "먼저 첫 단계를 같이 볼까?" + 힌트 | "요청을 처리할 수 없습니다" 한 줄 |
| 학생(위기 신호) | 대화 중단, 도움 기관 안내, 지정 교사 알림 | 일반 답변을 계속함 |
| 교사 | 모델 장애 시 템플릿 빈 양식으로 계속 작업 | 전체 도구 사용 불가 |

## 에듀테크 맥락

- 학생(특히 미성년): 쉬운 말 고지(개인정보 보호법 제22조의2 제3항의 취지), AI를 사람으로 오인하지 않게, 실패 시 학습이 끊기지 않게.
- 교사: 최종 책임자. 통제권과 근거가 없으면 사용하지 않는다 ([[domain/교사참여설계]]).
- 보호자: 투명성(무엇을 쓰는지)과 통제권(동의·철회)이 핵심.
- 관리자: 기관 단위 통제와 감사 가능성.

## 상태·예외

| 상황 | 해당 원칙 | 화면 처리 |
|------|-----------|-----------|
| AI 응답 지연 | ②③ | 진행 표시 + 정지, 예상 시간 안내 |
| 생성 실패 | ⑤ | 다시 시도 + 비AI 대안 |
| 거절 | ①⑤ | 이유 한 문장 + 대안 + 사람 연결 |
| 근거 없음 | ①③ | "자료에서 찾지 못함" 라벨, 추측 금지 |
| 한도 초과 | ③⑤ | 초기화 시점, 비AI 학습 계속 |
| 모델 장애 | ⑤ | 축소 모드 배너, 기록 열람 유지 |
| 콘텐츠 신고 | ④ | 신고 접수 확인 + 처리 결과 알림 |
| 상태 변화 알림 | 접근성 | 스크린리더에 상태 메시지 전달 (WCAG 4.1.3) |

## 에듀테크 PM 적용

- [ ] E10 AI 화면마다 5원칙 점검표를 붙였는가 (원칙별 예/아니오/해당 없음)
- [ ] ① 고지·라벨 문구가 P07과 일치하는가
- [ ] ② 정지·재생성·편집·끄기 위치가 화면마다 정해졌는가
- [ ] ③ 한계 안내와 불확실성 표시 방식이 A03에 있는가
- [ ] ④ 피드백 데이터가 A06·A13 평가 흐름으로 들어가는가
- [ ] ⑤ 거절·장애·위기 신호 처리가 A14·P08·P09와 같은가
- [ ] 와이어프레임 P0 검토 시 `sb-lowfi-pptx`·`sb-lowfi-figma` 산출물의 Description에 해당 원칙 번호를 적는다

## 흔한 오해

- "투명성은 'AI' 배지 하나면 된다" — 근거와 한계까지 보여야 신뢰가 조정된다.
- "통제권을 주면 사용자가 헷갈린다" — 정지·재생성·편집은 최소 장치다. 고급 설정은 숨기되 없애지 않는다.
- "실패 화면은 드물어서 나중에" — 생성형 AI는 실패·거절이 일상이다. 첫 와이어프레임부터 넣는다.
