# 고전 NLP와 정형 응답 (M1·M2)

> A10에서 "정답이 정해진 일"을 고를 때, A14 입력 필터를 만들 때 참고. 채점·출결·분류·추출처럼 **결정적이고 설명 가능한 답**이 필요한 곳은 생성형 LLM이 아니라 규칙(M1)과 고전 NLP(M2)가 기본이다.

## 핵심 요약

- **정형 응답이 필요한 일**: 채점(정답 비교·부분 점수), 출결·진도 판정, 문의 분류, 개체 추출(학년·과목·날짜·주문번호), 비속어·개인정보 탐지, 단답형 유사도 채점.
- 한국어는 **교착어**라 공백 단위 단어가 형태소 여러 개로 이루어진다. 키워드 매칭·검색·분류 전에 **형태소 분석**이 필요하고, 학생 입력은 **띄어쓰기·맞춤법 오류**가 많다.
- 의도 분류는 **TF-IDF + 로지스틱 회귀** 같은 단순 기준선부터 시작하고, 부족하면 문장 임베딩 + 분류기, 그다음 소형 파인튜닝(M5)으로 간다.
- 평가는 정확도 하나가 아니라 **클래스별 정밀도·재현율·F1과 혼동 행렬**로 본다. 비속어·위기어처럼 놓치면 안 되는 클래스는 재현율을 우선한다.
- LLM은 **저신뢰 구간의 대체 경로(fallback)**로 붙인다. 규칙·분류기가 확신할 때는 그 결과를 그대로 쓴다.

## 상세

### 정형 응답이 필요한 판단 기준

| 질문 | 예이면 |
|------|--------|
| 같은 입력에 항상 같은 답이어야 하나? | M1·M2 |
| 학생·학부모 이의 제기 때 근거를 보여 줘야 하나? | 규칙 근거·특징 가중치를 보여 줄 수 있는 방식 |
| 결과가 성적·출결·생활기록에 반영되나? | 결정적 방식 + 교사 확인 |
| 출력 형식이 고정(라벨, 숫자, 예/아니오)인가? | 분류·추출 |

### 한국어 처리 특이점

- **형태소 분석**: "풀었는데요" → 풀/VV + 었/EP + 는데/EC + 요/EF. 검색 색인·키워드 규칙은 원형(어간)과 명사 단위로 한다. 공개 분석기 예: Kiwi(kiwipiepy, Apache-2.0, 형태소 분석과 띄어쓰기 교정 제공, https://github.com/bab2min/kiwipiepy, verified: 2026-10-12), KoNLPy(여러 분석기 래퍼, https://konlpy.org/) [확인 필요: 각 분석기의 현재 유지 상태].
- **띄어쓰기**: 학생 입력 "광합성이뭐에요" 같은 붙여 쓰기가 흔하다. 형태소 분석 전에 띄어쓰기 교정을 하거나, 문자 n-gram 특징을 함께 쓴다.
- **맞춤법·구어체**: "됬어요", "몰겠어요", 초성("ㅇㅋ"), 이모티콘. 정규화 사전(오타 → 표준형)을 운영 데이터에서 계속 보강한다.
- **토크나이저**: 고전 NLP는 형태소 단위, 신경망 모델은 서브워드(BPE·SentencePiece) 단위. 같은 한국어 문장도 모델마다 토큰 수가 다르며, 이는 LLM 비용에도 영향을 준다 ([[domain/LLM비용과토큰과금]]).
- **교과 용어 사전**: "일차함수", "이산화탄소"처럼 붙어 있어야 하는 교과 용어를 사용자 사전에 넣지 않으면 잘게 쪼개진다. 교육과정 용어 목록을 사전 소스로 쓸 수 있다 ([[domain/교육과정지식그래프]]).

### 의도 분류 설계

1. **클래스 정의서**: 클래스마다 정의, 포함·제외 예, 경계 사례. "환불 문의"와 "결제 오류"의 경계를 미리 정한다.
2. **라벨링**: 실제 문의 로그에서 표본을 뽑아 2명 이상이 라벨링하고 일치도를 본다 ([[domain/AI평가메트릭과AB테스트]]).
3. **기준선**: 형태소 + TF-IDF + 로지스틱 회귀. 빠르고 CPU로 충분하며 특징 가중치로 설명 가능.
4. **개선**: 문장 임베딩 + 분류기, 데이터가 쌓이면 소형 모델 파인튜닝(M5).
5. **"기타·모름" 클래스와 신뢰도 임계값**: 임계값 미만은 FAQ 검색 또는 LLM, 사람에게 넘긴다.

### 단답형 유사도 채점

| 단계 | 방법 | 비고 |
|------|------|------|
| 1. 정규화 | 공백·조사·문장부호 제거, 동의어 사전("CO2"="이산화탄소") | M1 |
| 2. 정확 일치·허용 답 목록 | 교사가 등록한 허용 답과 비교 | 가장 많은 답을 처리 [가정] |
| 3. 핵심어 포함 규칙 | 필수 개념어 포함 여부, 부정어("아니다") 감지 | 부분 점수 |
| 4. 유사도 점수 | 문자 n-gram·임베딩 코사인 유사도 | 임계값은 교사 채점 표본으로 보정 |
| 5. 애매 구간 | 교사 확인 대기열 | 자동 확정 금지 |

- 서술형 루브릭 채점은 LLM이나 M5를 써도 **교사 확인 전 확정 점수로 쓰지 않는다** ([[domain/과제와평가설계]]).

### 정규식·규칙

- 개인정보 패턴(전화번호, 주민등록번호 형식, 이메일), 날짜·학년·반 추출, 금칙어. 규칙마다 **ID, 목적, 패턴, 양성·음성 테스트 예**를 둔다.
- 규칙은 코드처럼 관리한다: 저장소에 두고, 테스트를 붙이고, 변경 이력을 남긴다. 운영 로그에서 오탐·미탐 사례를 모아 주기적으로 갱신한다.

### 평가

- **혼동 행렬**로 어떤 클래스끼리 헷갈리는지 본다. **정밀도**(예측한 것 중 맞은 비율), **재현율**(실제 중 잡은 비율), **F1**(둘의 조화평균). 클래스 불균형이면 macro-F1도 본다.
- 클래스마다 비용이 다르다: 위기어 미탐 > 오탐, 자동 환불 처리 오탐 > 미탐. 임계값을 클래스별로 다르게 둔다.

### LLM 대체 경로와 결합

- 분류기 신뢰도 낮음 → LLM에 같은 클래스 목록으로 분류를 맡기거나 사람에게. LLM 분류 결과는 로그로 쌓아 다음 학습 데이터로 쓴다 (교사·운영자 확인 후).
- LLM이 생성한 답에도 M1 검증을 건다: 숫자 정답 재계산, JSON 스키마, 금칙어.

## 에듀테크 맥락

- **학생 데이터**: M1·M2는 서버나 기기 안에서 돌릴 수 있어 학생 글을 외부로 보내지 않는다. 학교 납품에서 큰 장점이다.
- **학교망**: 외부 API 없이 동작하므로 망 제약에 강하다.
- **교사 승인**: 채점 규칙·허용 답 목록을 교사가 편집하게 하면 신뢰가 오른다.
- **학습 효과**: 즉시·일관된 피드백이 가능하다 ([[domain/형성평가와피드백]]).

## 방식별 차이

| 과업 | M1 규칙 | M2 고전 NLP | M7 LLM |
|------|---------|-------------|--------|
| 객관식 채점 | 기본 | 불필요 | 쓰지 않음 |
| 단답형 채점 | 허용 답·핵심어 | 유사도 | 애매 구간 보조 |
| 문의 분류 | 키워드 초벌 | 기본 | 저신뢰 대체 |
| 개인정보 탐지 | 패턴 | 개체명 인식 | 보조 판정 |

## 흔한 오해

- "LLM이 나왔으니 고전 NLP는 끝났다" — 결정성·비용·로컬 실행이 필요한 곳에선 여전히 기본이다.
- "정확도 95%면 충분" — 드문 클래스(위기어)는 정확도에 묻힌다.
- "규칙은 한 번 만들면 끝" — 학생 표현은 계속 바뀐다.
