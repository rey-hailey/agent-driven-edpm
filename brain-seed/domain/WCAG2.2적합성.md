# WCAG 2.2 적합성

> [[domain/접근성]]의 학습앱 구현 체크리스트를 전제로, 이 페이지는 **적합성 범위·평가 계획·선언·조달 증빙**에 집중한다. 아래 제품 운영안은 실무 제안이다 [가정].

## 핵심 요약

- WCAG는 **인지 가능·운용 가능·이해 가능·견고함(POUR)**의 4원칙 아래 성취기준을 둔다. 적합성 등급은 A·AA·AAA이며, 상위 등급은 하위 등급 기준을 포함한다 (W3C WCAG 2.2, 서론·§5.2).
- **AA는 AA 항목만 통과한다는 뜻이 아니다.** A와 AA 기준, 전체 페이지·완전한 과정 등 적합성 요건을 모두 충족해야 한다 (W3C WCAG 2.2, §5.2).
- WCAG는 자동 검사와 사람의 평가를 결합해 시험하도록 설계됐다. 도구 점수만으로 적합성을 선언하지 않는다 (W3C WCAG 2.2, 서론·§5).
- **VPAT는 양식**, 작성된 제품별 문서는 **ACR(Accessibility Conformance Report)**다. ITI가 이를 심사·인증하는 것은 아니다 (ITI VPAT 공식 안내·FAQ).

## 상세

### 목표 등급과 평가 범위

| 항목 | 계획에 적을 것 |
|------|----------------|
| POUR | 인지 가능(Perceivable), 운용 가능(Operable), 이해 가능(Understandable), 견고함(Robust) 각각의 성취기준 |
| A | 모든 A 기준 충족 또는 규정에 맞는 적합한 대체 버전 |
| AA | 모든 A·AA 기준 충족 또는 규정에 맞는 적합한 대체 버전 |
| AAA | 모든 A·AA·AAA 기준 충족 또는 규정에 맞는 적합한 대체 버전 |

출처: W3C WCAG 2.2, 서론·§5.2.1. W3C는 일부 콘텐츠에서 모든 AAA 기준을 충족할 수 없으므로 **전체 사이트에 AAA를 일반 정책으로 요구하는 것은 권하지 않는다** (같은 절).

적합성에는 등급 외에도 다음 요건이 있다 (W3C WCAG 2.2, §5.2.2~5.2.5).

- **전체 페이지**: 일부 위젯만 떼어 합격 처리할 수 없다. 반응형 화면의 변형도 포함한다.
- **완전한 과정**: 활동 완료까지 연결된 과정의 모든 페이지가 해당 등급 이상이어야 한다.
- **접근성 지원 방식**: 기준 충족에 의존하는 기술 사용 방식이 접근성을 지원해야 한다.
- **비간섭**: 적합성 확보에 의존하지 않는 콘텐츠도 나머지 페이지 사용을 방해해서는 안 된다.

제품 명세에는 학생·교사·관리자 역할, 인증 상태, 웹 경로, 반응형 변형, 첨부·외부 콘텐츠, 핵심 과정을 목록화한다. 예를 들어 **로그인 → 문제 풀이 → 제출 → 결과 확인**을 끊지 않고 시험한다 [가정: 학습 서비스 평가 범위 제안].

### 2.2 신규 성취기준을 증빙 항목으로 바꾸기

2.2는 2.1에 아래 9개 기준을 추가하고 4.1.1 Parsing을 제거했다. 다른 판본도 계약 준거라면 해당 판본의 평가 요구를 별도로 확인한다 (W3C WCAG 2.2, *Comparison with WCAG 2.1*, *New Features in WCAG 2.2*).

| 번호·등급 | 공식 이름 | 남길 평가 증빙 예 [가정] |
|-----------|-----------|-------------------------|
| 2.4.11 AA | Focus Not Obscured (Minimum) | 고정 UI가 포커스 요소를 전부 가리는지 상태별 확인 |
| 2.4.12 AAA | Focus Not Obscured (Enhanced) | 포커스 요소 일부 가림까지 확인 |
| 2.4.13 AAA | Focus Appearance | 포커스 표시의 면적·대비와 예외 검토 기록 |
| 2.5.7 AA | Dragging Movements | 드래그 없이 단일 포인터로 완료하는 대안 경로 |
| 2.5.8 AA | Target Size (Minimum) | 대상 크기·간격과 예외 적용의 측정 기록 |
| 3.2.6 A | Consistent Help | 반복되는 도움 수단의 상대적 순서 비교 |
| 3.3.7 A | Redundant Entry | 같은 과정의 재입력 요구·자동 채움·예외 검토 |
| 3.3.8 AA | Accessible Authentication (Minimum) | 인증의 인지 기능 테스트와 허용 대안·보조 수단 확인 |
| 3.3.9 AAA | Accessible Authentication (Enhanced) | 강화 기준의 인증 예외 범위까지 확인 |

기준명·번호·등급의 출처: W3C WCAG 2.2. 표는 시험 설계 예이며, 각 기준의 본문·예외를 대체하지 않는다. 특히 **키보드 대안만으로 2.5.7의 단일 포인터 대안을 대신하지 않는다** (W3C WCAG 2.2, 2.5.7).

### 평가 방법: 자동 + 수동 + 보조기술 사용자 테스트

아래는 자동·사람 평가를 결합한다는 W3C 원칙을 적용한 **권장 운영안**이다 [가정]. 사용자 테스트 참여 자체를 WCAG의 별도 필수 성취기준처럼 쓰지 않는다.

| 방법 | 확인할 것 | 증빙 |
|------|-----------|------|
| 자동 검사 | 기계로 검출 가능한 마크업·이름·일부 대비 등의 문제 | 도구·버전·대상 경로·실행 일시·원 결과 |
| 전문가 수동 평가 | 키보드 순서·트랩, 대체 텍스트의 의미, 오류 복구, 확대·반응형·동적 상태 | 성취기준별 판정·재현 절차·화면 상태 |
| 보조기술 조합 시험 | 스크린리더·브라우저·OS 조합에서 의미·상태·조작 확인 | 제품·보조기술 버전, 실제 과업 수행 기록 |
| 장애가 있는 사용자 테스트 | 실제 보조기술 사용자에게 핵심 학습 과업을 맡겨 장벽 확인 | 사용 환경·과업·막힌 지점·개선·재확인 |

사용자가 과업을 마쳤다는 결과와 성취기준별 적합 판정은 분리한다. 대표 페이지를 평가했더라도 미검사 범위를 포함한 전체 서비스 적합성을 자동 추론하지 않는다 [가정: 증거 해석 원칙; 전체 페이지·과정 요건은 W3C §5.2].

### 적합성 선언과 평가 보고서

**적합성 선언 자체는 선택 사항**이다. 선언한다면 다음 5가지를 포함해야 한다 (W3C WCAG 2.2, §5.3.1).

1. 선언 날짜.
2. 지침 제목·버전·URI: *Web Content Accessibility Guidelines 2.2*, https://www.w3.org/TR/WCAG22/
3. 충족하는 등급(A·AA·AAA).
4. 적용 웹 페이지의 간결한 설명: URI 목록·범위 표현, 하위 도메인 포함 여부 등.
5. 적합성을 위해 의존하는 웹 콘텐츠 기술 목록.

평가 보고서에는 제품 빌드·평가자·환경·성취기준별 결과·미해결 결함·수정 및 재시험 이력을 추가한다 [가정: 증빙 관리 제안]. 일부 기준을 미충족한 상태를 "AA 대부분 충족"이라는 합격 선언으로 바꾸지 않는다. 제3자 콘텐츠에 대한 부분 적합성 진술도 완전한 적합성 선언과 다르다 (W3C WCAG 2.2, §5.2·§5.4).

### 조달 증빙: VPAT와 ACR

- **VPAT(Voluntary Product Accessibility Template)**는 제품의 접근성 기준별 지원 정도와 설명을 적는 양식이다. 작성된 ACR은 구매자의 제품 비교·조달 판단을 돕는다 (ITI VPAT 공식 안내).
- 판정은 Supports·Partially Supports·Does Not Support·Not Applicable 등으로 기록하며, 평가 방법과 구체적인 설명을 함께 제공한다 (ITI VPAT 공식 안내).
- ITI는 VPAT를 검토·승인하지 않으며 **VPAT 인증도 없다**. 조달 공고가 제3자 검토를 요구하는지는 별도로 확인한다 (ITI VPAT FAQ).
- 계약에서 요구하는 표준·양식 판본을 선택하고 제품 버전·범위·평가 일자·미지원 사유·개선 계획을 맞춘다 [가정: 조달 대응 제안]. WCAG·유럽·미국 기준을 다루는 VPAT 판본은 서로 포함 기준이 다를 수 있다 (ITI VPAT 공식 안내).

### 한국 KWCAG와의 관계

- **KWCAG(한국형 웹 콘텐츠 접근성 지침)**의 국내 맥락은 [[domain/접근성]]을 함께 본다. 이 페이지는 국내 표준의 최신 판본·표준번호·검사항목 수·인증 요건을 확정하지 않는다 [확인 필요: 국가표준 원문과 해당 조달·인증 지침].
- "WCAG 2.2 AA 평가 결과 = KWCAG 적합·국내 인증"으로 간주하지 않고, 계약이 지정한 국내 준거의 **판본·항목·증빙 요구를 따로 대조**한다 [가정: 조달 계획 원칙].
- 대응표는 `국내 기준 번호·판본 → WCAG 성취기준 → 공통 증빙 → 추가 검사 → 미확인 사항`으로 관리한다 [가정]. 확인 경로는 국가기술표준원 e나라표준인증(https://www.standard.go.kr/)과 해당 발주·인증 기관의 공개 문서다. 포털 주소 자체는 개별 기준 충족의 근거가 아니다.

## 에듀테크 PM 적용

**체크리스트 (E13·E16)** — 실무 제안 [가정].

- [ ] 목표 WCAG 판본·등급·역할·URL·전체 학습 과정을 먼저 고정한다
- [ ] 자동·수동·보조기술 조합·사용자 테스트의 범위와 담당을 나눈다
- [ ] 신규 9개 기준뿐 아니라 목표 등급의 기존 기준도 평가한다
- [ ] 문항 렌더러·인증·플레이어·외부 위젯·학습 콘텐츠까지 증거 범위에 넣는다
- [ ] 선언 필수 항목과 평가 보고서·ACR의 제품 버전·범위를 일치시킨다
- [ ] 국내 납품은 KWCAG 준거·대응표·추가 증빙의 미확인 항목을 해소한다
- [ ] 릴리스에서 바뀐 화면·콘텐츠·핵심 과정을 재시험하고 결함 기록을 갱신한다

**관련 산출물**: E13, E15, E16, E17, S01, S02.

## 흔한 오해

- "자동 도구 100점이면 AA 적합" — WCAG는 자동 검사와 사람의 평가를 결합하는 기준이다 (W3C WCAG 2.2, 서론).
- "접근 가능한 위젯을 붙이면 서비스 전체도 적합" — 전체 페이지·완전한 과정 요건이 있다 (W3C WCAG 2.2, §5.2).
- "VPAT가 있으면 인증을 받은 것이다" — 작성된 보고서이며 ITI의 인증이 아니다 (ITI VPAT FAQ).
- "AAA면 모든 장애 사용자의 필요를 충족한다" — WCAG는 최고 등급도 모든 필요를 다루지는 못한다고 명시한다 (W3C WCAG 2.2, 서론).
