# 프롬프트 입력 UX (빈 입력창을 줄이는 법)

## 핵심 요약

- 사용자는 "무엇을 물어야 할지" 모른다. 빈 입력창은 학생에게는 정답 요청을, 교사에게는 결과 편차를 낳는다. 입력 UX의 목표는 **자유 입력을 줄이고 맥락을 자동으로 채우는 것**이다 [가정].
- 입력 방식은 4단계로 고른다: ① 버튼·칩 선택, ② 템플릿(빈칸 채우기), ③ 구조화 폼, ④ 자유 입력. 대상이 어릴수록, 결과 품질 편차가 클수록 앞 단계를 쓴다.
- 학생 입력에는 이름·전화번호·학교·사진 속 얼굴 같은 개인정보가 섞인다. **입력 시점 경고 + 서버 측 마스킹**(A14)을 같이 둔다.
- 글자 수·첨부 용량·남은 사용량은 입력 전에 보여 준다. 보낸 뒤 거절하면 입력을 잃는다.

## 상세

### 입력 방식 선택

| 방식 | 언제 | 학생 예 | 교사 예 |
|------|------|---------|---------|
| ① 버튼·칩 | 가능한 요청이 몇 개로 정해짐, 저학년 | [힌트 줘] [예시 보여 줘] [다시 설명] | [쉽게 바꾸기] [문항 하나 더] |
| ② 템플릿 | 문장 틀이 반복 | "___ 개념을 ___ 예시로 설명해 줘" | "___ 단원 ___ 난이도 문항 ___개" |
| ③ 구조화 폼 | 필수 정보가 여러 개, 결과 형식이 중요 | 글쓰기 과제 제출(주제·장르·분량) | 학습지 생성(성취기준·유형·수량·난이도) |
| ④ 자유 입력 | 열린 질문, 고학년·성인 | 개념 질문 | 추가 지시 |

### 입력 영역 컴포넌트

| 컴포넌트 | 설계 포인트 |
|----------|-------------|
| 입력창 | 여러 줄 자동 확장, Enter 전송·Shift+Enter 줄바꿈(모바일은 전송 버튼), 보이는 라벨 (WCAG 3.3.2) |
| 플레이스홀더 | 예시 질문 형태("예: 이 식에서 x를 어떻게 구해?"). 플레이스홀더를 라벨 대신 쓰지 않음 |
| 시작 질문(starter) | 맥락별 3~4개 칩. 학생용은 학습 행동형, 교사용은 작업형 |
| 템플릿 | 빈칸을 입력 필드로, 빈칸 채우면 미리보기 문장 |
| 구조화 폼 | 필수·선택 구분, 기본값(프로필 학년·담당 반), 이전 값 재사용 (WCAG 3.3.7 중복 입력) |
| 맥락 칩 | 현재 과목·과제·단원이 칩으로 표시, 눌러서 변경 |
| 첨부 | 사진(문제 촬영), 파일(PDF·한글), 음성. 형식·용량 사전 표시, 업로드 진행률 |
| 글자 수·한도 | "320/1000자" 표시, 한도 근접 시 색+텍스트 경고. 토큰 대신 글자 수로 [가정] |
| 남은 사용량 | "오늘 질문 8회 남음" 입력창 근처 ([[domain/사용량대시보드설계]]) |
| 프롬프트 제안 | 입력 중 자동완성은 학습 질문 품질을 높이는 방향으로("어디까지 풀었는지도 적어 줘") |
| 개인정보 경고 | 전화번호·주민번호·이메일 패턴 감지 시 전송 전 경고 + 지우기 버튼 |
| 음성 입력 | 인식 결과를 입력창에 넣고 확인 후 전송 |

### 개인정보 입력 방지

| 층 | 처리 | 담당 |
|----|------|------|
| 사전 안내 | 첫 사용 시 "이름·전화번호·주소는 적지 마세요" (아동은 쉬운 말) | P07, 제22조의2 제3항 |
| 입력 중 감지 | 정규식 패턴(전화·이메일·주민번호) 감지 → 전송 전 경고 | 클라이언트 |
| 사진 첨부 | 얼굴·이름표 감지 시 "사진에 얼굴이 있어요. 문제 부분만 찍어 주세요" + 자르기 | 클라이언트·서버 [가정] |
| 서버 마스킹 | 모델 호출 전 마스킹, 로그 저장 전 마스킹 | A14 |
| 기록 | 마스킹 이벤트 수를 운영 지표로 | 백오피스 |

### 연령별 입력 규칙

| 항목 | 초등 저학년 | 초등 고학년·중학 | 고등·성인·교사 |
|------|-------------|------------------|----------------|
| 기본 입력 | 버튼·음성 | 칩 + 짧은 텍스트 | 텍스트·폼 |
| 자유 입력 길이 | 짧게 제한 [가정] | 중간 [가정] | 길게 |
| 첨부 | 보호자·교사 허용 시 사진만 | 사진 | 사진·문서·음성 |
| 개인정보 경고 | 그림·쉬운 문장 | 쉬운 문장 | 일반 |

## 에듀테크 맥락

- 학생: 좋은 질문을 하는 법 자체가 학습이다. 제안 문구가 "어디까지 풀었는지 적기", "왜 헷갈리는지 적기"를 유도하면 메타인지를 돕는다 [가정] ([[domain/형성평가와피드백]]).
- 교사: 폼과 템플릿이 생성 결과 편차와 검토 시간을 줄인다 ([[domain/생성형AI서비스IA]]).
- 보호자: 아동 입력 제한과 첨부 허용을 설정에서 확인.
- 관리자: 기관 공용 템플릿과 금지 입력 규칙 관리.

## 상태·예외

| 상황 | 처리 |
|------|------|
| 입력 비어 있음 | 전송 버튼 비활성, 시작 질문 칩 표시 |
| 글자 수 초과 | 전송 전 안내, 입력 보존 |
| 첨부 실패·형식 불가 | 이유와 허용 형식, 재시도 |
| 개인정보 감지 | 전송 전 경고 + 지우기/그래도 보내기(성인만) [가정] |
| AI 응답 지연 | 입력창 잠금 대신 정지 버튼으로 전환 |
| 거절(입력 단계 차단) | 어떤 부분이 문제인지 한 문장 + 고쳐 쓰기 예시 |
| 한도 초과 | 입력창 비활성 + 초기화 시점 + 비AI 대안 |
| 모델 장애 | 입력은 받되 "지금은 답하기 어려워요" + 선생님께 넘기기 |
| 오프라인 | 입력 임시 저장, 연결 시 전송 확인 |

## 에듀테크 PM 적용

- [ ] 기능마다 입력 방식(①~④)을 정하고 근거를 E10에 적었는가
- [ ] 시작 질문·템플릿 문구가 A03 프롬프트 설계와 같은 변수를 쓰는가
- [ ] 개인정보 감지 패턴과 서버 마스킹이 A14에 있고 고지 문구가 P07에 있는가
- [ ] 글자 수·첨부 한도·남은 사용량 표시가 P09 한도와 일치하는가
- [ ] 입력 라벨·오류 안내·중복 입력 방지가 E13 (c)에 있는가
- [ ] 와이어프레임 P0: 학생 입력(칩+텍스트), 교사 생성 폼, 개인정보 경고, 첨부 업로드, 한도 근접 상태

## 흔한 오해

- "자유 입력이 가장 유연하다" — 학생·교사 다수는 무엇을 쓸지 몰라 결과 편차가 커진다.
- "개인정보는 서버에서 지우면 된다" — 입력 시점 안내가 없으면 학생은 계속 적는다. 두 층이 필요하다.
- "토큰 한도를 보여 주면 된다" — 사용자는 토큰을 모른다. 글자 수·횟수로 번역한다.
