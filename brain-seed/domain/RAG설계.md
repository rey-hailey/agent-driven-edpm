# RAG 설계 (M4)

> A01 지식베이스설계서와 A02 검색·RAG설계서를 쓸 때 참고. RAG 품질 문제의 대부분은 **생성이 아니라 검색**에서 생긴다. 프롬프트를 고치기 전에 검색을 평가한다.

## 핵심 요약

- 파이프라인: **수집(ingest) → 청크 분할 → 임베딩 → 색인 → 검색 → 리랭킹 → 생성 → 인용**. 단계마다 실패 지점과 평가 지표가 다르다.
- **하이브리드 검색**(BM25 키워드 + 벡터 의미 검색)이 한국어 교과 용어·고유명사에 강하다. 두 결과는 순위 기반 융합(RRF 등)으로 합친다.
- **메타데이터 필터**(학년·과목·단원·교육과정 버전·출판사·권리 만료일)를 검색 전에 건다. 중1 학생에게 고2 내용이 근거로 나오는 것을 막는 가장 싼 방법이다.
- 평가는 두 층: 검색(**recall@k, MRR**)과 생성(**근거 충실도 faithfulness/groundedness, 답변 관련성**). Ragas는 이 축을 자동 평가하는 공개 프레임워크다 (https://arxiv.org/abs/2309.15217, verified: 2026-10-12).
- 답이 FAQ처럼 고정돼 있으면 RAG가 아니라 **M3 검색**, 문서 근거가 필요 없는 열린 대화면 M7, 지식이 작고 고정이면 프롬프트에 통째로 넣는 편이 나을 수 있다.

## 상세

### 파이프라인과 설계 결정

| 단계 | 결정 | 에듀테크 기본값 [가정] |
|------|------|------------------------|
| 수집 | 소스 목록, 권리 확인, 갱신 주기 | 자사 교재·해설·FAQ. 권리 미확인 자료 제외 ([[domain/교육저작권]]) |
| 정제 | PDF·HWP·이미지 텍스트화, 수식·표 처리 | 수식은 LaTeX 보존, 표는 행 단위 텍스트 + 원본 링크 |
| 청크 분할 | 단위(단원·소단원·문항), 크기, 겹침 | 의미 단위(소단원·개념·문항+해설) 우선, 고정 길이는 보조 |
| 메타데이터 | 학년·과목·단원·성취기준 코드·버전·출처 페이지 | 성취기준 코드로 교육과정과 연결 ([[domain/교육과정지식그래프]]) |
| 임베딩 | 모델, 차원, 다국어 지원 | 한국어 평가셋으로 후보 비교 |
| 색인 | 벡터 DB + 키워드 색인 | 하이브리드 |
| 검색 | top-k, 필터, 질의 재작성 | 학년·과목 필터 필수 |
| 리랭킹 | 교차 인코더·LLM 리랭커 | top-20 → top-5 [가정] |
| 생성 | 근거만 사용 지시, 모르면 모른다고 | [[domain/프롬프트엔지니어링]] |
| 인용 | 청크 ID → 교재명·쪽·단원 | 학생 화면에 출처 표시 |

### 하이브리드 검색

- **BM25**(키워드): "광합성", "피타고라스 정리"처럼 정확한 용어 일치에 강하다. 한국어는 형태소 분석 후 색인해야 조사 붙은 형태도 잡힌다 ([[domain/고전NLP와정형응답]]).
- **벡터**: "식물이 햇빛으로 양분 만드는 거"처럼 학생식 표현에 강하다.
- **융합**: 순위 기반 융합(Reciprocal Rank Fusion)은 점수 척도가 달라도 합칠 수 있어 많이 쓰인다. 가중치는 평가셋으로 조정한다.

### 한국어 임베딩 고려

- 다국어 임베딩 모델과 한국어 특화 모델의 성능 차이는 도메인마다 다르다 [확인 필요: 공개 한국어 검색 벤치마크 현행 순위]. **자사 교재 질의-정답 청크 쌍으로 recall@k를 직접 비교**한다.
- 학생 질문은 구어·오타가 많으므로 평가 질의도 실제 학생 표현으로 만든다. 교재 문장으로만 만든 평가셋은 성능을 부풀린다.
- 임베딩 모델을 바꾸면 전체 재색인이 필요하다. 모델 버전을 색인 메타데이터에 기록한다 ([[domain/MLOps와LLMOps]]).

### 평가 지표

| 층 | 지표 | 의미 |
|----|------|------|
| 검색 | recall@k | 정답 청크가 상위 k개 안에 있는 질문 비율 |
| 검색 | MRR | 정답 청크 순위의 역수 평균 (빨리 나올수록 높음) |
| 생성 | 근거 충실도 | 답의 주장이 검색된 문서로 뒷받침되는 비율 |
| 생성 | 답변 관련성 | 질문에 실제로 답했는가 |
| 생성 | 인용 정확도 | 표시한 출처가 실제 근거인가 |
| 교육 | 학년 적합성·교수법 | 수준에 맞는가, 정답을 바로 주지 않는가 ([[domain/AI튜터설계]]) |

- 골든셋(`A.AI/골든셋.csv`)에 질문, 기대 답, **정답 청크 ID**를 함께 적어야 검색 지표를 따로 잴 수 있다.

### 흔한 실패 유형

| 증상 | 원인 | 대응 |
|------|------|------|
| 엉뚱한 학년·교육과정 근거 | 필터 없음 | 메타데이터 필터 |
| 정답이 문서에 있는데 못 찾음 | 청크가 너무 크거나 표·수식 깨짐 | 청크 재설계, 정제 개선 |
| 근거가 있는데 답이 틀림 | 긴 문맥 중간 정보 무시, 상충 문서 | 리랭킹으로 근거 수 축소. 긴 입력 중간에 있는 정보를 덜 활용한다는 연구가 있다 (Liu et al. 2023, https://arxiv.org/abs/2307.03172, verified: 2026-10-12) |
| 문서에 없는 내용을 지어냄 | "모르면 모른다" 지시·검증 없음 | 근거 확인 가드레일, 저신뢰 시 거절 |
| 옛 교재 내용 | 버전 관리 없음 | 버전 메타데이터, 만료 처리 |
| 질문이 모호 | 대화 맥락 미반영 | 질의 재작성(이전 턴 포함) |

## 에듀테크 맥락

- **K-12 학생 데이터**: 지식베이스에는 공개·자사 교재만 넣고 학생 개인 데이터는 넣지 않는다. 학습자 메모리는 A04에서 따로 다룬다.
- **교육과정 정합**: 성취기준 코드 메타데이터가 있으면 "이 학생 학년 범위 안에서만" 검색할 수 있다.
- **교사 승인**: 교사가 업로드한 학급 자료를 지식베이스에 넣을 때는 권리·검수 절차와 학급 범위 필터가 필요하다.
- **권리**: 출판사 교재는 계약상 AI 활용 범위를 확인한다 ([[domain/강사계약과콘텐츠권리]]).

## 방식별 차이

| 상황 | 권장 |
|------|------|
| 고정된 답 (환불 규정, 로그인 방법) | M3 FAQ 매칭 |
| 문서 근거가 필요한 설명 | M4 RAG + M7 또는 M6 생성 |
| 지식이 작고 거의 안 바뀜 | 프롬프트에 통째로 (P3 노코드 점검: `ai_eval.py --context`) |
| 학생 데이터 기반 리포트 | RAG보다 SQL 조회 + 생성(구성 요소 데이터조회·생성물, A05) |
| 민감 문서 | 색인·생성 모두 내부망(M6) |

## 흔한 오해

- "RAG면 환각이 없다" — 검색이 틀리면 그럴듯한 오답이 나온다.
- "벡터 DB만 있으면 된다" — 한국어 용어 검색은 키워드 색인이 함께 필요하다.
- "top-k를 늘리면 좋아진다" — 근거가 많을수록 혼란·비용이 늘 수 있다.
