# 수료증과 디지털 크레덴셜

## 핵심 요약

- 수료증의 가치는 **"제3자가 진짜인지 쉽게 확인할 수 있는가"** 와 **"무엇을 했는지 구체적으로 말하는가"** 에서 나온다. PDF 한 장은 둘 다 약하다.
- **Open Badges 3.0**(1EdTech)은 최종 릴리스이며 **W3C Verifiable Credentials Data Model v2.0** 관례에 맞춘다 (https://www.imsglobal.org/spec/ob/v3p0, 문서 버전 1.4.5, 2026-06-29 발행) [verified 2026-10-12]. VC Data Model 2.0은 2025-05-15 W3C 권고안(Recommendation)이다 (https://www.w3.org/TR/vc-data-model-2.0/) [verified 2026-10-12].
- 블록체인은 "위변조 방지"를 위한 여러 수단 중 하나일 뿐이다. 대부분의 경우 **발급자 서명된 VC 또는 발급자 도메인의 검증 URL**로 충분하다 [가정].
- 한국에서 "수료증"과 "자격"은 다르다. 국가자격이 아닌 자격을 신설·운영하려면 자격기본법상 **민간자격 등록**이 필요하며, 금지 분야와 국가자격 명칭 사용 금지가 있다 (자격기본법 제14조·제17조 해설, https://www.nepla.ai/law/자격기본법) [확인 필요: 국가법령정보센터 원문].

## 상세

### 수료증 발급·검증 기본 설계

| 요소 | 설명 |
|------|------|
| 발급 조건 | 수료 기준 충족 시 자동 발급 ([[domain/학습진도관리]]) |
| 기재 항목 | 이름, 과정명, 학습 시간, 수료일, 발급 기관, 고유 번호, 성취 내용(역량·LO), 유효기간(있으면) |
| 진위 확인 | 고유 번호 조회 페이지 또는 QR → 발급자 도메인의 검증 페이지 |
| 이름 변경·재발급 | 본인 확인 후 재발급, 이전 번호 폐기 기록 |
| 취소 | 부정 수강 확인 시 취소(revocation) 상태를 검증 페이지에 표시 (P03) |
| 공유 | LinkedIn 등 외부 공유 링크, 이미지 다운로드 |

### Open Badges 3.0과 VC

- Open Badges 3.0의 각 배지(OpenBadgeCredential)는 Verifiable Credential로 서명된다. 즉 배지가 **발급자 서버가 꺼져도 서명으로 검증 가능**한 형태가 된다 (1EdTech 구현 가이드, https://standards.1edtech.org/open-badges/guides/standards/v3p0/impl) [verified 2026-10-12].
- 성취(Achievement) 정의에 기준(criteria), 정렬(alignment: 역량 체계·성취기준)을 담을 수 있다.
- 여러 성취를 묶은 학습 이력은 1EdTech CLR(Comprehensive Learner Record) 2.0이 다룬다 [확인 필요: CLR 2.0 발행일].
- **디지털 지갑**: 학습자가 VC를 보관·제시하는 앱. 지갑 생태계와 상호운용성은 아직 발전 중이다 [가정].

### 블록체인 크레덴셜: 언제 필요한가

| 해결하려는 문제 | 블록체인 없이 가능한 대안 |
|-----------------|---------------------------|
| 위변조 방지 | 발급자 디지털 서명(VC) |
| 발급 기관 폐업 후에도 검증 | 서명 + 공개키 보존, 기록 이관 계획 |
| 발급 사실의 공개 타임스탬프 | 서명된 발급 로그, 해시 공증 |
| 취소 상태 확인 | 상태 목록(status list) |

- 비용: 체인 수수료 또는 서비스 이용료, 키 관리, 개인정보(체인에 올린 데이터는 지우기 어려움) [가정].
- 개인정보는 체인에 올리지 않고 해시만 올리는 방식이 일반적이다 [가정].
- 판단: 검증자가 다수·국가 간이고 발급 기관 지속성이 불확실할 때만 검토한다 [가정].

### 한국 맥락: 수료증 vs 국가자격 vs 민간자격

| 구분 | 근거 | 의미 |
|------|------|------|
| 수료증·이수증 | 사업자 자체 발급 | 과정을 마쳤다는 사실 증명. "자격"이 아니다 |
| 국가자격 | 개별 법령 (국가기술자격법 등) | 국가가 관리 |
| 등록 민간자격 | 자격기본법 제17조 | 주무부장관에 등록해야 운영 가능. 등록 업무는 한국직업능력연구원이 위탁 수행해 온 것으로 알려짐 (https://krivet.re.kr/repository/bitstream/202405/259/2/A21257_fulltext.pdf) [확인 필요: 현행 위탁 기관·절차] |
| 공인 민간자격 | 자격기본법상 공인 절차 | 국가자격과 동등한 효력이 일부 인정 [확인 필요] |

- 금지 분야: 다른 법령에서 금지한 행위 관련 분야, 국민 생명·건강·안전·국방에 직결되는 분야, 선량한 풍속·사회질서에 반하는 분야 등 (자격기본법 제17조 제1항 해설, https://www.nepla.ai/law/자격기본법) [확인 필요: 원문·시행령 목록].
- 국가자격과 같은 명칭은 쓸 수 없다 (자격기본법 제14조 해설, 같은 출처) [확인 필요].
- **"OO 자격증 과정" 마케팅** 시, 실제로 발급되는 것이 수료증인지 등록 민간자격인지 명확히 표시한다. 등록 번호 표시 의무 등 광고 규정은 [확인 필요].
- 사업주 환급 과정·국비 과정 수료증의 양식·발급 요건은 훈련 규정을 따른다 [확인 필요].

## 서비스 유형별 차이

| 유형 | 크레덴셜 특징 |
|------|---------------|
| AT01 이러닝 마켓플레이스 | 자동 수료증 + 외부 공유. 가치가 낮아 검증 URL 정도면 충분 [가정] |
| AT02 기업교육 LMS | 법정교육 이수 증빙, HR 시스템 기록, 감사 대응 보관 |
| AT03 부트캠프 | 포트폴리오·프로젝트 링크 포함 배지, 채용 연계 |
| AT08 고등·평생교육 | 학점·마이크로크레덴셜, Open Badges·CLR 요구 가능성 |
| AT09 자격증·시험대비 | 자체 자격 운영 시 민간자격 등록 검토 |

## 에듀테크 PM 적용

- [ ] 발급 조건을 L03 수료 기준과 1:1로 연결했다 (L06)
- [ ] 진위 확인 방식(검증 URL / 서명 VC / 블록체인)을 문제 기준으로 골랐다 (L06)
- [ ] 수료증에 성취 내용(LO·역량)을 담았다 (E05)
- [ ] 취소·재발급 절차를 P03과 맞췄다
- [ ] "자격" 표현을 쓰면 민간자격 등록 여부와 광고 문구를 법무 확인했다 (S05)
- [ ] 개인정보 최소 기재와 공개 범위 설정을 E13에서 검토했다

## 흔한 오해

- "블록체인 수료증이면 신뢰도가 올라간다" — 신뢰는 발급 기관과 평가 품질에서 나온다. 기술은 위변조만 막는다.
- "수료증 = 자격증" — 법적으로 다르다. 혼동을 부르는 표현은 분쟁 원인이 된다.
- "Open Badges 2.0 배지를 그대로 3.0이라고 하면 된다" — 3.0은 VC 기반 서명 구조가 달라 재발급·변환이 필요하다 [가정].
