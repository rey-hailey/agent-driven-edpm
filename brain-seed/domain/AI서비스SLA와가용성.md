# AI 서비스 SLA와 가용성

> 계약 SLA 문구는 법적 효력이 있으므로 고객 계약 전 법무 검토를 받는다 (법률 자문이 아님). 이 페이지는 AI 기능의 목표 설정, 업체 의존, 장애 시 대체 동작을 다룬다.

## 핵심 요약

- 용어를 구분한다. **SLI**는 측정값(지연, 오류율, 가용성), **SLO**는 SLI의 목표, **SLA**는 SLO를 못 지켰을 때 결과(환불·배상)가 정해진 계약이다. 결과가 없으면 SLA가 아니라 SLO다 (Google SRE Book, https://sre.google/sre-book/service-level-objectives/). [verified 2026-10-12]
- 지연은 평균이 아니라 **백분위(p95·p99)**로 잡는다. 평균은 긴 꼬리를 가린다 (같은 출처). [verified 2026-10-12] SLO를 넘겨도 되는 허용량인 **오류 예산**으로 배포 속도를 조절한다.
- AI 기능의 가용성은 우리 서버보다 **외부 모델 업체**에 더 의존한다. 우리가 고객에게 약속하는 SLA는 업체 SLA보다 높을 수 없다는 전제로, 대체 경로가 있을 때만 높인다 [가정: 설계 원칙].
- 교육 서비스는 **피크가 달력에 정해져 있다**: 학기초, 수업 시작 시각, 과제 마감 전, 시험 기간 ([[domain/학사일정]]). 이 기간에는 배포 동결과 증설, 대체 동작 점검을 미리 한다.

## 상세

### AI 기능 SLO 예시 틀 [가정: 수치는 A13에서 측정 후 확정]

| SLI | 정의 | 목표 설정 방법 |
|-----|------|----------------|
| 가용성 | 정상 응답 / 전체 요청 (대체 응답 포함 여부를 명시) | 기능 중요도별 등급 |
| 첫 토큰 지연 p95 | 요청→첫 출력 | 대화형은 체감 기준, 배치형은 완화 |
| 전체 응답 지연 p95 | 요청→완료 | 응답 길이에 따라 구간별 |
| 오류율 | 5xx·시간 초과·빈 응답 비율 | 업체 오류와 자체 오류 분리 집계 |
| 품질 SLI | 평가 표본 합격률, 신고율 | 가용하지만 틀린 답도 장애로 본다 |

- "AI가 응답은 했지만 품질이 무너진" 상태(모델 교체 후 성능 저하 등)도 장애 등급에 넣는다 ([[domain/할루시네이션대응]]).

### 기능 중요도 등급

| 등급 | 예 | 기대 |
|------|----|------|
| T1 핵심 | 시험·평가 중 기능, 과제 제출 연계 채점 | AI 실패 시에도 핵심 흐름(제출·저장)은 반드시 동작 |
| T2 주요 | 수업 중 튜터, 교사 자료 생성 | 대체 동작으로 축소 운영 |
| T3 보조 | 추천 문구, 요약 | 일시 비활성 허용 |

- **원칙**: AI가 실패해도 학습 기록 저장, 답안 제출, 출결은 막히지 않게 AI 호출을 핵심 트랜잭션 밖으로 분리한다.

### 단계적 기능 축소 (graceful degradation)

```
기본 모델 → (지연·오류) → 대체 업체·소형 모델 → 로컬 모델 → FAQ·검색 결과(M3) → 규칙 기반 안내(M1) → "잠시 후 다시" + 교사 안내
```

- 대체 경로는 **같은 평가세트를 통과한 것**만 쓴다. 대체 모델이 다른 국가 리전이면 국외 이전 근거를 미리 확인한다 ([[domain/AI개인정보보호]]).
- 회로 차단기: 오류율이 임계치를 넘으면 일정 시간 기본 모델 호출을 멈추고 대체 경로로 전환 [가정].

### 상태 페이지와 장애 공지

| 대상 | 채널 | 내용 |
|------|------|------|
| 학습자 | 앱 내 배너 | 영향 기능, 대체 방법, 예상 복구 |
| 교사 | 대시보드·메시지 | 수업 대체안(인쇄 자료, 비AI 활동) |
| 학교·기관 관리자 | 이메일·상태 페이지 | 장애 등급, 원인(1차), 사후 보고 일정 |
| 기업 고객 | 계약상 연락처 | SLA 위반 여부, 크레딧 산정 |

- 사후 보고서: 타임라인, 원인(업체/자체), 영향 사용자 수, 재발 방지. 업체 장애도 우리 고객에게는 우리 장애다.

### 점검 시간

- 학교 수업 시간대(평일 오전~오후)와 시험 기간을 피하고, 학원은 저녁 수업 시간대를 피한다. 고객 세그먼트별 사용 시간 분포를 보고 정한다 ([[domain/세그먼트별의사결정구조]]).

## 에듀테크 맥락

- **미성년**: 수업 중 장애는 교사 한 명이 수십 명을 동시에 대처해야 한다. 교사용 "AI 없이 수업 계속하기" 안내를 미리 준비한다.
- **학생 평가**: 시험 중 AI 채점·감독 기능 장애는 재시험·민원으로 이어진다. 평가 기능은 오프라인 저장·사후 채점으로 설계한다.
- **고객 요구**: 교육청 B2G 계약은 가용성·장애 대응 시간·보고 의무를, 기업 고객은 월간 가용성과 서비스 크레딧을 요구하는 경우가 많다 [가정: RFP·계약별 확인]. 업체 장애를 면책 사유로 넣을지, 대체 경로로 책임질지 계약 전에 정한다.

## 방식별 차이

| 방식 | 가용성 특성 |
|------|-------------|
| 규칙·NLP | 자체 서버 가용성과 같음. 최종 대체 경로로 적합 |
| RAG | 검색 색인·벡터 DB가 추가 장애 지점 |
| 로컬 LLM | 업체 의존 없음. GPU 용량이 피크 상한, 증설 리드타임 |
| 클라우드 LLM | 업체 장애·한도·모델 폐기 일정에 의존. 다중 업체 구성 검토 |

## 에듀테크 PM 적용

- [ ] 기능별 중요도 등급(T1~T3)과 SLI·SLO를 정한다 (A13, P09)
- [ ] 업체 SLA·한도·모델 폐기 일정을 표로 관리한다 (A11, P09)
- [ ] 단계적 기능 축소 경로와 전환 조건을 A11에 적는다
- [ ] 시험·학기초 피크 캘린더에 배포 동결·증설·사전 부하 시험을 넣는다 (M02, A13)
- [ ] 상태 페이지·대상별 공지 문안을 P09에 둔다
- [ ] B2B·B2G 계약 SLA 조항(가용성 정의, 측정 방법, 제외 사유, 크레딧)을 법무와 정한다 (S03, P09)
- [ ] 품질 저하를 장애 등급에 포함한다 (A13)

**관련 산출물**: P09(주), A13, A11, A12(대체 경로 비용), A14(대체 모델에도 같은 가드레일), P08(장애 중 안전 기능 유지), P07(장애·하향 고지), E13(대체 리전 국외 이전), S03, M02, B04.

## 흔한 오해

- "업체가 99.9%를 약속하니 우리도 99.9%" — 우리 구성 요소가 더해지면 전체 가용성은 낮아진다.
- "평균 응답 2초면 충분" — p95가 10초면 수업 중 체감은 나쁘다.
- "AI가 죽으면 기능을 끄면 된다" — 제출·저장까지 막히는 구조면 학습 장애가 된다.
