# AI 방식 스펙트럼 (M1~M8)

> A10 AI방식선택·아키텍처설계서를 쓸 때 참고. 방식 정의와 고르는 순서는 가이드 10(AI 방식 선택)의 M1~M8을 그대로 쓰고, 이 페이지는 방식별 깊이, 에듀테크 예, 판단 기준, 혼합 패턴을 더한다.

## 핵심 요약

- 에듀테크의 "AI 기능"은 대부분 **여러 방식의 조합**이다. 기능 하나에 방식 하나가 아니라, **요청 하나가 여러 단계를 거친다**.
- 원칙은 **요구를 충족하는 가장 단순한 방식**. 정답이 정해진 일(채점·출결·진도 판정)은 M1, 분류·추출은 M2, 이미 있는 답은 M3, 근거 문서 기반 설명은 M4, 특정 과업 정확도는 M5, 생성이 필요하고 데이터를 밖으로 못 보내면 M6, 그 외 열린 생성은 M7.
- M8 혼합의 대표 패턴은 두 가지: **캐스케이드**(의도 분류 → FAQ → RAG → LLM)와 **로컬 우선**(민감 데이터는 M6, 나머지는 M7).
- 방식 선택의 근거는 **같은 평가셋으로 방식별 결과를 비교한 표**다 (`ai_eval.py`의 `--target claude|local|cmd`). 느낌이나 리더보드가 아니다.
- 학생 평가·성적에 영향을 주는 판단은 결정성·설명 가능성이 우선이며, AI 기본법상 고영향 영역으로 다룬다 ([[domain/아동개인정보보호]]).

## 상세

### 방식별 깊이

| 방식 | 입력 → 출력 | 필요한 것 | 품질을 좌우하는 것 | 에듀테크 예 |
|------|-------------|-----------|---------------------|-------------|
| M1 규칙·템플릿 | 조건 → 정해진 값·문구 | 업무 규칙 정의, 테스트 | 규칙의 완전성 | 객관식·수치 채점, 출석 판정, 진도율 계산, "3일 미접속" 알림 문구 |
| M2 고전 NLP | 텍스트 → 라벨·개체·점수 | 라벨 데이터 수백~수천 건 [가정], 형태소 분석기 | 라벨 품질, 클래스 정의 | 문의 의도 분류, 비속어 필터, 단답형 유사도 채점 ([[domain/고전NLP와정형응답]]) |
| M3 검색·FAQ 매칭 | 질문 → 기존 답 | 검증된 FAQ·해설 DB | 질문 표현 다양성 커버, 임베딩 | 학부모 FAQ 챗봇, 유사 문항 찾기, 해설 검색 |
| M4 RAG | 질문 + 검색 문서 → 생성 답 | 지식베이스(A01), 검색(A02), LLM | 검색 재현율, 청크 설계, 인용 | 교재 근거 질의응답, 강의 요약 ([[domain/RAG설계]]) |
| M5 소형·파인튜닝 | 특정 입력 → 고정 과업 출력 | 과업 데이터, 학습·서빙 | 데이터 양·대표성, MLOps | 발음 평가, 필기·수식 인식, 루브릭 점수 예측 |
| M6 로컬 LLM | 프롬프트 → 생성 (내부망) | GPU, 서빙 스택, 오픈 모델 라이선스 | 모델 크기·양자화, 운영 | 학교 서버에서 학생 글 피드백 ([[domain/로컬LLM과온프레미스]]) |
| M7 클라우드 LLM | 프롬프트 → 생성 (외부 API) | API 계약, 비용 관리, 개인정보 검토 | 프롬프트, 모델 선택 | AI 튜터 대화, 자료 초안 ([[domain/프롬프트엔지니어링]]) |
| M8 혼합 | 단계별 결합 | 라우팅·관측 | 라우팅 정확도, 단계별 평가 | 아래 패턴 |

### 판단 기준 (A10에 기능마다 기록)

1. **틀렸을 때 피해**: 성적·자격·생활기록에 영향 → 결정적 방식(M1·M2·M5) + 사람 확인. 학습 보조 설명 → 생성 허용.
2. **같은 입력 같은 출력**이 필요한가: 채점 이의 제기에 재현 가능한 답이 필요하면 LLM은 보조로만.
3. **데이터 민감도**: 만 14세 미만 학생 글·음성, 실명, 상담 내용 → 가명화 또는 M6. 국외 이전 여부 확인 ([[domain/학습데이터프라이버시]]).
4. **학교망·오프라인**: 학교망 방화벽이 외부 API를 막거나 교실 오프라인 → 기기 내 모델·학교 서버.
5. **지연 예산**: 발음 피드백·대화는 빠른 응답, 리포트 생성은 배치 가능.
6. **학습자당 비용**: 월 요청 수 × 요청당 원가로 A12에서 계산 ([[domain/LLM비용과토큰과금]]).
7. **운영 역량**: 모델 학습·GPU 운영 인력이 없으면 M1~M4·M7 중심으로 시작.

### 혼합 패턴

**패턴 1. 캐스케이드 (질문 응답형 서비스)**

```text
질문 → [M1 정규식: 개인정보·위기어 감지] → [M2 의도 분류]
   ├─ 행정 문의(환불·로그인) → [M3 FAQ 매칭] → 신뢰도 높음: 원문 답 / 낮음: 다음 단계
   ├─ 학습 질문 → [M4 RAG: 교재 검색 + 생성 + 인용]
   └─ 열린 대화·복잡한 설명 → [M7 LLM] (난이도 높으면 큰 모델, A11)
모든 출력 → [출력 가드레일] → 학생 ([[domain/AI가드레일설계]])
```

- 앞 단계에서 처리되는 비율(**앞 단계 해결률, deflection rate**)이 높을수록 비용·지연이 줄고 답이 검증된 원문이 된다. 단계마다 신뢰도 임계값과 다음 단계로 넘기는 조건을 A11에 적는다.

**패턴 2. 로컬 우선 (민감 데이터)**

- 학생 글·상담·실명이 들어간 요청은 M6(학교 서버·VPC)로, 공개 교재 기반 일반 질문은 M7로. 민감도 판정은 M1 규칙(개인정보 패턴) + M2 분류로 하고, **판정이 애매하면 로컬로 보낸다**.

**패턴 3. 생성 후 결정적 검증**

- LLM이 문항·해설을 생성하고, 정답 키는 M1(계산·정답 비교)으로 독립 검증 ([[domain/문항자동생성]]). LLM이 JSON을 내면 스키마 검증(M1)으로 거른다.

**패턴 4. 오프라인 생성 + 온라인 조회**

- 해설·피드백 문구를 미리 LLM으로 만들어 교사·검수자가 승인한 뒤 DB에 넣고, 서비스 시에는 M3로 조회. 실시간 LLM 호출 없이 품질·비용을 통제한다.

## 에듀테크 맥락

- **K-12 학생 데이터**: 아동 개인정보·보호자 동의·국외 이전이 방식 선택의 가장 강한 제약이다. 같은 기능도 성인 B2C는 M7, K-12 학교 납품은 M6나 가명화 후 M7이 될 수 있다.
- **학교망**: 교육청·학교망 정책으로 특정 외부 도메인이 막힐 수 있다 [확인 필요: 기관별]. 도입 전 화이트리스트 요청 절차를 확인한다.
- **교사 승인**: 학생에게 바로 가는 생성물과 교사 검토를 거치는 생성물은 위험 수준이 다르다. 교사 검토가 있으면 더 넓은 방식을 허용할 수 있다 ([[domain/교사참여설계]]).
- **학습 효과**: 방식은 비용·정확도뿐 아니라 학습 효과로 평가한다. 정답을 바로 주는 LLM보다 힌트 사다리를 강제하는 혼합 구조가 학습에 낫다 ([[domain/AI튜터설계]]).

## 방식별 차이

위 "방식별 깊이" 표 참조. 요약하면 M1→M7로 갈수록 표현력은 커지고, 결정성·설명 가능성·비용 예측성은 낮아진다. M5·M6는 운영 부담을 대가로 데이터 통제와 과업 정확도를 얻는다.

## 에듀테크 PM 적용

**체크리스트 (A10)**

- [ ] 기능마다 판단 기준 7개를 채우고 선택 방식과 탈락 방식의 이유를 쓴다
- [ ] 혼합이면 단계 순서, 단계별 신뢰도 임계값, 넘김 조건을 그림과 표로 그린다 (A11로 이어짐)
- [ ] 같은 평가셋으로 최소 2개 방식을 비교한 결과를 A06에 첨부한다
- [ ] 민감 데이터 경로(M6 또는 가명화)를 E13·P07과 맞춘다
- [ ] 비용 추정(A12), 운영 계획(A13), 가드레일(A14)이 선택 방식과 맞는지 확인한다

**관련 산출물**: A10(주), A11, A12, A13, A14, A00, A01~A06, E14, P07~P09.

## 흔한 오해

- "AI 기능 = LLM 호출" — 대부분의 요청은 규칙·분류·검색으로 끝낼 수 있다.
- "혼합은 대기업이나 하는 것" — 의도 분류 + FAQ + LLM 3단계만으로도 혼합이다.
- "가장 좋은 모델 하나로 통일하면 단순하다" — 비용·지연·데이터 정책을 한 모델이 모두 만족하기 어렵다.
- "로컬이면 안전하다" — 로컬도 접근 통제·로그·가드레일이 필요하다.
