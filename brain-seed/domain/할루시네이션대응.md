# 할루시네이션 대응

> 법적 위험 관련 서술은 법률 자문이 아니다. 할루시네이션(환각)은 모델이 근거 없이 그럴듯한 내용을 만드는 현상이다. 교육에서는 틀린 내용이 **학습되어 남는다**는 점에서 일반 서비스보다 피해가 크다. 이 페이지는 예방·탐지·정정·신고 흐름과 지표를 다룬다.

## 핵심 요약

- 원인은 크게 넷이다: (1) 학습 데이터에 없거나 드문 지식, (2) 근거 없이 "답해야 한다"는 생성 압력, (3) 검색 실패(RAG에서 잘못된·빈 문서), (4) 계산·논리 단계 오류 [가정: 실무 분류].
- 예방의 기본은 **사실은 생성하지 않고 가져오는 것**이다. 정답·점수·날짜·규정은 규칙·DB·SQL로 처리하고 LLM은 설명 문장만 만든다 ([[domain/AI튜터설계]], 가이드 10 "정답 비교·점수 계산을 LLM에게 시킨다" 실수).
- 탐지는 층으로 쌓는다: 인용 일치 검사 → 자기 일관성(여러 번 샘플링해 답이 갈리면 의심) → 검증 모델 → 교과 전문가(SME) 표본 검수. 자기 일관성 방식의 대표 연구는 SelfCheckGPT다 (Manakul et al., EMNLP 2023, https://arxiv.org/abs/2303.08896). [verified 2026-10-12]
- 법적으로도 고영향 AI(학생 평가)는 위험관리·이용자 보호 조치 의무가 있고 (AI 기본법 제34조 ①), 생성형 결과물은 생성 사실 표시 대상이다 (제31조 ②, https://casenote.kr/법령/인공지능_발전과_신뢰_기반_조성_등에_관한_기본법/제31조). [verified 2026-10-12]

## 상세

### 예방

| 기법 | 내용 | 효과가 큰 곳 |
|------|------|--------------|
| 근거 연결(RAG) | 승인된 교재·해설만 근거로, 근거 밖이면 "모름" | 개념 설명, 교재 Q&A |
| 결정적 처리 | 정답·채점·계산·규정은 코드로 | 채점, 환불·일정 안내 |
| 출력 제약 | JSON 스키마, 선택지 고정, 길이 제한 | 문항 생성, 피드백 |
| 거절 허용 | "근거 없음" 응답을 정상 동작으로 평가 | 범위 밖 질문 |
| 범위 제한 | 현재 단원·과정으로 질문 범위 제한 | 튜터 |
| 도구 호출 | 계산기·코드 실행으로 수치 검증 | 수학·과학 |

### 탐지

| 층 | 방법 | 비용 | 한계 |
|----|------|------|------|
| L1 규칙 | 인용 문서 ID 존재·인용문 원문 일치, 숫자·정답 키 대조 | 낮음 | 문장 수준 왜곡은 못 잡음 |
| L2 자기 일관성 | 같은 질문 N회 샘플링 후 불일치 표시 (SelfCheckGPT형) | 중 | 일관되게 틀리면 못 잡음, 지연·비용 증가 |
| L3 검증 모델 | 별도 모델이 "답이 근거로 뒷받침되는가" 판정 | 중 | 검증 모델도 틀림, 평가 필요 |
| L4 SME 표본 | 교과 전문가가 주간 표본 검수 | 높음 | 표본 크기에 따라 놓침 |

- 문항·해설처럼 **배포 전 검수가 가능한 콘텐츠**는 L4를 전수 또는 고위험 전수로, 실시간 대화는 L1~L3 + 사후 표본으로 나눈다 ([[domain/문항자동생성]]).

### 정정과 알림 흐름

```
신고/탐지 → 분류(심각도) → 노출 중지(필요 시) → 수정·근거 보강 → 재평가 → 영향 받은 사용자 알림 → 평가세트에 회귀 케이스 추가
```

| 심각도 | 예 | 대응 [가정: 기준은 P08에서 확정] |
|--------|----|------|
| S1 | 시험·성적에 영향, 안전 관련 오정보 | 즉시 노출 중지, 교사·고객 알림 |
| S2 | 핵심 개념 오류 | 영업일 기준 단기 수정, 해당 학습자 정정 안내 |
| S3 | 사소한 표현·예시 오류 | 정기 배포에 포함 |

- 콘텐츠 오류 SLA는 [[domain/콘텐츠품질관리]]의 심각도 체계와 맞춘다.

### 학습자 고지와 교사 신고

- 학습자 화면: "AI가 만든 설명은 틀릴 수 있어요. 교재와 선생님 설명을 우선하세요" 같은 연령별 문구 + 응답마다 "틀렸어요" 버튼. 고지문은 면책이 아니라 학습 습관(검증)을 기르는 장치로 설계한다.
- 교사 화면: 학급에서 나온 AI 응답 신고 목록, 오류 수정 결과 회신, 같은 오류를 본 학생 수.

### 지표

| 지표 | 정의 |
|------|------|
| 할루시네이션 비율 | 평가세트 응답 중 근거와 불일치·사실 오류로 판정된 비율 (판정 기준을 A13에 명시) |
| 근거 인용 정확도 | 인용한 문서가 실제로 주장을 뒷받침하는 비율 |
| 적절한 거절률 | 근거 없는 질문에 "모름"으로 답한 비율 |
| 신고율·확인율 | 사용자 신고 수 / 응답 수, 신고 중 실제 오류 비율 |
| 정정 소요 시간 | 심각도별 탐지→수정 시간 |

- 공개 벤치마크의 환각률을 우리 서비스 수치로 인용하지 않는다. 우리 교과·연령 평가세트로 측정한다.

## 에듀테크 맥락

- **미성년**: 아동은 AI 답을 권위 있게 받아들이기 쉽다. 저학년일수록 생성 범위를 좁히고 검수된 콘텐츠 비중을 높인다.
- **학생 평가**: 채점·피드백 오류는 성적·진로 분쟁으로 번진다. 자동 채점 결과는 교사 확인 후 확정한다.
- **고객 요구**: 학교·교육청은 오류 신고 처리 절차와 책임 소재를, 기업은 사내 규정 Q&A의 근거 표시를 요구하는 경우가 많다 [가정].

## 방식별 차이

| 방식 | 환각 특성 | 대응 |
|------|-----------|------|
| 규칙·NLP | 생성 없음. 규칙 오류는 결정적으로 반복 | 규칙 테스트 |
| RAG | 검색 실패·근거 왜곡이 주원인 | 검색 평가(A02) 먼저, 인용 검사 |
| 로컬 LLM | 소형 모델일수록 지식 오류 증가 경향 [가정] | 범위 축소, 근거 강제 |
| 클라우드 LLM | 유창해서 오류가 덜 눈에 띔 | 검증 층, 모델 교체 시 재평가 |

## 에듀테크 PM 적용

- [ ] 기능별로 "생성해도 되는 것/가져와야 하는 것"을 나눈다 (A10, A14)
- [ ] 탐지 층(L1~L4)과 적용 기능을 정한다 (A14)
- [ ] 심각도 기준과 정정·알림 흐름을 P08에 적는다
- [ ] 학습자 고지 문구(연령별)와 신고 버튼을 화면 설계에 넣는다 (E10, P07)
- [ ] 할루시네이션 비율·인용 정확도를 평가세트로 측정하고 출시 기준을 정한다 (A13, A06)
- [ ] 모델·프롬프트·근거 문서 변경 시 회귀 평가를 돌린다 (A13)
- [ ] 검증 층 추가로 늘어나는 비용·지연을 A12·P09에 반영한다

**관련 산출물**: P08(주), A14, A13, A06, A02, P07, E13(안전 관련 오정보), A12, P09.

## 흔한 오해

- "RAG를 쓰면 환각이 사라진다" — 검색이 틀리면 근거 있는 척하는 오답이 나온다.
- "고지문을 달면 책임이 없다" — 고지는 위험 관리의 일부일 뿐이다. 학생 평가는 사람 감독 의무가 따로 있다.
- "최신 큰 모델은 충분히 정확하다" — 우리 교과·학년 평가세트로 측정하기 전에는 알 수 없다.
