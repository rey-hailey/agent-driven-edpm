# 학습 콘텐츠 구조 (과정 > 섹션 > 레슨 > 활동)

## 핵심 요약

- 과정을 판매·운영하는 서비스는 콘텐츠를 **계층 구조**로 다룬다: 프로그램(트랙·학위) > 과정(코스) > 모듈·섹션 > 레슨(차시) > 활동·학습객체. 계층마다 판매·진도·수료·정산 규칙이 붙는다.
- 어느 계층을 **판매 단위**, **진도 집계 단위**, **수료 단위**, **정산 단위**로 삼을지가 제품 구조를 결정한다. 네 단위가 서로 다르면 규칙이 복잡해진다 [가정].
- 콘텐츠 유형(VOD, 라이브, 인터랙티브, 실습 환경, 문서, 퀴즈, 과제, 프로젝트)마다 "완료"의 정의와 제작 비용이 다르다.
- 개정·재촬영은 반드시 생긴다. 버전 관리 없이 콘텐츠를 교체하면 진도율·수료 기록·리뷰가 깨진다 [가정].

## 상세

### 계층과 각 계층의 역할

| 계층 | 예 | 보통 붙는 규칙 |
|------|----|----------------|
| 프로그램·트랙·학위 | 데이터 분석가 트랙, 학점 과정, 자격 준비 묶음 | 번들 가격, 이수 순서, 크레덴셜 발급 |
| 과정(코스) | "SQL 기초" | 판매 단위, 수강 기간, 수료 기준, 강사 정산 |
| 모듈·섹션 | "1주차: SELECT" | 순차 잠금, 주차별 일정(코호트형) |
| 레슨·차시 | "WHERE 절" 영상 12분 | 진도 집계 단위, 미리보기 여부 |
| 활동·학습객체 | 영상, 퀴즈 3문항, 실습 1개 | 완료 조건, 점수, 재사용 |

- SCORM은 패키지 안의 실행 단위를 SCO(Sharable Content Object)로 부르며, 2004판은 SCO 간 순서·분기(sequencing) 규칙을 정의한다 ([[domain/SCORM과xAPI]]).
- **마이크로러닝**: 3~10분 단위 레슨을 독립 소비 단위로 설계하는 방식. 시간 범위는 업계 관행으로 정해진 표준이 없다 [가정]. 모바일·업무 중 학습에 유리하지만 개념 간 연결이 끊기기 쉽다.

### 콘텐츠 유형과 완료 정의

| 유형 | 완료 정의 예 | 운영 쟁점 |
|------|--------------|-----------|
| VOD | 시청 비율 N% 이상 | 건너뛰기·배속 처리 ([[domain/학습진도관리]]) |
| 라이브 | 출석(입장·체류 시간) | 녹화본 제공 여부, 시간대 |
| 인터랙티브(H5P·시뮬레이션) | 모든 단계 통과 | 저작 도구 종속, 표준 패키징 |
| 실습·샌드박스 | 자동 채점 통과 | 인프라 비용, 환경 만료 |
| 문서·읽기 자료 | 열람 또는 확인 버튼 | "열람=학습" 아님 |
| 퀴즈 | 응시 또는 합격 점수 | 재응시 규칙 ([[domain/과제와평가설계]]) |
| 과제·프로젝트 | 제출 또는 채점 통과 | 채점 인력·기한 |

### 학습 경로와 묶음

- **번들**: 여러 과정을 할인 가격으로 묶은 판매 상품. 진도·수료는 과정별로 남는다.
- **트랙·경로**: 권장 순서가 있는 과정 묶음. 선수 과정 잠금 여부를 정한다.
- **학위·자격 경로**: 이수 학점·필수 과목 규칙과 공식 크레덴셜이 붙는다 ([[domain/수료증과디지털크레덴셜]]).

### 메타데이터 최소 세트

제목, 설명, 학습 목표(LO), 대상 수준, 선수 지식, 예상 학습 시간, 콘텐츠 유형, 언어·자막, 강사, 버전, 최종 수정일, 카테고리·태그, 역량·성취기준 코드(K-12는 성취기준, 직무교육은 NCS 등) [가정]. 학습 목표는 [[domain/블룸분류체계]]로 태깅하면 평가 정렬이 쉬워진다.

### 버전 관리와 재촬영

- 과정 버전(v1, v2)과 레슨 버전을 분리한다. 수강 중인 학습자를 어느 버전에 묶을지(고정 vs 자동 이전) 정책이 필요하다 [가정].
- 레슨 교체 시 기존 시청 기록을 새 레슨으로 이전할지, 진도율 분모가 바뀌는지 정한다.
- 환급 과정·기업 납품 과정은 승인받은 내용과 실제 콘텐츠가 같아야 하는 경우가 많아 임의 수정이 제한될 수 있다 [확인 필요].

### 미리보기·무료 레슨

- 구매 전환을 위해 일부 레슨을 무료 공개한다. 무료 레슨이 진도율 분모에 포함되는지, 환불 계산의 "수강 진행률"에 포함되는지 정한다 ([[domain/과정가격전략]]).

## 서비스 유형별 차이

| 유형 | 구조상 특징 |
|------|-------------|
| AT01 이러닝 마켓플레이스 | 과정 = 판매·정산 단위. 강사가 구조를 직접 만들기 때문에 최소 구조 규칙(레슨 길이, 필수 메타데이터)을 강제한다 |
| AT02 기업교육 LMS | 외부 SCORM·xAPI 패키지 수입이 많다. 필수 교육(법정교육) 과정과 선택 과정 구분, 직무별 경로 |
| AT03 부트캠프 | 주차 모듈 + 라이브 + 프로젝트. 코호트 일정이 구조의 일부 |
| AT04 라이브·튜터링 | 회차(세션) 중심. 커리큘럼이 느슨하고 녹화본이 부속 콘텐츠 |
| AT05 K-12 코스웨어 | 교과·학년·단원·차시 구조와 성취기준 정렬이 필수 ([[domain/교육과정지식그래프]]) |
| AT07 소비자 앱 | 레벨·유닛·레슨의 짧은 반복 구조, 스트릭과 결합 ([[domain/동기설계]]) |
| AT09 자격증·시험대비 | 과목·출제 영역·문항 은행 구조가 중심 |

## 에듀테크 PM 적용

- [ ] 판매·진도·수료·정산 단위를 각각 어느 계층으로 할지 표로 확정했다 (L01)
- [ ] 콘텐츠 유형별 완료 정의를 L01에 쓰고 L03 진도 규칙과 맞췄다
- [ ] 필수 메타데이터 목록과 강사·제작팀 입력 책임을 정했다 (L01, L02)
- [ ] 버전 정책(수강 중 학습자 처리, 기록 이전)을 정했다 (L01, P04)
- [ ] 미리보기 레슨이 환불·진도 계산에 미치는 영향을 P01과 맞췄다
- [ ] 외부 패키지(SCORM·xAPI) 수입 여부를 L05에 반영했다

## 흔한 오해

- "구조는 콘텐츠팀 일" — 계층 선택이 결제·진도·정산 데이터 모델을 정한다. 기획 초기에 PM이 정한다.
- "레슨은 짧을수록 좋다" — 짧은 단위는 소비는 쉽지만 개념 연결과 응용 과제가 빠지기 쉽다 ([[domain/인지부하이론]]).
- "문서 열람도 완료로 치면 된다" — 열람 기록은 학습 증거가 아니다 ([[domain/학습분석지표]]).
