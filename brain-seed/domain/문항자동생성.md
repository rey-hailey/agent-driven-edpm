# 문항 자동 생성

> A08 문항자동생성설계서를 쓸 때 참고. LLM은 문항 **초안**을 빠르게 만들지만, 정답 오류·모호성·편향을 스스로 잡지 못한다. "생성 → 자동 검증 → 사람 검토 → 시범 배포 → 문항 분석" 전체를 설계해야 문항 은행이 된다.

## 핵심 요약

- 입력은 세 가지다: **원천 콘텐츠**(교재·강의 원고), **성취기준·학습목표**(무엇을 재는가), **오개념 목록**(오답 보기의 원천).
- 좋은 선다형 오답 보기는 그럴듯한 **실제 오개념**에서 나온다. 무작위로 틀린 보기는 쉽게 지워져 변별력이 없다.
- 난이도는 "어렵게 만들어줘" 프롬프트로 통제되지 않는다. **인지 수준(블룸 분류), 풀이 단계 수, 수치 복잡도, 보기 유사도** 같은 설계 변수로 조절하고, 실제 난이도는 배포 후 데이터로 확정한다 ([[domain/블룸분류체계]]).
- 정답 키는 반드시 독립 검증한다: 계산 문제는 코드·수식 엔진으로 다시 풀고, 지식 문제는 근거 문장을 원천에서 찾는다.
- 배포 후 **문항 분석**(정답률 p, 변별도, 보기별 선택률)으로 문항을 유지·수정·폐기한다.

## 상세

### 생성 단계

| 단계 | 내용 | 담당 |
|------|------|------|
| 1. 명세 | 성취기준, 인지 수준, 문항 유형, 난이도 목표, 금지 사항 | 사람 (E11 문항 명세표) |
| 2. 근거 선택 | 원천 콘텐츠 구간, 오개념 태그 선택 | 규칙·검색 |
| 3. 초안 생성 | 문두, 정답, 오답 보기(오개념별), 해설 | LLM |
| 4. 자동 검증 | 정답 재계산, 근거 대조, 형식 검사, 중복·유사도 | 코드 + LLM 보조 |
| 5. 사람 검토 | 내용 전문가 검토, 편향·민감성 검토 | 사람 |
| 6. 시범 배포 | 채점 미반영 문항으로 소규모 노출 | 운영 |
| 7. 문항 분석 | p값, 변별도, 보기 분석 → 확정·수정·폐기 | SQL·통계 |

### 오답 보기 설계

- 오답 보기마다 **어떤 오개념을 진단하는지** 태그를 단다 (예: "분수 덧셈에서 분모끼리 더함").
- 이렇게 하면 보기별 선택률이 진단 정보가 되고, AI 튜터 힌트([[domain/AI튜터설계]])와 연결된다.
- 피할 것: "위의 모든 것", 길이가 유독 긴 정답, 문법적으로 문두와 안 맞는 오답, 서로 포함 관계인 보기.

### 자동 검증 항목

| 항목 | 방법 |
|------|------|
| 정답 정확성 | 계산형은 코드 재계산, 지식형은 원천 근거 문장 매칭 |
| 정답 유일성 | 다른 보기가 정답일 가능성을 별도 모델·규칙으로 검사 (복수 정답 탐지) |
| 모호성 | 문두에 "가장", "옳지 않은" 등 부정·최상급 표현 강조 여부, 조건 누락 |
| 범위 | 단원·교육과정 밖 개념 사용 여부 ([[domain/교육과정지식그래프]]) |
| 중복 | 기존 문항 은행과 의미 유사도 |
| 원천 복제 | 원천 지문·기출 문장과의 표절 유사도 (저작권) |
| 편향·민감성 | 성별·지역·장애 고정관념, 특정 문화 배경 지식 의존 |
| 가독성 | 대상 학년 어휘 수준 |

- LLM으로 다른 LLM의 문항을 검토하게 할 수 있지만 최종 판정은 사람이 한다 (E14 원칙).

### 배포 후 문항 분석

- **정답률(p값, 고전검사이론의 난이도)**: 응답자 중 정답자 비율. 매우 높거나 낮으면 정보가 적다.
- **변별도**: 총점 상위 집단과 하위 집단의 정답률 차이, 또는 문항 점수와 총점의 점이연 상관. 변별도가 음수면 정답 키 오류나 모호성을 먼저 의심한다.
- **보기 분석**: 아무도 고르지 않는 오답 보기는 기능하지 않는다. 상위 집단이 특정 오답을 많이 고르면 그 보기가 사실상 정답일 수 있다.
- 판단 임계값(예: 변별도 0.2~0.3 이상 양호)은 교과서적 관행으로 소개되지만 시험 목적에 따라 다르다 [확인 필요: 기준 출처]. 표본이 작으면(수십 명) 수치가 불안정하다.
- **문항반응이론(IRT) 기초**: 학습자 능력(θ)과 문항 모수(난이도 b, 변별도 a, 추측 c)를 같은 척도에 놓는 모형(1·2·3모수). 응답 집단이 바뀌어도 문항 모수가 비교적 안정적이라 적응형 시험·대규모 문항 은행에 쓴다. 모수 추정에는 상당한 응답 수가 필요하다 [확인 필요: 모형별 최소 표본]. 이 위키에는 IRT 전용 페이지가 아직 없다.

### 저작권과 시험 보안

- 원천 교재·기출을 입력으로 쓸 때 이용 권리를 확인한다 ([[domain/교육저작권]], [[domain/강사계약과콘텐츠권리]]). 기출 문항을 거의 그대로 바꿔 쓴 문항은 권리 침해·표절 소지가 있다.
- 생성 문항이 외부 모델 학습 데이터에 남지 않도록 업체 조건을 확인한다 (E13).
- 고부담 시험용 문항 은행은 노출 관리(노출 횟수 상한, 문항 순환)를 한다 ([[domain/부정수강방지]]).
- AI 생성 문항임을 표시해야 하는지 AI 기본법 제31조를 검토한다 [확인 필요: 적용 범위]. K-12 학생 평가에 쓰이면 고영향 AI 해당 여부도 검토한다 ([[domain/아동개인정보보호]]).

### 평가 세트 접근

- 사람이 검증한 기준 문항 세트(예: 성취기준별 10문항)를 두고, 프롬프트·모델을 바꿀 때마다 같은 명세로 재생성해 비교한다.
- 지표: 자동 검증 통과율, 사람 검토 승인율, 정답 키 오류율(0이 목표), 수정 소요 시간, 배포 후 폐기율.
- A06 평가 결과와 함께 기록한다.

## 에듀테크 PM 적용

**체크리스트 (A08 문항자동생성설계서)**

- [ ] 문항 명세표(성취기준, 인지 수준, 유형, 오개념 태그)를 E11에서 가져온다
- [ ] 생성 7단계별 담당과 통과 조건을 정한다
- [ ] 정답 키 독립 검증 방법을 문항 유형별로 정한다
- [ ] 자동 검증 8항목 중 구현 범위를 정한다
- [ ] 사람 검토자(내용 전문가, 편향 검토)와 승인 화면을 정한다 (E14 4장)
- [ ] 시범 배포와 문항 분석 기준(p값, 변별도, 보기 분석)을 정한다
- [ ] 원천 자료 권리와 업체 데이터 조건을 확인한다 (P02, E13)
- [ ] 기준 문항 세트와 비교 지표를 A06에 둔다

**관련 산출물**: A08(주), E11, E14, A06, A00, P04, L04.

## 흔한 오해

- "LLM이 만든 문제는 정답도 맞다" — 정답 키 오류가 가장 흔하고 가장 치명적이다.
- "난이도는 프롬프트로 지정" — 실제 난이도는 응답 데이터로만 확정된다.
- "많이 만들수록 좋다" — 검증되지 않은 문항은 문항 은행 신뢰를 떨어뜨린다.
