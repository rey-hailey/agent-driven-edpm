# 모델 선택과 라우팅

> A11 모델선택·라우팅설계서를 쓸 때 참고. 모델은 **자사 데이터로 만든 평가셋 결과**로 고르고, 요청마다 다른 모델로 보내는 **라우팅**으로 비용·품질·데이터 정책을 맞춘다.

## 핵심 요약

- 공개 리더보드는 후보를 좁히는 데만 쓴다. 최종 선택은 **자사 골든셋·시나리오셋·E14 교육적 평가세트** 결과(합격률, 루브릭, 안전 위반률, 지연, 비용)로 한다.
- 라우팅 전략 4가지: **과업별 규칙 라우팅**, **난이도 분류 라우팅**, **데이터 민감도 라우팅**(로컬 vs 클라우드), **비용 상한 라우팅**.
- 모든 외부 호출에 **시간 제한·재시도·대체 경로(fallback)**를 두고, 대체 경로가 품질·안전 기준을 낮추지 않는지 확인한다.
- 공급사별 차이를 감추는 **추상화 계층**을 두되, 모델별 프롬프트·형식 차이는 설정으로 관리한다.
- **모델 버전을 고정**하고, 공급사의 지원 종료(deprecation) 일정을 추적해 교체 전 회귀 평가를 한다. 모델 교체도 A/B나 단계 출시로 한다.

## 상세

### 모델 선택 절차

1. **후보 목록**: 품질 상위, 저비용, 로컬 가능(오픈 가중치) 후보를 각 1개 이상. 라이선스·데이터 처리 조건을 먼저 거른다 ([[domain/로컬LLM과온프레미스]]).
2. **평가 실행**: 같은 세트로 후보마다 `ai_eval.py --model ... --label ...` 실행 ([[domain/AI평가메트릭과AB테스트]]).
3. **비교표**: 기능별로 합격률, 안전 실패 수, 지연 p50·p95, 요청당 원가 ([[domain/LLM비용과토큰과금]]).
4. **결정 기록**: 기능별 기본 모델, 대체 모델, 탈락 이유를 A11과 ADR에 남긴다.

| 기능 | 후보 A (대형) | 후보 B (소형) | 후보 C (로컬) | 선택 |
|------|------|------|------|------|
| 튜터 대화 | 합격률·안전·지연·원가 | ... | ... | 근거와 함께 |
| 문의 분류 | ... | ... | ... | M2 분류기면 LLM 불필요 |

### 라우팅 전략

| 전략 | 판정 방법 | 예 | 위험 |
|------|-----------|----|------|
| 과업별 규칙 | 기능·엔드포인트별 고정 | 문항 초안=대형, 요약=소형 | 단순, 과업 내 난이도 차이 무시 |
| 난이도 분류 | M2 분류기·소형 LLM이 난이도 판정 | 단순 개념 질문=소형, 다단계 풀이=대형 | 오분류 시 품질 저하 → 소형 응답 신뢰도 낮으면 대형으로 승격 |
| 데이터 민감도 | 규칙(개인정보 패턴) + 분류 | 학생 글·상담=로컬, 공개 교재 질문=클라우드 | 미탐 시 민감 데이터 외부 전송 → 애매하면 로컬 |
| 비용 상한 | 사용자·기관별 월 사용량 | 상한 근접 시 소형 모델 또는 FAQ만 | 사용자 경험 저하 → 고지 필요 (P09) |

- 여러 전략을 순서대로 건다: **민감도 → 과업 → 난이도 → 비용 상한**. 민감도 판정이 항상 먼저다.
- 라우팅 결정도 로그로 남겨 어떤 경로가 얼마나 쓰였는지, 경로별 품질이 어떤지 본다.

### 대체 경로와 시간 제한

- 기능별 **시간 제한**(대화형은 짧게, 리포트는 길게)과 재시도 횟수(지수 백오프)를 정한다.
- 대체 순서 예: 기본 모델 → 같은 공급사 다른 모델 → 다른 공급사 또는 로컬 → 정적 응답("지금은 답하기 어려워요. 선생님께 질문해 보세요") ([[domain/MLOps와LLMOps]]).
- **대체 경로도 같은 가드레일**을 통과해야 하고, 데이터 민감도 정책을 어기면 안 된다 (민감 요청을 장애 시 클라우드로 넘기지 않기).
- 수업 중 장애는 교사에게 영향이 크다. 장애 시 동작을 P09 SLA에 적는다.

### 다중 공급사 추상화

- 내부 인터페이스: `generate(task, messages, schema, constraints) → result`. 공급사·로컬 서버 차이는 어댑터에서 처리. OpenAI 호환 API를 공통 형식으로 쓰는 방법도 있다.
- 추상화가 감추지 못하는 차이: 프롬프트 반응, 구조화 출력 지원, 토크나이저(원가), 안전 정책, 데이터 보존 조건. **모델별 프롬프트 변형**을 레지스트리에서 관리한다 ([[domain/프롬프트엔지니어링]]).

### 버전 고정과 지원 종료

- 별칭(최신을 가리키는 이름) 대신 **날짜·버전이 고정된 모델 식별자**를 쓰는 것이 일반적인 권장이다 [확인 필요: 공급사별 식별자 규칙].
- 공급사는 지원 종료 일정을 공개 페이지로 알린다 (예: Anthropic 모델 지원 종료 문서 https://platform.claude.com/docs/en/about-claude/model-deprecations). 일정을 M03 위험대장에 넣고, 종료 전에 후속 모델 회귀 평가를 끝낸다.
- 학기 중 모델 교체는 피하고 방학·학기 전 변경 동결 기간을 고려한다 ([[domain/학사일정]]).

### 모델 A/B

- 오프라인 평가 통과 후, 일부 트래픽(예: 5~10% [가정])에 새 모델을 배정하고 품질(학생 평점, 교사 신고), 안전 지표, 원가, 지연을 비교한다. 학습 결과 지표는 기간이 더 필요하다.
- 아동 대상은 실험 고지·보호자 정책과 안전 가드레일 지표를 먼저 정한다 ([[domain/AI평가메트릭과AB테스트]]).

## 에듀테크 맥락

- **K-12 학생 데이터**: 민감도 라우팅이 개인정보 보호의 핵심 장치다. E13·P07에 "어떤 데이터가 어느 모델로 가는지" 표를 둔다.
- **학교망**: 학교망에서 특정 공급사 도메인이 막히면 그 경로는 대체 경로로 넘어간다. 기관별 경로 설정이 필요할 수 있다.
- **교사 승인**: 교사용 자료 생성처럼 사람 검토가 있는 기능은 저비용 모델을 쓰기 쉽다.
- **학습 효과**: 큰 모델이 항상 교육적으로 낫지는 않다. 교수법 규칙 준수(정답 미제공)를 별도 평가한다.

## 방식별 차이

| 방식 | 라우팅에서의 역할 |
|------|------------------|
| M1·M2 | 라우터 자체(민감도·의도·난이도 판정) |
| M3 | 첫 경로(FAQ로 해결되면 LLM 미호출) |
| M4 | 학습 질문 경로 |
| M5 | 특정 과업 고정 경로 |
| M6 | 민감 데이터·대체 경로 |
| M7 | 고난도·열린 생성 경로 |

## 에듀테크 PM 적용

**체크리스트 (A11)**

- [ ] 후보 모델 비교표(평가 결과 기반)와 선택 근거를 남긴다
- [ ] 라우팅 순서(민감도 → 과업 → 난이도 → 비용)와 판정 방법·임계값을 적는다
- [ ] 기능별 시간 제한·재시도·대체 경로와 장애 시 사용자 문구를 P09와 맞춘다
- [ ] 모델 식별자 고정, 지원 종료 일정, 교체 절차(회귀 평가 → A/B → 전환)를 적는다
- [ ] 경로별 사용량·품질·원가를 A13 대시보드 항목으로 넣는다

**관련 산출물**: A11(주), A10, A12, A13, A06, P09, M03.

## 흔한 오해

- "리더보드 1위가 우리에게도 1위" — 한국어·교과·교수법 기준은 다르다.
- "대체 경로는 아무 모델이나" — 민감 데이터 정책과 가드레일을 지켜야 한다.
- "최신 별칭을 쓰면 자동으로 좋아진다" — 예고 없는 동작 변화가 회귀를 만든다.
