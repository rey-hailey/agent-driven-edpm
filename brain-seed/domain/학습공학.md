# 학습공학 (Learning Engineering)

> 학습 목표를 제품 기능·학습 데이터·실험으로 연결할 때 참고. 아래 루프와 역할표는 공개 정의를 EdPM 업무로 옮긴 실무 제안이다 [가정].

## 핵심 요약

- **학습공학**은 학습과학을 인간중심 설계·공학 방법·데이터에 근거한 의사결정과 결합해 학습자의 발달을 지원하는 과정과 실천이다 (IEEE ICICLE, https://sagroups.ieee.org/icicle/).
- 학습과학이 학습의 원리·가설을 제공하고, 데이터는 관찰 증거를, 공학은 구현·계측·반복 개선 수단을 제공하는 교차 영역으로 이해할 수 있다 (IEEE ICICLE 정의의 요약).
- 학습 설계와 연구용 콘텐츠·도구·데이터 인프라를 함께 다루는 공개 사례로 CMU의 **Open Learning Initiative(OLI)**가 있다. 연구·콘텐츠 수정·새 도구 통합을 지원한다고 설명한다 (https://oli.cmu.edu/research/).
- 제품에서는 **설계 → 계측(telemetry) → 실험 → 개선** 루프로 운영한다 [가정: 이 페이지의 실행 틀]. 클릭·체류시간의 변화와 학습 성과를 구분하는 지표 설계는 [[domain/학습분석지표]]를 참고한다.

## 상세

### 학습과학·데이터·공학의 교차

IEEE ICICLE의 정의를 다음 업무 질문으로 구체화한다 [가정]. 기술 적용 자체가 아니라 학습 지원이라는 목적에서 출발한다 (IEEE ICICLE).

| 관점 | 물을 질문 | 결과물 예 |
|------|-----------|-----------|
| 학습과학 | 어떤 학습 문제를 어떤 메커니즘으로 바꿀 것인가 | 학습목표, 교수 가설, 형성평가와 피드백 설계 |
| 데이터 | 목표 변화의 어떤 흔적을 관찰할 수 있는가 | 이벤트·측정 도구·지표·분석 단위 |
| 공학 | 같은 개입을 재현하고 결과를 비교할 수 있는가 | 콘텐츠·코드 버전, 실험 배정, 계측 검증, 배포·되돌리기 |
| 인간중심 설계 | 학습자·교사의 실제 맥락에서 가능한가 | 관찰·사용성 검증, 접근성, 교사 운영 경로 |

### 설계 → 계측 → 실험 → 개선

아래는 EdPM 적용 제안이다 [가정]. 단계 번호는 국제표준이나 인증 절차가 아니다.

| 단계 | 할 일 | 다음 단계로 넘길 증거 |
|------|-------|----------------------|
| 1. 설계 | 목표·대상·개입 메커니즘·비교 조건 정의 | 학습목표에 정렬된 독립 평가 증거, 성공·중단 조건 |
| 2. 계측 | 행동 이벤트와 결과 측정 연결 | 이벤트 명세, 표본 로그 검증, 결측·중복 점검 |
| 3. 실험 | 개입 버전을 비교하고 실행 충실도 확인 | 배정·노출·탈락 기록, 사전·사후·지연 측정 |
| 4. 개선 | 효과·부담·비용을 함께 보고 유지·수정·폐기 | 판단 근거, 변경 버전, 다음 검증 가설 |

예: **풀이 예제 뒤 자기설명 질문을 넣는다**는 기능안만 쓰지 않고, 목표 개념·기대 메커니즘·교사 검토·독립 전이 문항·질문 노출 로그·비교 조건까지 한 묶음으로 명세한다 [가정: 설명용 가상 사례이며 효과가 검증됐다는 뜻은 아님].

### 계측(telemetry)을 학습 증거로 연결

- 학습 활동 기록의 공개 표준인 **xAPI**는 Statement에 행위자(Actor), 행위(Verb), 대상(Object)을 표현하고 Result·Context·Timestamp 등을 담을 수 있게 한다. 이벤트 형식이 곧 학습 효과를 보장하는 것은 아니다 (ADL xAPI Specification, Part Two, §2.4).
- 제품에서는 **의도한 개입 → 실제 배정 → 실제 노출 → 학습 행동 → 결과 측정**을 구분해 기록한다. "힌트 버튼 클릭"만으로 힌트 내용을 읽거나 이해했다고 판정하지 않는다 [가정: 계측 해석 원칙].
- 이벤트에는 개념·문항·콘텐츠·실험 버전과 가명 학습자 키를 연결하고, 수집 목적·최소 필드·보관 기간을 정한다 [가정: 데이터 설계 제안].
- 결과 지표·참여 지표·사업 지표·가드레일은 분리해 해석한다. 기존 정의와 계산 경로는 [[domain/학습분석지표]]를 따른다.

### 학습 엔지니어의 역할

아래는 **권장 역할 분담**이며, 특정 자격·직무의 공인 요건이 아니다 [가정]. 학습과학·설계·공학·데이터를 연결한다는 범위는 IEEE ICICLE 정의를 따른다.

| 협업 상대 | 함께 책임질 것 |
|-----------|----------------|
| 교사·내용 전문가·교수설계자 | 목표·교수 가설·평가 정렬, 수업 실행 가능성 |
| 데이터 분석가·연구자 | 측정 타당도, 비교 설계, 결과 해석 |
| 개발자·데이터 엔지니어 | 이벤트 계약, 배정·노출의 재현성, 데이터 품질 |
| 디자이너·접근성 담당 | 학습 행동을 방해하지 않는 UI와 사용성 |
| PM·운영 담당 | 개선 우선순위, 출시·중단 결정, 현장 실행 |

학습 엔지니어의 핵심 산출물을 **가설·설계·이벤트·실험·결정 사이의 추적 가능한 연결**로 둔다. 한 사람이 모든 전문 업무를 대체하는 구조로 만들지 않는다 [가정].

### A/B·효과측정과 연결

다음은 실험 명세 제안이다 [가정]. 연구설계와 효과 해석의 근거는 [[domain/효과크기와증거수준]], 제품 실험 절차는 [[domain/AI평가메트릭과AB테스트]]를 참고한다.

- **A/B**: 비교 버전·배정 단위(학습자/학급/학교)·기간·주 결과 지표·가드레일을 먼저 정한다. 교사가 개입을 공유하는 수업이면 집단 간 섞임을 검토한다.
- **실행 확인**: 배정됐지만 노출되지 않은 경우, 계측 누락, 결과 검사 미응시를 구분한다. 배정 기준 분석과 실제 사용량 분석을 섞지 않는다.
- **효과 해석**: 효과크기와 신뢰구간, 사전 차이·탈락·측정 도구·기간을 함께 보고한다. 비교군 없는 향상을 제품의 인과 효과라고 쓰지 않는다 (WWC 기준에 대한 [[domain/효과크기와증거수준]]의 정리).
- **판단**: 표본 수·검정력·최소 탐지 효과는 설계에 맞춰 산출한다 [확인 필요: 제품별 산출 근거]. Kraft(2020)는 교육 개입의 효과크기를 연구·측정·비용·확장 맥락에서 해석해야 함을 논의한다 (https://doi.org/10.3102/0013189X20912798).

## 에듀테크 PM 적용

**체크리스트 (E05 → E12 → E16 → E19)** — 실무 제안 [가정].

- [ ] 학습목표·평가 증거를 먼저 정하고 기능을 설계한다 ([[domain/역방향설계]])
- [ ] 각 기능에 학습 가설·반증 조건·측정 도구를 연결한다
- [ ] 개발 전에 이벤트 명세·배정 단위·노출 정의를 확정하고 계측을 검증한다
- [ ] 실험 버전과 콘텐츠·모델 버전을 함께 고정해 비교 가능하게 한다
- [ ] 학습 효과·실행 충실도·교사 부담·접근성·비용을 함께 보고한다
- [ ] 결과가 불명확하면 개선 가설을 기록하고, 유의한 지표만 골라 성공으로 보고하지 않는다

**관련 산출물**: E05, E07, E08, E12, E16, E17, E19, E20.

## 흔한 오해

- "학습공학은 학습 로그를 많이 쌓는 일" — 정의에는 학습과학·인간중심 설계·공학·데이터 의사결정이 함께 들어간다 (IEEE ICICLE).
- "A/B에서 클릭률이 오르면 교육 효과도 확인됐다" — 참여와 학습 결과를 별도 지표로 둔다 ([[domain/학습분석지표]]).
- "효과크기 하나로 다음 출시를 결정한다" — 연구 설계·측정·대상·비용·확장성을 함께 해석한다 (Kraft, 2020).
