# 교육 기술 상호운용 표준

## 핵심 요약

- 교육용 소프트웨어는 LMS·학사시스템·평가 시스템과 연결되어야 쓰인다. 표준 지원 여부가 기관 구매의 전제조건이 되는 경우가 많다 (특히 미국 K-12·고등교육·기업교육).
- 주요 표준 관리 주체: **1EdTech**(구 IMS Global: LTI, OneRoster, QTI, Caliper, CASE), **ADL/IEEE**(SCORM, xAPI, cmi5), **Ed-Fi Alliance**(Ed-Fi 데이터 표준).
- 한국 K-12 공교육에서 이 표준들이 어떻게 요구되는지는 사업·교육청마다 다르다 [확인 필요]. 국내 학교 계정·명단은 별도 국가·교육청 시스템과 연동하는 경우가 많다 [확인 필요].

## 상세

### 표준별 요약

| 표준 | 무엇을 표준화하나 | 최신 버전 (확인 상태) | 주로 중요한 세그먼트 |
|------|-------------------|------------------------|----------------------|
| LTI 1.3 / LTI Advantage | LMS에서 외부 도구를 보안(OAuth2/OIDC) 실행. Advantage는 성적 반환(AGS), 명단(NRPS), 딥링킹 서비스 묶음 | LTI 1.3이 최신 핵심 버전 (https://www.1edtech.org/standards/lti) [verified 2026-10-12] | 고등교육, 미국 K-12, LMS 연동이 필요한 모든 B2B |
| OneRoster | 학생·교사·학급·등록 명단과 성적 교환 (CSV, REST) | 1.2 (2022.9) (https://www.1edtech.org/standards/oneroster) [verified 2026-10-12] | 미국 K-12 (학사시스템↔앱 자동 명단) |
| QTI | 문항·시험 구조와 결과 교환 | 3.0 (2022.5) (https://www.1edtech.org/standards/qti/versions) [verified 2026-10-12] | 평가·문항은행, 출판사 |
| Caliper Analytics | 학습 활동 이벤트 데이터 모델 | 버전 [확인 필요] (1.2로 알려짐) | 고등교육 학습분석 |
| CASE | 성취기준·역량 체계의 기계 판독형 교환 | 버전 [확인 필요] | 성취기준 정렬, 미국 K-12 |
| xAPI | "행위자-동사-대상" 학습 경험 기록을 LRS에 저장 | xAPI 2.0 = IEEE 9274.1.1-2023 (https://adlnet.gov/news/2023/11/22/xAPI-Officially-Becomes-a-Published-IEEE-Standard) [verified 2026-10-12] | 기업교육, 시뮬레이션, 모바일·오프라인 학습 |
| cmi5 | xAPI 위에서 LMS 실행·완료·합격 규칙 정의 (SCORM 대체 지향) | IEEE 표준화 상태 [확인 필요: 출처 간 상충] | 기업교육 LMS |
| SCORM | 이러닝 콘텐츠 패키징과 LMS 실행·추적 | SCORM 2004 4th Edition이 마지막 판으로 알려짐 [확인 필요]. 현장에서는 SCORM 1.2도 널리 쓰임 [가정] | 기업교육 HRD, 공공 이러닝 |
| Ed-Fi | 미국 주·학군 단위 학생 데이터 통합 모델 | 버전 [확인 필요] (https://www.ed-fi.org) | 미국 주·학군 데이터 시스템 |

### 표준 간 관계

- LTI = "실행·연결", OneRoster = "명단", QTI = "문항", Caliper·xAPI = "활동 로그", CASE = "성취기준 사전".
- OneRoster 1.2는 성적 항목을 CASE 식별자와 연결할 수 있게 했다 (1EdTech 블로그 https://www.1edtech.org/blog/rostering-resources-and-gradebook-standards).

## 상충하는 근거

- cmi5의 IEEE 표준 번호(9274.3.1) 확정 여부: 미 국방부 문서는 IEEE 9274.3.1로 표기하지만 Rustici Software(2023)는 표준화 진행 중으로 설명한다 (https://rusticisoftware.com/blog/what-happened-in-2023-and-whats-next-for-elearning-standards/). 사용 전 IEEE 표준 목록으로 확인한다.

## 에듀테크 PM 적용

- [ ] 세그먼트별 필수 표준을 E06 비기능 요구사항에 명시한다: 고등교육 → LTI 1.3, 미국 K-12 → OneRoster + LTI, 기업교육 → SCORM/xAPI/cmi5, 평가 제품 → QTI
- [ ] 1EdTech 인증 여부가 구매 체크리스트 항목인지 확인한다 (미국 학군·대학) [가정]
- [ ] 학습 이벤트 로그 스키마(E12)를 처음부터 xAPI 또는 Caliper 형태에 매핑 가능하게 설계하면 나중 연동 비용이 줄어든다 [가정]
- [ ] 문항 메타데이터에 성취기준 코드를 넣는다. 국내는 교육과정 성취기준 코드, 해외는 CASE GUID ([[domain/블룸분류체계]] 태그와 함께)
- [ ] 국내 공교육: 교육청 계정 연동·SSO 요구, 학습 데이터 제출 형식 요구를 사업 공고문에서 확인한다 [확인 필요]
- [ ] 명단 연동이 교사의 수업 전 준비 시간을 줄이는 핵심 기능임을 기억한다 ([[domain/교사참여설계]])

## 흔한 오해

- "SCORM은 죽었다" — 기업교육 LMS에서는 여전히 기본 요구사항인 경우가 많다 [가정].
- "xAPI만 지원하면 LMS 연동 끝" — xAPI는 기록 형식이지 실행 규칙이 아니다. LMS 실행에는 cmi5나 LTI가 필요하다.
- "LTI 1.1이면 충분" — 1EdTech는 보안상 이유로 LTI 1.3으로의 이전을 권고해 왔다 [확인 필요: 1.1 지원 종료 공지 원문].
