# 학습 이탈 예측

> A09 학습이탈예측설계서를 쓸 때 참고. 목표는 "누가 그만둘지 맞히기"가 아니라 **개입으로 결과를 바꿀 수 있는 학습자를 찾아 제때 돕기**다. LLM이 아니라 고전 ML·규칙으로 만든다.

## 핵심 요약

- 이탈 정의는 서비스 유형마다 다르다: **과정 미완주**(VOD·환급 과정), **구독 해지**(소비자 앱), **비활성**(N일 미접속). 정의가 개입 시점과 지표를 정한다.
- **레이블과 예측 시점(horizon)**을 먼저 정한다: "가입 후 7일 시점의 데이터로, 이후 21일 안에 비활성이 될지"처럼. 미래 정보가 특징에 섞이는 **누수(leakage)**가 가장 흔한 실패다.
- 특징은 학습 이벤트(**최근성, 빈도, 진도 속도, 퀴즈 성과, 도움 요청, 세션 패턴**)에서 만들고, **규칙 기준선과 로지스틱 회귀**를 먼저 만든다.
- 평가는 정확도가 아니라 **개입 용량에서의 정밀도·재현율**(예: 하루에 연락할 수 있는 100명 중 실제 위험자 비율), **보정(calibration)**, 그리고 **업리프트**(개입으로 바뀌는 사람)로 본다.
- 예측 점수는 학습자 지원에만 쓰고 자동 불이익에 쓰지 않는다 (자동화된 결정 대응권, 개인정보 보호법 제37조의2, [[domain/학습데이터프라이버시]]).

## 상세

### 문제 정의 (유형별)

| 유형 | 이탈 정의 예 | 예측 시점 | 개입 |
|------|--------------|-----------|------|
| AT01 VOD 과정 | 수강 기간 내 진도 80% 미도달 | 구매 후 7일 | 학습 계획 알림, 짧은 강부터 추천 |
| AT02 환급 과정 | 수료 기준 미충족 | 기간 중간 | 담당자 독려, 마감 안내 |
| AT03 부트캠프 | 중도 하차 | 매주 | 멘토 1:1 상담 |
| AT07 구독 앱 | 다음 결제 전 해지 | 결제 14일 전 | 목표 재설정, 난이도 조정 |
| AT08 대학·평생교육 | 학기 중 포기·낙제 | 3~4주차 | 학업 상담 연결 |

### 레이블·시간 설계

- **관찰 구간**(특징 계산, 예: 시작 후 0~7일)과 **예측 구간**(레이블, 예: 8~28일)을 나눈다. 특징은 관찰 구간 끝까지의 이벤트만 쓴다 ("최종 진도율"을 특징으로 쓰면 누수). 학습·검증은 **시간 기준으로 분할**하고(과거 코호트로 학습, 최근 코호트로 검증), 학기·방학 계절성을 고려한다 ([[domain/학사일정]]).

### 특징 (예)

| 범주 | 특징 | 해석 |
|------|------|------|
| 최근성 | 마지막 학습 후 경과일 | 강한 신호인 경우가 많음 [가정: 서비스별 확인] |
| 빈도 | 최근 7일 학습일 수, 세션 수 | |
| 진도 속도 | 기대 진도 대비 실제 진도 | 기간제 과정에서 중요 |
| 퀴즈 성과 | 최근 퀴즈 정답률, 연속 오답 | 좌절 신호 |
| 도움 요청 | 힌트 사용, 질문 게시, AI 튜터 질문 수 | 위험 신호일 수도, 참여 신호일 수도 |
| 세션 패턴 | 평균 세션 길이 감소, 중도 이탈 강 | 콘텐츠 문제와 구분 필요 |
| 맥락 | 가입 경로, 결제 유형(본인·회사), 기기 | 민감 속성은 공정성 점검용으로만 |

### SQL 특징 예

테이블: `learning_events(learner_id, event_type, occurred_at, lesson_id, score)`, `enrollments(learner_id, course_id, started_at)`
```sql
-- 관찰 구간: 시작 후 7일. 기준 시점 이후 이벤트는 쓰지 않는다 (누수 방지)
WITH obs AS (
  SELECT e.learner_id, e.course_id, e.started_at,
         e.started_at + INTERVAL '7 day' AS cutoff
  FROM enrollments e
)
SELECT
  o.learner_id,
  DATE_PART('day', o.cutoff - MAX(le.occurred_at))              AS days_since_last,
  COUNT(DISTINCT DATE(le.occurred_at))                          AS active_days_7d,
  COUNT(DISTINCT le.lesson_id) FILTER (WHERE le.event_type = 'lesson_complete') AS lessons_7d,
  AVG(le.score) FILTER (WHERE le.event_type = 'quiz_submit')    AS quiz_avg_7d,
  COUNT(*) FILTER (WHERE le.event_type = 'hint_request')        AS hints_7d
FROM obs o
LEFT JOIN learning_events le
  ON le.learner_id = o.learner_id
 AND le.occurred_at >= o.started_at
 AND le.occurred_at <  o.cutoff
GROUP BY o.learner_id, o.cutoff;
```

```sql
-- 레이블 (위 obs CTE를 이어서 사용): 8~28일 사이 학습 이벤트가 하나도 없으면 비활성(1)
SELECT o.learner_id,
       CASE WHEN COUNT(le.learner_id) = 0 THEN 1 ELSE 0 END AS churn_label
FROM obs o
LEFT JOIN learning_events le
  ON le.learner_id = o.learner_id
 AND le.occurred_at >= o.cutoff
 AND le.occurred_at <  o.started_at + INTERVAL '28 day'
GROUP BY o.learner_id;
```

### 모델 순서 (이벤트 정의는 E12·L03과 같게)

1. **규칙 기준선** ("3일 이상 미접속 AND 진도 기대치 50% 미만") → 2. **로지스틱 회귀** (계수로 설명, 보정 양호) → 3. **트리 기반 모델**(그래디언트 부스팅 등)은 기준선 대비 precision@K가 의미 있게 오를 때만.
- **LLM을 예측에 쓰지 않는다** (비용·재현성·보정·설명 가능성 모두 불리). LLM은 개입 메시지 초안에만 쓴다.

### 평가

| 지표 | 왜 |
|------|-----|
| 개입 용량에서의 정밀도 (precision@K) | 연락 가능한 K명 중 실제 위험자 비율 |
| 재현율 (recall@K) | 위험자 중 몇 %를 잡는가 |
| 보정 | 예측 확률 30%인 집단의 실제 이탈률이 30% 근처인가 (위험 등급 표시에 필요) |
| PR-AUC, 집단별 성능 차이 | 이탈이 드물 때 ROC-AUC보다 유용 / 공정성 점검 |

- **예측 ≠ 개입 효과**: 위험이 가장 높은 사람은 무엇을 해도 떠날 수 있고, 위험이 낮은 사람은 개입 없이도 남는다. 개입으로 결과가 바뀌는 사람을 찾는 것이 **업리프트 모델링**이며, 무작위 실험 데이터가 있어야 추정할 수 있다.

### 개입 설계와 실험

- 개입: 자동 넛지(알림, 학습 계획), 콘텐츠 조정(난이도, 짧은 강), 사람 연락(튜터·담당자). **A/B 테스트**로 위험 점수 상위 집단을 무작위로 개입/비개입으로 나눠 완주율·재활성화율 차이를 본다. 알림 피로(수신 거부, 해지 증가)를 가드레일 지표로 둔다 ([[domain/학습분석지표]], [[domain/동기설계]]). 개입 후 행동이 바뀌면 모델 분포가 변하므로 주기적으로 재학습하고, 비개입 대조군을 소량 유지한다.

### 공정성·프라이버시·투명성

- 민감 속성을 빼도 대리 변수로 편향이 생길 수 있으므로 집단별 정밀도·재현율·보정을 비교한다. 학습 패턴 기반 도움 제안 사실을 고지하고, 교사에게는 점수 대신 "연락이 필요한 학생"과 근거(미접속 5일)만 보여 준다. 고용주에게 위험 점수를 보내지 않는다. 불이익 조치(수강 제한, 환불 거절)에 쓰지 않는다.

## 서비스 유형별 차이

위 문제 정의 표 참조. 추가로 AT02는 고용주 보고와 분리, AT05 K-12는 교사 주도 개입과 아동 데이터 기준([[domain/아동개인정보보호]]), AT07은 구독 결제 주기와 연동, AT09는 시험일 역산 진도로 위험을 정의한다.

## 에듀테크 PM 적용

**체크리스트 (A09 학습이탈예측설계서)**

- [ ] 이탈 정의, 관찰 구간, 예측 구간을 정하고, 특징 SQL을 E12 이벤트 정의에 맞추고 누수 점검을 리뷰 항목에 넣는다
- [ ] 규칙 기준선 → 로지스틱 회귀 순서로 비교하고, 개입 용량(K)을 운영팀과 정하고 precision@K와 집단별 성능 차이로 평가한다
- [ ] 개입 A/B 테스트 설계(대조군, 가드레일 지표)를 E16에 넣는다
- [ ] 점수 사용처·노출 범위·고지 문구를 E13에 기록한다

**관련 산출물**: A09(주), E07, E12, E13, E16, A00.

## 흔한 오해

- "AUC가 높으면 좋은 모델" — 개입 용량에서의 정밀도와 개입 효과가 중요하다.
- "위험 상위부터 연락하면 된다" — 개입으로 바뀌지 않는 사람일 수 있다.
- "최신 AI 모델로 예측하자" — 기준선 모델이 대부분의 가치를 내는 경우가 많다 [가정].
