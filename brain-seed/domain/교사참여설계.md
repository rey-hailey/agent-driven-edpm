# 교사 참여 설계 (Teacher-in-the-loop, 수업 오케스트레이션)

## 핵심 요약

- 학교에서 쓰는 에듀테크의 실제 사용 여부는 교사가 결정한다. 교사가 수업 흐름 안에서 쉽게 통제·조정할 수 없는 도구는 도입돼도 쓰이지 않는다 [가정: 현장 관찰로 보강 필요].
- **수업 오케스트레이션**: 교사가 제한된 시간·공간·주의 자원 안에서 여러 활동과 학생을 실시간으로 관리하는 일. Dillenbourg(2013)는 교실 도구 설계가 이 제약을 우선 고려해야 한다고 주장했다 (https://doi.org/10.1016/j.compedu.2013.04.013).
- **Teacher-in-the-loop**: AI·적응형 시스템이 판단을 대신하기보다 교사가 결과를 보고 개입·수정할 수 있게 설계하는 원칙. 교사용 실시간 도구(예: 스마트 안경 대시보드 연구)가 학습 향상과 연결된 사례가 있다 (Holstein, McLaren & Aleven, 2018, AIED, https://doi.org/10.1007/978-3-319-93843-1_12).

## 상세

### 교사가 도구를 평가하는 실제 기준 [가정: 일반화된 현장 통념, 인터뷰로 검증]

| 기준 | 질문 |
|------|------|
| 준비 시간 | 수업 전 세팅에 몇 분이 드나? 학생 계정 생성·로그인이 수업 시간을 잡아먹지 않나? |
| 수업 중 통제 | 화면 잠금, 일시 정지, 전체 진도 맞추기가 되나? |
| 가시성 | 누가 막혔는지 수업 중에 바로 보이나? |
| 업무 추가 | 채점·기록·보고 업무를 줄이나, 늘리나? |
| 교육과정 정렬 | 우리 학교 교과서·성취기준·진도와 맞나? |
| 책임·민원 | 학부모 민원, 개인정보 사고 시 교사에게 부담이 오지 않나? |

### 업무 부담 맥락

- OECD TALIS 2018에서 한국 중학교 교사는 행정 업무를 주요 스트레스 요인으로 꼽은 비율이 높게 나타났다 [확인 필요: 구체 수치는 TALIS 원자료 확인 후 인용] (https://www.oecd.org/education/talis/).
- 따라서 "교사 업무를 덜어 준다"는 가치 제안은 강력하지만, 실제로는 새 도구가 계정 관리·연수·보고 업무를 추가하는 경우가 흔하다 [가정].

## 에듀테크 PM 적용

- [ ] 교사 여정을 수업 전(준비) / 수업 중(오케스트레이션) / 수업 후(채점·기록·상담)로 나눠 각 단계 소요 시간을 측정한다 (E03, E08)
- [ ] 학생 계정 생성·로그인을 수업 시간 밖으로 빼는 방법(명단 연동, 학급 코드, SSO)을 설계한다 ([[domain/상호운용표준]])
- [ ] AI 추천·자동 판정은 교사가 보고 덮어쓸 수 있게 한다 (E14 G-AI). 특히 학생 평가에 쓰는 AI는 고영향 AI 해당 여부를 검토한다 ([[domain/아동개인정보보호]])
- [ ] 교사 대시보드는 "지금 개입할 학생 3명"처럼 행동 가능한 요약을 제공하고, 차트 나열을 피한다
- [ ] 교사 파일럿 지표: 수업당 실제 사용 시간, 재사용 의향, 준비 시간, 교사가 개입한 횟수 (E16, E17)
- [ ] 연수·온보딩은 학사일정의 연수 가능 시기(방학, 학기 초 전)에 맞춘다 ([[domain/학사일정]])

## 흔한 오해

- "학생이 좋아하면 교사는 따라온다" — 공교육에서는 교사가 사용 게이트키퍼다.
- "AI가 교사를 대체한다" — 수업 운영·관계·판단 책임은 교사에게 남는다. 제품은 교사의 판단을 돕는 방향이 도입 저항이 적다 [가정].
- "기능이 많을수록 교사에게 유용하다" — 수업 중 교사의 주의 자원은 매우 제한적이다.
