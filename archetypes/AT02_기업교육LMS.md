# AT02 기업교육 LMS

## 1. 정의와 예

기업이 임직원 교육을 배정·운영·증빙하는 학습관리 서비스입니다. 자체 콘텐츠 라이브러리를 좌석 단위로 파는 형태, 고객사 콘텐츠를 올려 쓰는 LMS 솔루션 형태, 사업주 직업능력개발훈련(환급 과정) 운영을 대행하는 형태가 섞여 있습니다.

| 형태 | 설명 | 범주 예시 |
|------|------|-----------|
| 콘텐츠 구독형 | 직무·리더십 라이브러리를 좌석·기업 단위 구독 | 기업용 이러닝 라이브러리형 |
| LMS 솔루션형 | 고객사 콘텐츠·SCORM 패키지 업로드, 배정·리포트 | Cornerstone·Docebo형, 국내 HRD 솔루션형 |
| 위탁 운영형 | 법정 의무교육·환급 과정 운영, 수료 증빙 대행 | 원격훈련기관형 |

## 2. 이해관계자와 구매 구조

| 역할 | 누구 | 원하는 것 |
|------|------|-----------|
| 사용자 | 임직원 학습자 | 업무 중 짧게, 필수 교육은 빨리 끝내기 |
| 운영 사용자 | HRD 담당자 (기업 관리자) | 배정·독려·수료 현황·증빙 자동화 |
| 의사결정자 | HRD 팀장·인사 임원, 큰 계약은 구매·IT 보안 | 예산 대비 효과, 보안 심사 통과 |
| 결제자 | 회사 교육 예산 (환급 과정은 일부 환급) | 연간 계약, 정산 명확성 |
| 현업 관리자 | 팀장 | 팀원 역량 변화, 업무 공백 최소화 |

사용자(학습자)와 구매자(HRD)가 분리되어 **학습자 경험보다 관리자 리포트가 계약을 좌우**하기 쉽습니다. E02에서 둘을 모두 SH로 두고, E07에서 학습 효과 지표를 관리자 리포트에 노출합니다 ([[domain/세그먼트별의사결정구조]]).

## 7. 규제·리스크 포인트

- **환급 과정**: 사업주 직업능력개발훈련 지원의 인정 요건(진도·시간·평가·모사 답안 기준), 훈련 기관 요건, 심사 일정 [확인 필요]. 요건은 L03·L04·P03에 계산식으로 반영합니다.
- **법정 의무교육**: 직장 내 성희롱 예방, 개인정보 보호, 산업안전 등 의무교육의 이수 시간·증빙 요건 [확인 필요].
- **개인정보·보안**: 고객사 보안 심사(ISMS 등 인증 요구), 데이터 위치, 위탁 계약 [확인 필요]. [[domain/학습데이터프라이버시]]
- **평가 데이터 활용**: 학습 기록을 인사 평가에 쓰는지 고객사와 합의하고 학습자에게 고지합니다.
- **접근성**: 공공기관·대기업 고객은 웹 접근성 요구 ([[domain/접근성]]).
- **콘텐츠 권리**: 고객사 업로드 콘텐츠와 플랫폼 콘텐츠의 권리 분리 ([[domain/강사계약과콘텐츠권리]]).

## 9. 자주 하는 실수

- 관리자 리포트만 공들이고 학습자 경험(모바일·짧은 단위)을 방치한다.
- 환급 과정 요건을 개발 후에 확인해 진도·평가 로직을 다시 만든다.
- SSO·HRIS 연동(L05)을 고객사마다 일회성으로 구현해 유지보수가 폭증한다.
- 완료율을 북극성으로 둬서 학습 효과 증명을 못 한다.
- 고객사 보안 심사 문서(B04·E13)가 없어 계약이 지연된다.
- 대리 수강 방지(P03)를 개인정보 영향 검토 없이 강하게 적용해 민원이 생긴다.
