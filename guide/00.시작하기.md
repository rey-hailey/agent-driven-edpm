# 시작하기: 설치와 문제 해결

이 문서는 설치·옵션·외부 도구·문제 해결만 다룹니다. 무엇을 하는 프레임워크인지와 스킬 목록은 [README](../README.md), 설치 이후 실제 순서는 [14.AtoZ사용가이드](14.AtoZ사용가이드.md)를 보세요.

## 1. 필요한 것

| 도구 | 버전 | 확인 | 설치 |
|------|------|------|------|
| Claude Code | 최신 | `claude --version` | [claude.com/claude-code](https://claude.com/claude-code), 설치 후 `claude`로 로그인 |
| python3 | 3.9 이상 | `python3 --version` | macOS: `xcode-select --install` 또는 `brew install python` |
| git | 아무 버전 | `git --version` | macOS: `xcode-select --install` |
| bash | 3.2 이상 | 기본 포함 | Windows는 WSL |

스크립트는 표준 라이브러리만 씁니다. LLM 위키는 따로 설치하는 도구가 아니라 워크스페이스의 `02.wiki/` 폴더와 `/edpm-wiki` 스킬입니다.

쓰는 기능에 따라 필요한 것 (없어도 나머지는 동작):

| 도구 | 필요한 기능 |
|------|-------------|
| [Antigravity](https://antigravity.google) + Claude Code 확장 | 권장 작업 환경: 폴더·문서를 보면서 작업 (2절). 없으면 터미널의 `claude`로도 동작 |
| [Obsidian](https://obsidian.md) | 위키·산출물을 링크·그래프로 보기 (워크스페이스 폴더를 볼트로) |
| GitHub CLI `gh` (`gh auth login`) | WBS를 GitHub 이슈·마일스톤·Projects로 공유 |
| Node.js 20 이상 | P4 코드 MVP, 공식 `pptx`·`docx` 스킬 |
| `pip install anthropic` + `ANTHROPIC_API_KEY` | `/edpm-ai eval`의 Claude 평가 (비용 발생). 없으면 로컬 모델이나 정확 일치 채점만 |
| Ollama·vLLM·llama.cpp | 로컬 LLM 평가·비교 |
| pandoc / Chrome | 산출물 Word 출력 / PDF 출력 (`edpm_export.py`) |
| Aside CLI | `/edpm-wiki collect` 웹 수집 (없으면 자료를 `00.inbox/`에 직접) |
| 디스크 300MB + 네트워크 | 교육과정 지식그래프 (`--with-kg`) |

`./install.sh --check`가 위 도구와 외부 스킬을 한 번에 점검합니다.

## 2. 작업 환경: Antigravity + Claude Code 확장 (권장)

산출물이 모두 마크다운 파일이라, 폴더와 문서를 옆에 띄워 두고 일하는 것이 가장 편합니다. 권장 조합은 **Antigravity(에디터) + Claude Code 확장(에이전트)** 입니다.

| 단계 | 할 일 |
|------|-------|
| 1 | [Antigravity](https://antigravity.google) 설치. 에디터 앱 이름은 **Antigravity IDE**입니다. 같은 Mac에 별도 앱 `Antigravity`가 함께 있을 수 있으니, 워크스페이스는 `Antigravity IDE`로 엽니다 |
| 2 | 확장(Extensions)에서 **Claude Code** 설치 후 로그인 |
| 3 | File > Open Folder → 워크스페이스 폴더 (대화형 설치는 마지막에 바로 열지 묻습니다) |
| 4 | 오른쪽 아래 "권장 확장 설치" 알림이 뜨면 설치: Claude Code, Mermaid 미리보기, CSV 보기 (워크스페이스 `.vscode/extensions.json`) |
| 5 | Claude Code 패널을 열고 `/edpm-start` |

일하는 모습:

- 왼쪽 탐색기에서 `PRD.md`, `03.docs/`, `06.prototypes/`를 바로 엽니다. 마크다운 미리보기는 `Cmd+Shift+V`, 옆에 띄우기는 `Cmd+K V`. 표와 Mermaid 다이어그램(상태 흐름 포함)이 그대로 보입니다.
- 에이전트가 문서를 고치면 탐색기와 편집기에 바로 반영되고, 변경 내용은 소스 제어 탭(git diff)에서 확인합니다.
- **대시보드**: `.edpm/dashboard.html`을 브라우저로 열어 옆 화면에 두세요 (`/edpm-brief dashboard`가 열어 줌). 가운데는 탭 세 개입니다: **여정**(단계별 칸에 문서 카드 — 상태·기다리는 것·수정일·**다음 할 일 명령**(복사해서 Claude Code에 붙여 넣기), 지금 단계와 "지금 할 일" 카드 강조. 카드는 끌어 옮기지 않습니다 — 상태는 문서와 훅이 정합니다, 아래에 프로토타입·운영 개선 과제·결정·관리 줄), **스펙 추적**(E09·F02의 기능마다 REQ → 유저스토리 → 인수조건 → 상태 흐름 → 작업 → 테스트가 이어지는지, 끊긴 곳 표시), **화면**(E10의 모든 화면 목록과 빠진 것, 누르면 **화면 지도** `.edpm/screens.html` — 화면별 저충실도 프레임·상태 탭, 버튼을 누르면 연결된 화면으로 이동. 보여주는 실무형 화면설계서는 `edpm_screens.py --sb-md` → sb-lowfi 스킬, 만들어 두면 화면 지도가 화면마다 링크), **지식**(위키·산출물 그래프 — 위키가 쌓일수록 쓸모가 커지고, 링크를 깊이 따라가려면 같은 폴더를 Obsidian으로). 왼쪽은 지금 단계와 다음 명령·PRD 명확도·진행 요약·WBS 달력·최근 파일, 오른쪽은 주의·스킬·최근 활동입니다. 문서를 저장할 때마다 훅이 다시 만들고, 화면은 조용할 때 스스로 새로 읽습니다. 문서·그래프의 점을 누르면 편집기에서 그 파일이 열립니다. 설치된 편집기를 Antigravity IDE → Cursor → VS Code 순서로 찾으며, 직접 정하려면 환경변수 `EDPM_EDITOR_URL`(예: `antigravity-ide://file`, `cursor://file`)을 쓰고 `/edpm-brief dashboard`로 다시 만듭니다. 보기 전용입니다 — 상태를 바꾸는 일은 Claude Code가 합니다.
- 클릭 프로토타입(`06.prototypes/**/*.html`)은 파일을 우클릭해 브라우저로 엽니다.
- 보관함 `.edpm/library/`는 탐색기에는 보이지만 검색에서는 빠집니다 (같은 문서가 두 번 검색되지 않도록). 꺼내는 것은 `/edpm-doc <ID>`로 합니다.

**주의: EdPM 작업은 Claude Code 패널에서 하세요.** 스킬(`/edpm-*`), 세션 시작 상황판, 순서를 지키는 훅은 Claude Code 기능입니다. Antigravity에 내장된 에이전트로 작업하면 `AGENTS.md`는 읽더라도 스킬과 훅이 동작하지 않아, "A가 끝나야 B"나 개인정보 차단 같은 장치가 꺼질 수 있습니다. 상황판이 패널에 보이지 않으면 `/edpm-brief`로 부릅니다.

다른 환경:

| 환경 | 언제 |
|------|------|
| Cursor·VS Code + Claude Code 확장 | 이미 쓰는 에디터가 있을 때. 같은 `.vscode/` 설정을 그대로 씀 |
| 터미널만 (`cd <워크스페이스> && claude`) | 원격 서버, 가벼운 작업 |
| Obsidian (같은 폴더를 볼트로) | 위키 링크·그래프를 볼 때. 작업은 에디터에서, 보기는 Obsidian으로 함께 써도 됨 |

## 3. 설치

```bash
git clone https://github.com/rey-hailey/agent-driven-edpm.git && cd agent-driven-edpm
./install.sh                                              # 대화형: 이름·위치·업무 모드·개발 체계를 묻습니다
./install.sh ~/Work/우리회사-edpm --mode F --dev team       # 직접 지정
```

| 옵션 | 뜻 |
|------|----|
| `--mode N\|F\|NF` | 업무 모드: 새 서비스(N) / 운영 중 서비스 개선(F) / 둘 다. 모드 문서(N01·N03·N04 또는 F00·백로그·과제 템플릿)를 함께 꺼냅니다 — [09.업무모드](09.업무모드.md) |
| `--dev team\|vibe` | 개발 체계: 개발팀이 있음(PM은 스펙까지) / 개발자 없이 PM이 LLM과 구현(스펙 승인 후 `src/`) |
| `--archetype AT0x[,AT0y]` | 서비스 유형을 미리 기록. 모르면 비워 두고 PRD를 쓴 뒤 `/edpm-start blueprint detect` |
| `--brain <경로>` | 개인 EdTech Brain 위치 (기본 `~/EdTech-Brain`) |
| `--with-kg` | 교육과정 지식그래프 받기 (K-12·학원·교과 연계면 권장, 나중에 `/edpm-curriculum setup`도 가능) |
| `--no-git` | git 초기화 안 함 (회사 저장소 안에 둘 때) |
| `--no-sb-lowfi` | 화면설계 스킬 sb-lowfi 설치를 건너뜀 (기본은 설치) |

생기는 것:

| 무엇 | 위치 |
|------|------|
| 워크스페이스: `AGENTS.md`, `PRD.md`, 핵심 경로 산출물(E00·E05·E06·E09·프로토타입) + 모드 문서, 스킬(`.claude/skills/`), 훅·점검기·스크립트 | 지정한 경로 |
| 산출물 보관함 (필요할 때 `/edpm-doc <ID>`로 꺼냄) | `<워크스페이스>/.edpm/library/` |
| 개인 Brain (처음 한 번) | `~/EdTech-Brain` |
| 화면설계 스킬 `sb-lowfi-pptx`·`sb-lowfi-figma` | `~/.claude/skills/` |

기존 폴더가 비어 있지 않으면 설치가 멈춥니다 (덮어쓰지 않음). 설치가 끝나면 Antigravity에서 워크스페이스 폴더를 열고 Claude Code 패널에서 `/edpm-start` (2절).

## 4. 함께 쓰는 스킬

EdPM은 결과를 마크다운으로 먼저 만들고, 다른 형식이 필요할 때만 아래를 씁니다.

| 스킬·도구 | 설치 | 쓰는 곳 |
|-----------|------|---------|
| `sb-lowfi-pptx`, `sb-lowfi-figma` ([rey-hailey/sb-lowfi](https://github.com/rey-hailey/sb-lowfi)) | 설치 때 자동. 네트워크가 없었으면 `./install.sh --extras` 또는 Claude Code에서 `/plugin marketplace add rey-hailey/sb-lowfi` → `/plugin install sb-lowfi@sb-lowfi` | E10 → low-fi 와이어프레임 HTML·PPTX, Figma 화면설계서 |
| `edpm_export.py` | 워크스페이스에 포함 | 산출물 → 인쇄용 HTML·PDF(Chrome)·Word(pandoc, `--reference 회사양식.docx`) |
| 클릭 프로토타입 시작 파일 | 워크스페이스에 포함 (`06.prototypes/_starter/`) | P1 클릭 프로토타입 |
| 공식 `docx`·`pptx`·`xlsx`·`pdf`, `webapp-testing` | Claude Code에서 `/plugin marketplace add anthropics/skills` → `/plugin install document-skills@anthropic-agent-skills`, `example-skills@anthropic-agent-skills` | 발표 자료, 표 계산, 화면 E2E (`/edpm-spec qa run --auto`) |
| n8n 스킬 | [czlonkowski/n8n-skills](https://github.com/czlonkowski/n8n-skills) | 회사가 n8n을 쓸 때만 ([04.자동화레이어선택](04.자동화레이어선택.md)) |

## 5. 하네스 (설치하면 켜짐)

세션을 시작하면 상황판(지금 단계, 다음 할 일, 주의할 것)이 뜨고, 파일을 쓸 때 훅이 자료실 원본 수정·전제 전 본문 쓰기·게이트 미충족 완료·식별 정보 저장·스펙 전 제품 코드를 막습니다. 막히면 사유가 표시되고, 사용자가 허용하면 `gate_skip: [사유]`로 통과합니다. 상세: [13.하네스와점검](13.하네스와점검.md).

## 6. 문제 해결

| 증상 | 원인·조치 |
|------|-----------|
| `/edpm-*`가 자동완성에 안 나옴 | 에디터에서 연 폴더가 워크스페이스 루트인지(상위 폴더가 아닌지), 터미널이면 워크스페이스 폴더에서 `claude`를 열었는지 확인. `ls -a .claude/skills`로 `edpm-*` 폴더 확인. 없으면 `./install.sh --upgrade <경로>` |
| 필요한 산출물이 워크스페이스에 없음 | 보관함에 있습니다. `/edpm-doc <ID>` 또는 `python3 automation/scripts/edpm_check.py add <ID>`, 목록은 `/edpm-doc list` |
| 저장이 "차단"으로 거부됨 | 훅이 순서·게이트·개인정보를 막은 것. 메시지의 사유대로 전제를 먼저 끝내거나 가명 처리. 사용자가 허용하면 `gate_skip: [사유]` |
| 진행표에 "이번 경로에 없는 전제"가 보임 | 막는 것이 아니라 알림입니다. 이 제품에 필요하면 꺼내고, 아니면 그대로 둡니다 |
| `--to docx`·`pdf`가 HTML만 남김 | pandoc(Word)·Chrome(PDF) 미설치. `./install.sh --check` |
| 설치가 "비어 있지 않습니다"로 멈춤 | 기존 워크스페이스 보호. 새 경로를 쓰거나 기존 폴더를 직접 정리 |
| `/edpm-curriculum`이 데이터 없음 | `automation/kg/kg_sync.sh && python3 automation/kg/kg_build.py` (git·네트워크) |
| `/edpm-ai eval` 인증 오류 | `pip install anthropic`, `ANTHROPIC_API_KEY` 환경변수. 키를 파일에 쓰지 마세요 |
| `/edpm-wbs push`가 저장소 없음 | `automation/wbs.json`의 `repo`(owner/name), `gh auth status` |
| Projects 날짜가 안 채워짐 | `gh auth refresh -s project`, 프로젝트에 날짜 필드 `시작`·`종료` 추가 |
| 세션 시작 상황판이 안 뜸 | `/edpm-brief`로 부릅니다. 그래도 안 되면 `.claude/settings.json`이 있는지, `python3 automation/scripts/edpm_check.py brief`가 실행되는지 |
| 대시보드에서 파일을 누르면 IDE가 아닌 다른 앱이 열림 | `Antigravity`와 `Antigravity IDE`가 함께 설치된 경우입니다. 대시보드를 다시 만들면 IDE 주소(`antigravity-ide://`)를 씁니다 (`/edpm-brief dashboard`). 그래도 다르면 `EDPM_EDITOR_URL` |
| 스킬·훅이 전혀 동작하지 않음 | Antigravity 내장 에이전트로 작업 중인지 확인. EdPM은 Claude Code 패널에서 씁니다 (2절) |
| 권장 확장 알림이 안 뜸 | 확장 탭에서 `@recommended` 검색, 또는 Claude Code·Markdown Preview Mermaid Support·Rainbow CSV를 직접 설치 |
| 클릭 프로토타입 기록이 사라짐 | 기록은 그 브라우저에만 저장됨. 세션마다 "기록 → CSV 내보내기" |

## 7. 업데이트

```bash
cd agent-driven-edpm && git pull
./install.sh --upgrade ~/Work/우리회사-edpm     # 스킬·스크립트·훅·보관함만. 작성한 산출물·위키는 그대로
```

`AGENTS.md`(사람이 관리)와 이미 작성 중인 산출물의 템플릿 변경은 [CHANGELOG](../CHANGELOG.md)를 보고 필요한 부분만 옮깁니다. `settings.json`을 직접 고쳤다면 `settings.new.json`과 비교해 합칩니다.
