# 시작하기: 설치 준비, 설치, 사용법

처음 쓰는 PM이 이 문서 하나만 보고 워크스페이스를 만들어 첫 산출물까지 가도록 정리했습니다. 설치 이후 실제 업무 흐름(1일차 온보딩, 매일 루틴, 과제·신사업 끝까지)은 [14.AtoZ사용가이드](14.AtoZ사용가이드.md)를 따라가세요. 개념과 설계 배경은 [01.설계원칙과구조](01.설계원칙과구조.md), 산출물 순서는 [02.산출물체인과게이트](02.산출물체인과게이트.md)를 보세요.

## 1. 한눈에 보기

| 단계 | 할 일 | 시간 |
|------|-------|------|
| 1 | 필수 도구 확인: `./install.sh --check` | 1분 |
| 2 | (선택) 문서 변환·화면설계 스킬 설치: `./install.sh --extras` + 공식 플러그인 | 5분 |

## 3. 스킬 구성

스킬은 두 종류입니다. **EdPM 스킬은 설치할 때 자동으로 들어가고**, 문서 변환용 외부 스킬은 따로 설치합니다.

### 3.1 EdPM 스킬 33종 — 자동 설치

`install.sh`가 `workspace-template/.claude/skills/`를 워크스페이스의 `.claude/skills/`로 복사합니다. 폴더 이름이 `.`으로 시작해 Finder와 `ls`에는 보이지 않습니다(`ls -a`로 확인). 이 스킬은 **그 워크스페이스 안에서 Claude Code를 열 때만** 보입니다. 다른 폴더에서는 `/edpm-*`가 나타나지 않습니다.

확인: 워크스페이스에서 `claude`를 열고 `/edpm`을 입력하면 자동완성 목록에 33개가 나옵니다.

| 묶음 | 스킬 | 언제 |
|------|------|------|
| 매일 | `/edpm-brief`, `/edpm-meeting`, `/edpm-decide` | 상황판·오늘 할 일, 회의 준비·회의록 처리, 결정 기록·채점 |
| 협업 | `/edpm-handoff` | 개발·디자인·영업·경영진·CS·콘텐츠·법무에 맞춘 전달 패키지, 피드백 반영 ([15.협업가이드](15.협업가이드.md)) |
| 시작 | `/edpm-init`, `/edpm-blueprint` | 설치 직후 한 번, 서비스 유형 바뀔 때 |
| 업무 모드 | `/edpm-feature`(운영 개선), `/edpm-venture`(신사업) | 매 과제 |
| 산출물 | `/edpm-doc`, `/edpm-review`, `/edpm-policy`, `/edpm-ai-design`, `/edpm-eval`, `/edpm-curriculum`, `/edpm-qa` | 산출물 작성·검토 |
| 수치 | `/edpm-metrics` | 지표 정의 → SQL → 계산·효과크기·기준선 비교. 산출물의 숫자는 여기서만 |
| 만들어 검증 | `/edpm-proto` | 가설·해결안을 클릭 프로토타입·오즈의 마법사·코드 MVP로 만들어 사용자 테스트 ([11.프로토타입과MVP](11.프로토타입과MVP.md)) |
| 관리·보고 | `/edpm-wbs`, `/edpm-report`, `/edpm-weekly` | 주간·단계별. WBS는 GitHub(기본)·스프레드시트·Notion·Jira·Linear로 공유 ([12.일정관리도구연동](12.일정관리도구연동.md)) |
| 영업 | `/edpm-proposal`, `/edpm-content` | 수주·마케팅 |
| 자료·지식 | `/edpm-ingest`, `/edpm-query`, `/edpm-lint`, `/edpm-library`, `/edpm-collect`, `/edpm-promote` | 매일 |
| 포트폴리오 | `/edpm-portfolio` | 사이클이 끝날 때. 문제 정의·결정과 이유·산출물·AI 결과 검증·결과를 한 장으로 |

스킬별 인자는 [workspace-template/AGENTS.md](../workspace-template/AGENTS.md) 5절, 주제별 진입점은 [08.에듀테크PM커버리지맵](08.에듀테크PM커버리지맵.md)에 있습니다.

### 3.2 문서 변환·화면설계·테스트 스킬 — 별도 설치 (선택)

EdPM 스킬은 결과를 **마크다운으로 먼저** 만들고, Word·PDF·PPT·와이어프레임·자동 테스트로 바꿀 때만 아래 스킬을 부릅니다. 없어도 마크다운 산출물은 그대로 나옵니다. 이 스킬들은 사용자 전역(`~/.claude/skills/`)에 설치해 모든 워크스페이스에서 씁니다.

**① sb-lowfi 스킬 2종** — 한 줄로 설치 (`--extras`가 공개 저장소 [rey-hailey/sb-lowfi](https://github.com/rey-hailey/sb-lowfi)에서 `sb-lowfi-pptx`·`sb-lowfi-figma`를 받아 설치)

```bash
./install.sh --extras                              # 또는 워크스페이스 설치 때 --with-extras
```

| 스킬·스크립트 | 쓰는 곳 | 추가로 필요한 도구 |
|---------------|---------|---------------------|
| `sb-lowfi-pptx` | E10 → low-fi 와이어프레임 HTML·편집 가능한 PPTX 화면설계서 | Chrome (python-pptx는 처음 실행 때 자동 설치) |
| `sb-lowfi-figma` | low-fi HTML → Figma 화면설계서 | Figma MCP 연결, Chrome |
| `edpm_export.py` (EdPM 자체 스크립트, 설치 불필요) | `/edpm-report --format docx·pdf`, `/edpm-doc` 보고서: `python3 automation/scripts/edpm_export.py <md> --to html\|pdf\|docx` (표지·목차·쪽 번호, 예시 행 제거, `--reference 회사양식.docx`) | html은 추가 도구 없음, PDF는 Chrome, docx는 pandoc |

클릭 프로토타입은 워크스페이스의 `06.prototypes/_starter/click-prototype.html`을 씁니다. 챗봇·튜터의 모델·프롬프트 수준 검증은 `/edpm-eval`(`ai_eval.py`, 골든셋·시나리오셋), 화면 E2E는 아래 공식 `webapp-testing`으로 합니다.

이미 같은 이름의 스킬이 있으면 덮어쓰지 않고 건너뜁니다. 네트워크가 없어 sb-lowfi를 받지 못하면 Claude Code에서 `/plugin marketplace add rey-hailey/sb-lowfi` → `/plugin install sb-lowfi@sb-lowfi`로 설치합니다. 상세: [extras/README.md](../extras/README.md).

**② Anthropic 공식 스킬** — Claude Code 안에서 설치

```text
/plugin marketplace add anthropics/skills
/plugin install document-skills@anthropic-agent-skills     # docx, pptx, xlsx, pdf
/plugin install example-skills@anthropic-agent-skills      # webapp-testing 등
```

| 스킬 | 쓰는 곳 | 추가로 필요한 도구 |
|------|---------|---------------------|
| `docx`, `pptx`, `xlsx`, `pdf` | `/edpm-proposal deck`, `/edpm-content`, `/edpm-venture` 경영진 보고, `/edpm-report --format pptx` | Node.js(`pptxgenjs`, `docx`), LibreOffice(미리보기·변환), `pip install "markitdown[pptx]"` — 각 스킬 안내에 따름 |
| `webapp-testing` | `/edpm-qa run --auto`, B06 E2E | `pip install playwright && playwright install chromium` |

`docx`·`pptx`·`xlsx`·`pdf`는 Anthropic 라이선스(재배포 불가)라 이 프레임워크에 넣지 않았습니다.

**③ n8n 스킬 (회사가 n8n을 쓸 때만)** — [czlonkowski/n8n-skills](https://github.com/czlonkowski/n8n-skills)의 안내대로 설치. [04.자동화레이어선택](04.자동화레이어선택.md) 참고.

`./install.sh --check`가 어떤 스킬이 보이는지 알려줍니다.

## 4. 설치

```bash
git clone https://github.com/rey-hailey/agent-driven-edpm.git     # 또는 zip을 받아 풀기
cd agent-driven-edpm
./install.sh --check                      # 필수 도구·외부 스킬 점검만
./install.sh ~/Work/우리회사-edpm --mode F --archetype AT07,AT10
```

| 옵션 | 뜻 | 고르는 법 |
|------|----|-----------|
| `--mode N\|F\|NF` | 업무 모드 | 새 서비스를 만들면 N, 운영 중인 서비스를 개선하면 F, 둘 다면 NF — [09.업무모드](09.업무모드.md) |
| `--archetype AT0x[,AT0y]` | 서비스 유형 | [archetypes/README.md](../archetypes/README.md)의 표에서 가까운 것 1~2개. 모르면 비워 두고 `/edpm-init`에서 판정 |
| `--brain <경로>` | 개인 EdTech Brain 위치 | 기본 `~/EdTech-Brain`. 회사가 바뀌어도 가져가는 공개 지식 저장소 |
| `--with-kg` | 교육과정 지식그래프 받기 | K-12·학원·교과 연계 서비스(AT05·AT06·AT09)면 권장. 나중에 `/edpm-curriculum setup`으로도 가능 |
| `--no-git` | git 초기화 안 함 | 회사 저장소 안에 둘 때 |
| `--with-extras` | sb-lowfi 스킬 2종을 `~/.claude/skills`에 설치 | 처음 설치하는 컴퓨터면 권장 (3.2절) |

설치 결과:

| 생기는 것 | 위치 |
|-----------|------|
| 워크스페이스 (폴더 체계, 산출물 템플릿 84종(PRD 포함), 스킬 33종, 점검기·훅, 자동화 스크립트) | 지정한 경로 |
| 개인 Brain (처음 한 번, 공개 지식 87페이지) | `~/EdTech-Brain` |
| 위키 도메인 지식 시드 | `<워크스페이스>/02.wiki/domain/` |
| 서비스 유형 프로필 | `<워크스페이스>/02.wiki/company/서비스유형_AT0x_*.md` |

기존 폴더가 비어 있지 않으면 설치가 멈춥니다. 덮어쓰지 않습니다.

## 4.1 하네스 (설치하면 켜짐)

워크스페이스의 `.claude/settings.json`이 두 가지 훅을 켭니다. 세션을 시작하면 상황판(게이트·검토 대기·지연 WP·프로토타입·재검토할 결정·반영 안 된 회의록·개인정보 의심)이 자동으로 뜨고, 파일을 쓸 때 자료실 원본 수정·게이트 미충족 done 전환·식별 정보 저장을 막습니다. 막히면 사유가 표시되고, 사용자가 허용하면 `gate_skip: [사유]`로 통과합니다. 상세: [13.하네스와점검](13.하네스와점검.md).

## 5. 첫 사용

### 5.1 초기화 (한 번)

```bash
cd ~/Work/우리회사-edpm
claude
```

Claude Code 안에서:

1. `/edpm-init` — 회사·제품·사용자·수익 구조를 묻는 인터뷰에 답합니다. 결과: `03.docs/0.온보딩/E00_*.md`, 활성 산출물 목록, 위키 시드.
2. `/edpm-blueprint apply AT07,AT10` — 설치 때 유형을 지정했다면 init이 이어서 안내합니다. 유형별 필수·권장 산출물이 켜집니다.
3. `/edpm-blueprint check` — 비즈니스 로직·IA·화면·정책·AI 영역별로 비어 있는 곳을 보여줍니다.

### 5.2 기존 자료 넣기

1. 회사 소개서, 기획서, 회의록, 데이터 추출본을 `00.inbox/`에 넣습니다. 형식과 정리법은 [06.기존자료가져오기](06.기존자료가져오기.md).
2. `/edpm-ingest` — 개인정보를 확인·비식별화한 뒤 `01.자료실/`에 보관하고 위키를 갱신합니다. 학습자 개인정보가 든 원본은 먼저 비식별화하세요.
3. `/edpm-query "우리 서비스의 환불 규정 요약"` — 위키 근거로 답이 나오면 정상입니다.

### 5.3 모드별 첫 흐름

**F 운영 개선** — 운영 중인 서비스의 PM

```text
/edpm-feature baseline          # F00 서비스 현황 진단
/edpm-feature intake            # 들어온 요청을 백로그로
/edpm-feature prioritize        # 점수 공식으로 우선순위
/edpm-feature new 진도율개선     # 과제 폴더 생성 → F01 문제 정의
/edpm-feature spec              # F02 기능 기획 + 영향 점검(환불·정산·진도·개인정보·AI)
/edpm-feature launch            # F03 실험·출시 계획
/edpm-feature review            # F04 출시 후 효과 리뷰
```

**N 신사업** — 새 서비스를 맡은 PM

```text
/edpm-venture opportunity       # N01 사업기회 (가설·중단 기준)
/edpm-venture case              # N02 타당성·투자심의
/edpm-venture mvp               # N03 MVP·PMF 검증 계획
/edpm-venture gate              # N04 단계 심사 (확장·전환·중단)
```

**두 모드 공통: 만들어서 검증하기**

```text
/edpm-proto new 음성피드백      # PT-01 폴더 생성 → V01 계획 (검증 질문, 충실도, 성공·중단 기준)
/edpm-proto build              # 클릭 프로토타입·오즈의 마법사·코드 MVP 빌드 → 06.prototypes/, V02
/edpm-proto test               # 진행자 스크립트·관찰 기록지, 결과는 /edpm-ingest
/edpm-proto decide             # V03 판정 → 폐기·재검증·MVP 확장·개발 이관
```

**팀과 일정 공유 (기본 GitHub)**

```text
/edpm-wbs create               # M02 WBS·간트 (학사일정 반영)
/edpm-wbs setup                # 처음 한 번: 저장소 지정, 라벨·마일스톤
/edpm-wbs push                 # WP → GitHub 이슈 (팀원은 이슈를 닫거나 상태 라벨로 진행 표시)
/edpm-wbs pull                 # 진행 상태 → CSV (주간보고 전에 /edpm-weekly가 자동으로)
/edpm-wbs export sheets        # 회사가 스프레드시트·Notion·Jira·Linear를 쓰면
```

두 모드 모두 필요할 때 `/edpm-doc <ID>`로 개별 산출물(E10 화면, P01 환불 정책, A10 AI 방식 등)을 씁니다. `/edpm-doc`은 전제 산출물이 없으면 게이트에서 멈추고 무엇이 먼저인지 알려줍니다.

### 5.3.1 최소 경로 — 첫 2주에 쓸 것만

산출물 84종을 다 쓰지 않습니다. 모드별로 첫 2주의 최소 경로는 아래와 같고, 나머지는 `/edpm-blueprint check`가 "빈칸"으로 보여줄 때 필요한 것만 엽니다.

| 모드 | 1주 | 2주 | 그 뒤 |
|------|-----|-----|-------|
| F 운영 개선 | E00(init), F00 현황 진단, `/edpm-metrics connect`로 기준선 SQL 1~2개 | 개선백로그 5건, 첫 과제 F01·F02, 필요하면 PT-01 클릭 프로토타입 | F03·F04, 기준 문서(P01·L03·E13) 보강, WBS를 GitHub로 |
| N 신사업 | E00(init), N01 사업기회, 인터뷰 3건 ingest | N03의 가장 위험한 가설 1개를 PT-01(P1·P2)로, ADR 1건 | N02 투자심의, N03 전체, E05·E13 최소본 |

매일 `/edpm-brief`가 "지금 쓸 수 있는 산출물"을 보여주므로 순서를 외울 필요는 없습니다.

### 5.4 매일·매주

| 주기 | 할 일 |
|------|-------|
| 매일 | 세션 시작 상황판 확인(`/edpm-brief`), 새 자료 → `00.inbox/` → `/edpm-ingest`, 회의 후 `/edpm-meeting notes`, 결정은 `/edpm-decide new`, 궁금한 것 → `/edpm-query` |
| 주 1회 | `/edpm-weekly` 주간보고(WBS pull·회의 액션·재검토할 결정 포함), `/edpm-lint` 위키·산출물 점검 |
| 단계 끝 | `/edpm-review <ID>` 이해관계자 패널 검토, `/edpm-report M04` 등 |
| 분기·퇴사 전 | `/edpm-promote` — 일반화 가능한 지식을 개인 Brain으로 (기밀 제거) |

산출물의 진행 상태는 각 파일 frontmatter의 `status`(`draft | review | done | n/a`)가 기준입니다. 영역별로 무엇을 했는지 보려면 `03.docs/_dashboard.md`(Obsidian + Dataview) 또는 `/edpm-blueprint check`를 쓰세요.

## 6. 문제 해결

| 증상 | 원인·조치 |
|------|-----------|
| `/edpm-*`가 자동완성에 안 나옴 | 워크스페이스 폴더에서 `claude`를 열었는지 확인. `ls -a .claude/skills`로 33개 폴더 확인. 없으면 설치를 다시 하거나 `workspace-template/.claude`를 복사 |
| `--format docx`·`pdf`·`pptx`가 마크다운만 남김 | 변환 도구 미설치. docx는 pandoc, pdf는 Chrome(`edpm_export.py`), pptx는 공식 플러그인 설치 (3.2절), `./install.sh --check`로 확인 |
| 설치가 "비어 있지 않습니다"로 멈춤 | 기존 워크스페이스 보호. 새 경로를 쓰거나 기존 폴더를 직접 정리 |
| `/edpm-curriculum`이 데이터 없음 | `automation/kg/kg_sync.sh && python3 automation/kg/kg_build.py` 실행 (git·네트워크 필요) |
| `/edpm-eval`이 인증 오류 | `pip install anthropic`, `ANTHROPIC_API_KEY` 설정. 키를 파일에 쓰지 마세요 |
| `/edpm-collect`가 Aside 없음 | Aside CLI 설치 또는 자료를 `00.inbox/`에 직접 넣기 |
| 대시보드 표가 코드로 보임 | Obsidian 커뮤니티 플러그인 Dataview 설치 |
| `/edpm-wbs push`가 저장소 없음 | `automation/wbs.json`의 `repo`(owner/name) 확인, `gh auth status` |
| Projects 날짜가 안 채워짐 | `gh auth refresh -s project`, 프로젝트에 날짜 필드 `시작`·`종료` 추가 |
| 저장이 "차단"으로 거부됨 | 훅이 자료실 원본 수정·게이트 미충족 done·식별 정보를 막은 것. 메시지의 사유대로 전제 산출물을 먼저 완료하거나 가명 처리. 사용자가 허용하면 `gate_skip: [사유]` ([13.하네스와점검](13.하네스와점검.md)) |
| 세션 시작 상황판이 안 뜸 | `.claude/settings.json`이 있는지, `python3 automation/scripts/edpm_check.py brief`가 직접 실행되는지 확인 |
| 클릭 프로토타입 기록이 사라짐 | 기록은 그 브라우저에만 저장됨. 세션마다 "기록 → CSV 내보내기" |

## 7. 업데이트

프레임워크 새 버전을 받은 뒤, 워크스페이스에는 스킬과 템플릿만 덮어씁니다. 작성한 산출물·위키는 건드리지 않습니다.

```bash
cd agent-driven-edpm && git pull
./install.sh --upgrade ~/Work/우리회사-edpm     # 스킬·스크립트·훅·설정·새 템플릿만. 산출물·위키는 그대로
```

`AGENTS.md`(사람이 관리)와 이미 작성 중인 산출물 템플릿 변경은 [CHANGELOG](../CHANGELOG.md)를 보고 필요한 부분만 옮기세요. `settings.json`을 직접 고쳤다면 `settings.new.json`과 비교해 합칩니다.
