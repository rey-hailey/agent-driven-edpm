EdPM Framework 마스터 가이드

설치 후 무엇을 입력하면 → 어떤 산출물이 생기고 → 그것을 어떻게 쓰는지를 실제 흐름과 산출물 예시로 보여줍니다. 이러닝 마켓플레이스부터 기업교육 LMS·K-12·AI 튜터까지, 어느 에듀테크 회사로 옮겨도 같은 방식으로 일합니다.

업무 모드 2종 서비스 유형 15종 산출물 83종 스킬 32 + 외부 2 게이트 12종

EdPM은 단순한 "AI에게 문서 써달라고 하기"가 아닙니다. 에듀테크 PM이 실제로 하는 일(문제 정의 → 학습 성과 설계 → 기능·화면 → 정책·정산 → 파일럿 → 효과 측정 → 영업·제안)을 순서·게이트·근거가 있는 산출물 체계로 만들고, 반복 업무는 스킬이, 규칙은 장치(훅·스크립트)가 지키게 합니다.

이 가이드가 쓰는 가상 제품설명을 구체적으로 하려고 가상 제품 매스핏(중학생 수학 오답 코칭 앱 · 학원 B2B2C + 학부모 결제 · AI 오답 해설)과 신사업 리딩버디(만 5~9세 영어 읽기 음성 피드백)를 예시로 씁니다. 모든 수치는 가상입니다.

2. 어떻게 쓰나 — 입력 한 줄이 산출물이 되기까지

워크스페이스 폴더에서 Claude를 열고 평소 말하듯 입력하면 됩니다. 슬래시 명령을 몰라도 됩니다. 핵심은 "스킬을 연다"가 아니라, 입력 → 에이전트가 근거를 모아 산출물 초안을 만들고 → 게이트·추적성을 챙기고 → PM이 판단·승인 → 파일로 남는다는 흐름입니다.

매스핏에서 중학생이 오답을 그냥 베껴 적고 같은 유형을 또 틀려. 이걸 교육 문제로 정의해줘.
에이전트가 하는 일: E00 회사 프로필과 02.wiki/의 현장 인터뷰·오답 데이터를 읽고 → 해법("AI 해설이 없다")을 학습자에게 일어나는 문제로 바꾸고 → 증거 2건 이상을 자료실 경로와 함께 달고 → 03.docs/1.발견/E01_교육문제정의서.md 초안을 만든 뒤, 근거가 약한 곳을 알려줍니다.

그 결과로 생기는 산출물은 이런 모양입니다 (실제 템플릿 구조):

03.docs/1.발견/E01_교육문제정의서.md
1. 문제 진술

PB-01 · 중학생이 수학 문제를 틀린 뒤 오답 원인을 확인하지 않고 정답만 베껴, 같은 유형을 시험에서 다시 틀린다 (대상: 중2 수학 중하위권 · 영역: 일차함수·연립방정식)

4. 증거

① 직전 시험 오답 유형 재오답률이 높음 — 로그(집계) · automation/sql/재오답률.sql
② 학생들이 오답 노트를 "정답 옮겨 적기"로 처리 — 관찰 · 01.자료실/현장/2026-09-25_학원참관_B.md

7. 학습 변화 가설

PB-01-H1 · 오답마다 원인을 진단하고 3·7일 뒤 유사 문항을 다시 풀면, 한 학기 안에 같은 유형 재오답률이 의미 있게 준다. 근거: [[domain/인출연습]], [[domain/간격반복]]

— "AI 해설을 만든다"가 아니라 "학생이 원인을 진단 못 한다"로 정의되고, 모든 주장에 출처가 붙습니다. 이 문서가 done이 되어야 다음(E05)으로 갑니다.

PM이 이것으로 하는 일: 강사·학습과학 자문에게 이 한 장을 보여 "우리가 풀 문제가 이게 맞나"를 합의하고, 증거가 약한 칸은 현장 확인 과제로 돌립니다. 다음 턴에 "이제 학습 성과를 설계해줘"라고 하면 E01을 근거로 E05가 이어집니다 — 문서끼리 ID로 연결되어, 나중에 "이 기능이 어떤 학습 목표에서 나왔지?"를 되짚을 수 있습니다.

핵심 감각EdPM은 한 번의 거대한 출력이 아니라, 작은 입력이 쌓여 서로 연결된 산출물 체계가 되는 방식입니다. 각 산출물은 ① 이전 산출물을 전제로 하고 ② 모든 수치·주장에 출처가 있고 ③ 게이트를 통과해야 done이 됩니다.

3. EdPM이 에듀테크 PM을 돕는 순간

"AI에게 글 써달라기"와 다른 점은, 에듀테크 PM이 늘 막히는 지점마다 산출물·게이트가 준비되어 있다는 것입니다.

PM의 실제 고충이렇게 입력생기는 산출물어떻게 도움
"기능은 많은데 성적은 왜 안 오르지?""학습 성과부터 설계해줘"E05 학습성과설계서 (LO + 평가 증거)기능보다 "무엇을 할 수 있게 되나 + 무엇으로 확인하나"를 먼저 못 박아, 있으면 좋은 기능만 쌓이는 걸 막음
"작은 기능 하나 바꿨는데 환불·정산이 깨졌다""이 개선안 영향 점검해줘"F02 영향 점검표개인정보·AI·환불·진도·교육과정·접근성·시즌을 한 행씩 판정 — 미처리면 출시(F03) 자체가 막힘
경영진이 "효과 있어?""효과크기 계산해줘"지표 결과표 (효과크기·신뢰구간)LLM 추정이 아니라 SQL로 계산. 신뢰구간이 0을 포함하면 단정하지 않음
영업이 "효과 40% 향상" 쓰고 싶어함"제안서 효과 문장 점검해줘"S02 제안서 (근거 연결 점검)E19·E17 근거 없는 효과 문장을 찾아 삭제·정성 표현 제안 — 과장 리스크 차단
"이 결정, 나중에 맞았는지 어떻게 알지?""이 결정 기록하고 예측도 붙여줘"ADR (예측 + 재검토일)재검토일이 지나면 상황판이 알림 → 예측을 SQL로 채점해 판단 적중률을 봄
"회사 바꾸면 쌓은 지식이 다 사라져""일반 지식만 개인 Brain으로 승격해줘"개인 EdTech Brain (공개 지식)기밀·개인정보를 뺀 도메인 지식만 이식 → 다음 회사에서 다시 씨앗
"성취기준을 기억으로 쓰다 틀림""일차방정식 성취기준 찾아줘"교육과정 매핑 (KG 조회)기억이 아니라 지식그래프에서 코드와 함께 조회. 공식 선수관계와 권장순서를 구분
"학기 중간에 출시해서 아무도 안 씀""출시 일정 시즌 충돌 봐줘"E18 도입·출시계획 (G-CAL)학사일정·시험기·기업 예산 시기와 충돌을 검토 — 시험 2주 전 배포 동결 등

5. 설치와 1일차 — 반나절이면 일할 준비 끝

# 1) 내려받고 점검
git clone https://github.com/rey-hailey/agent-driven-edpm.git ~/agent-driven-edpm && cd ~/agent-driven-edpm
./install.sh --check

# 2) 워크스페이스 만들기 — 인자 없이 실행하면 회사 이름·업무 모드·개발 체계·서비스 유형을 묻습니다
./install.sh
#    (직접 지정: ./install.sh ~/Work/우리회사-edpm --mode NF --dev team --archetype AT07,AT09 --with-extras)

# 3) 그 폴더에서 Claude Code를 열면 상황판이 "지금 단계"를 알려줍니다. 처음이면
cd ~/Work/우리회사-edpm && claude
/edpm-start      # → /edpm-init → /edpm-prd

설치하면 워크스페이스 폴더, 개인 Brain, 위키 도메인 지식 ~91종, 서비스 유형 프로필이 생깁니다. 1일차에 하는 일과 그 결과:

입력

/edpm-init → 회사·제품·학습자·모드·유형을 3~4개씩 묻는 인터뷰에 답

이후 모든 산출물이 "우리 회사는 누구에게 무엇을 파는가"를 전제로 자동 반영

7. 산출물 전체 지도

제품 트랙(E)은 학기·분기마다 한 바퀴 도는 사이클입니다. E20의 다음 후보가 다시 E01로 들어갑니다. 서비스 유형·업무 모드가 "이번에 어떤 산출물을 켤지"를 먼저 정하므로, 전부 쓰지 않습니다.

10. 워크스루 ① — 제품을 정의하는 흐름 (E 체인)

매스핏을 예로, 문제에서 출발해 학습 성과·결정까지 어떻게 이어지는지입니다. 각 단계는 "무엇을 입력 → 무엇이 생김 → 어떻게 씀"으로 봅니다.

1문제 정의 (E01)

산출물

활용

13. 프로토타입·MVP — 가장 위험한 가정부터 싸게

  • 학생 원문·음성·식별 정보가 외부 API로 나가면 E13·P07 검토, 필요하면 가명화·로컬 모델.
  • 방식·모델·프롬프트 변경은 같은 평가셋 결과(/edpm-eval)로 판단, 비용은 ai_cost.py로 계산.
출시 게이트 (G-AI)AI 기능이면 E14·A10(방식)·A14(가드레일) done, A 트랙을 쓰면 A06 평가 합격, 유료·대량이면 A12(비용)도 done이어야 출시. 한국에서 초·중등 학생 평가용 AI는 AI 기본법(2026.1.22. 시행)의 고영향 AI입니다.

15. 게이트·하네스 — 규칙을 장치로

게이트는 산출물을 done으로 바꿀 때 확인하는 관문입니다. "게이트 무시"를 명시하면 경고 후 진행하고 gate_skip 사유가 상황판·린트에 계속 보입니다. 코드 강제 표시는 점검기가 결정적으로 막는 것, 나머지는 LLM이 보완합니다.

16. 데이터 보호·교육과정 규칙 (항상 적용)

데이터 보호 (핵심)
  • 실명·연락처·학번·얼굴·음성은 자료실에 넣기 전 가명(학생A, OO중)으로. 전화·주민번호·이메일은 훅이 저장을 막음.
  • 비식별화 전 자료를 외부 AI·브라우저 에이전트로 보내지 않는다.
  • 실제 아동·학생 데이터로 프로토타입을 테스트하지 않는다 (가상 페르소나·가명 샘플).
  • 조회·계산(점수·정답률·효과크기)은 SQL·스크립트로. LLM이 수치를 추정하지 않는다.
교육과정 데이터 (국가 교육과정 기반)성취기준·선수 관계는 지식그래프에서 코드와 함께 조회(기억으로 쓰지 않음). 공식 선수 관계와 권장 순서를 구분하고, KG는 공식 자료가 아니므로 제출 문서 원문은 공식 고시로 확인하며 출처 고지를 남긴다. 전환기 격차를 개인의 '뒤처짐'으로 표현하지 않는다.
