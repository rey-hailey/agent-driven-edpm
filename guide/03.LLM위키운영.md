# LLM 위키 운영 (Obsidian)

## 1. 왜 위키인가

보통의 문서 기반 AI 활용(NotebookLM, 파일 업로드 RAG)은 질문할 때마다 원본에서 조각을 다시 찾아 답을 만듭니다. 지식이 쌓이지 않고, 다섯 개 문서를 엮어야 하는 질문에서는 매번 처음부터 다시 엮습니다.

LLM 위키는 다릅니다. 원본이 들어올 때마다 LLM이 읽고 **이미 있는 위키 페이지들을 고칩니다**. 페르소나 페이지에 새 근거를 더하고, 경쟁사 페이지의 가격을 바꾸고, 앞선 주장과 충돌하면 표시합니다. 교차 참조와 종합이 미리 되어 있으니, 질문과 산출물 작성은 위키에서 시작합니다. 이 패턴은 Andrej Karpathy가 2026년 4월 공개한 "LLM Wiki" 아이디어(원본 → 위키 → 스키마의 3층, ingest·query·lint 동작)를 에듀테크 PM 업무에 맞게 옮긴 것입니다.

에듀테크 PM에게 특히 맞는 이유:

- 현장 자료(교사 인터뷰, 수업 관찰, 학부모 VOC)가 몇 달에 걸쳐 조금씩 들어옵니다. 매번 다시 읽으면 앞선 맥락이 사라집니다.
- 규제·정책·교육과정은 자주 바뀌고 출처와 확인 날짜가 중요합니다. 위키 페이지의 `verified` 필드와 lint가 이를 관리합니다.
- 산출물(E00~E20)은 서로 같은 사실(페르소나, 학습 목표, 지표 정의)을 반복해서 씁니다. 위키가 단일 기준이 되면 산출물끼리 어긋나지 않습니다.
- 회사를 옮길 때 가져갈 수 있는 것은 일반화된 지식뿐입니다. 위키는 `domain/`(가져갈 수 있음)과 `company/`(못 가져감)로 처음부터 나뉘어 있습니다.

## 2. 세 층과 스키마

| 층 | 위치 | 성격 |
|----|------|------|
| 원본 | `01.자료실/` | 비식별화된 자료. 수정 금지. 진실의 원천 |
| 위키 | `02.wiki/` | LLM이 쓰고 고치는 마크다운. 사람은 읽고 판단 |
| 산출물 | `03.docs/` | 위키에서 만드는 의사결정 문서 |
| 스키마 | `AGENTS.md` | 위의 규칙. 사람과 LLM이 함께 다듬음 |

Obsidian은 위키를 읽는 도구(IDE), LLM은 위키를 고치는 작성자, 위키는 코드베이스라고 보면 됩니다. 한쪽 창에 Claude Code, 다른 쪽 창에 Obsidian을 열고, LLM이 고친 페이지를 그래프 뷰와 링크로 따라가며 확인합니다.

## 3. 세 가지 동작

### Ingest — 자료 넣기 (`/edpm-ingest`)
1. 개인정보 확인과 비식별화 (G-PII)
2. `01.자료실/`에 저장
3. 핵심 3~5개를 사람과 짧게 논의
4. 원본 요약 페이지 작성, 관련 페이지 5~15개 갱신, 충돌 표시
5. index·log 갱신, 다시 볼 산출물 알림

처음에는 자료를 하나씩 넣으며 LLM이 무엇을 고치는지 지켜보세요. 규칙이 자리 잡으면 여러 건을 한꺼번에 넣어도 됩니다. 이때 바꾸고 싶은 규칙은 `AGENTS.md`에 적습니다.

### Query — 질문하기 (`/edpm-query`)
index → 관련 페이지 → 출처 달린 답. 좋은 답(비교표, 종합 분석)은 `05.outputs/`에 저장하고 위키에도 되돌립니다. 탐색한 결과도 지식으로 쌓이게 하는 것이 핵심입니다.

### Lint — 점검하기 (`/edpm-lint`, 2주마다)
개인정보 노출, 오래된 규제·가격 정보, 출처 없는 주장, 모순, 고립 페이지, 끊긴 링크, 추적이 끊긴 ID(성과 없는 기능), 게이트 위반을 찾습니다. 다음에 모을 자료도 제안합니다.

## 4. index.md와 log.md

- **index.md**: 내용 목록. 페이지마다 링크와 한 줄 요약. 페이지가 수백 개가 될 때까지는 벡터 검색 없이 index만으로 충분히 찾습니다. 그보다 커지면 로컬 검색 도구를 붙이는 것을 검토합니다.
- **log.md**: 시간 순 기록. `## [2026-10-12] ingest | 교사 인터뷰 B` 형식을 지키면 `grep "^## \["`로 최근 작업을 훑을 수 있고, `/edpm-weekly`가 이 기록으로 주간보고를 만듭니다.

## 5. Obsidian 설정 (선택)

Obsidian 없이도 모든 파일은 일반 마크다운으로 동작합니다. 쓴다면:

| 설정·플러그인 | 용도 |
|---------------|------|
| 볼트 = 워크스페이스 폴더 | 워크스페이스 전체를 볼트로 엽니다 |
| Files & Links → 첨부 폴더 `01.자료실/assets` | 이미지·첨부를 한곳에 |
| Web Clipper (브라우저 확장) | 웹 기사를 마크다운으로 `00.inbox/`에 저장 |
| Dataview | `03.docs/_dashboard.md`의 산출물 현황, frontmatter 기반 표 |
| Templater | 회의록·ADR 템플릿 빠르게 만들기 |
| Obsidian Git | 자동 커밋으로 위키 변경 이력 보관 |
| Marp | 위키 내용을 슬라이드로 (`/edpm-query --format 슬라이드`) |
| 그래프 뷰 | 고립 페이지, 허브 페이지(많이 연결된 페르소나·개념) 확인 |

## 6. 두 개의 볼트: 회사 워크스페이스와 개인 Brain

| | 회사 워크스페이스 | 개인 EdTech Brain |
|--|------------------|-------------------|
| 위치 | 회사 승인 저장소 (회사 git, 회사 기기) | 개인 저장소 |
| 내용 | 회사·제품·고객·현장 자료 전부 | 공개 근거의 일반 에듀테크 지식, 일반화된 교훈, 일하는 방식 |
| 수명 | 재직 기간 | 경력 전체 |
| 흐름 | `/edpm-init`이 Brain에서 domain/을 받아옴 | `/edpm-promote`가 기밀을 지운 일반 지식만 받아옴 |

회사 기기·저장소 정책, 비밀유지계약이 이 구분보다 우선합니다. 회사 자료를 개인 기기나 개인 저장소로 옮기지 않습니다.

## 7. 규모별 운영 팁

| 위키 규모 | 운영 |
|-----------|------|
| ~50 페이지 | index만으로 충분. 매 ingest 후 결과 확인 |
| 50~300 페이지 | lint를 2주마다. domain/ 페이지는 분기마다 `verified` 갱신 |
| 300 페이지 이상 | 하위 index(폴더별 `_index.md`)로 나누거나 로컬 검색 도구 도입 검토 |

## 8. NotebookLM은 어떻게 하나

NotebookLM은 위키를 대신하지 않습니다. 쓴다면 **공유·청취용**으로 씁니다: 완료된 산출물이나 위키 일부를 경영진·영업팀이 질문하거나 오디오 요약으로 들을 수 있게 올립니다. 기준 원본은 언제나 워크스페이스입니다. 학생 데이터나 회사 기밀이 담긴 페이지는 올리기 전에 회사 정책을 확인합니다.
