# 회사 온보딩 플레이북 (30-60-90)

새 에듀테크 회사에 합류했을 때 이 프레임워크로 첫 90일을 보내는 방법입니다. 목표는 90일 안에 "이 회사의 학습자·고객·제품·제약을 위키로 설명할 수 있고, 다음 학기 계획을 근거와 함께 제시하는 것"입니다.

## 0일차: 준비 (1~2시간)

| 할 일 | 방법 |
|-------|------|
| 회사 정책 확인 | 외부 AI 도구 사용, 브라우저 에이전트 사용, 업무 자료 저장 위치에 대한 회사 정책을 먼저 확인합니다. 정책이 없으면 보안 담당에게 묻습니다 |
| 워크스페이스 생성 | 회사 기기·회사 승인 저장소에 `workspace-template/` 복사, git 초기화 |
| 설치 | 프레임워크 `install.sh <워크스페이스 경로> --archetype <AT0x>` |
| 초기화 | `/edpm-start init` — 회사 프로필 인터뷰(아는 만큼만), 서비스 유형 판정·적용(`/edpm-start blueprint`), Brain에서 domain/ 시드 |
| 자료실 | 받은 자료를 분류별로 `/edpm-wiki ingest`, `/edpm-wiki library catalog`로 목록 확인 |
| AGENTS.md | 회사 컨텍스트, 기밀 등급, 브라우저 에이전트 허용 범위 기록 |

## 1~30일: 듣고 모으기

목표: E00 완료, E02·E04 초안, 위키 50페이지 내외.

| 주 | 할 일 | 위키·산출물 |
|----|-------|-------------|
| 1주 | 회사 소개서, 사업 계획, 제품 데모 계정, 최근 지표 대시보드, 조직도를 받아 ingest | company/, E00 |
| 1주 | 팀원 1:1 (개발·디자인·콘텐츠·영업·CS·운영) — "가장 큰 고민 하나"를 묻고 회의록으로 ingest | company/, research/ |
| 2주 | CS 문의·앱 리뷰·영업 실패 사유 모음을 받아 ingest, R01·R08 실행 | research/, market/ |
| 2주 | 경쟁사 정리, R02·R03 정기 실행 등록 | market/, E04 |
| 3주 | 고객 현장 방문: 교사 2~3명, 학원 원장 1명, 학부모 1~2명 (가능하면 수업 참관) | 01.자료실/현장, learners/ |
| 4주 | 이해관계자맵 초안, `/edpm-wiki lint`·`/edpm-start blueprint check`로 빈자리 확인 | E02 |
| 4주 | 맡은 프로젝트가 있으면 착수·일정·위험 정리 | M01, M02, M03 (`/edpm-brief report`, `/edpm-wbs`) |

이 기간에는 의견을 내기보다 위키를 채우는 데 집중합니다. `/edpm-wiki query "지금까지 들은 것 중 서로 모순되는 것"`이 좋은 1:1 질문 거리를 줍니다.

## 31~60일: 진단하기

목표: E01·E03 완료, 현재 제품의 E07(지표 체계) 진단, 첫 의사결정 기록.

| 할 일 | 산출물 |
|-------|--------|
| 현장 인터뷰·관찰 추가 (누적 6~10건) | E03 현장리서치종합 |
| 가장 큰 학습 문제 1~2개를 문제 정의로 | E01 |
| 현재 지표가 학습 효과를 보고 있는지 진단 (참여 지표만 있는지) | E07 진단판 |
| 지금 효과 근거가 무엇인지 정리 (있다면) | E19 진단판 |
| 학사·영업 캘린더를 위키에 반영 | domain/학사일정 보완, company/영업캘린더 |
| 첫 의사결정을 ADR로 남김 | decisions/ADR-001 |

## 61~90일: 제안하기

목표: 다음 학기(또는 다음 분기) 계획을 근거와 함께 제시.

| 할 일 | 산출물 |
|-------|--------|
| 학습 성과 정의 | E05 |
| 제품 요구사항 | E06 |
| 이해관계자 패널 리뷰 → 실제 교사 2~3명에게 확인 | `/edpm-doc review`, E16 후보 |
| 다음 학기 릴리즈 방향 (학사 일정 정렬) | E15 초안 |
| 90일 회고, 일반화할 교훈 정리 | E20 형식의 메모, `/edpm-wiki promote --dry-run` |

## 회사 유형별 첫 질문

| 유형 | 먼저 확인할 것 |
|------|---------------|
| K-12 공교육 (B2G·B2S) | 도입 결정은 누가 하나(교사·학교·교육청), 예산 항목과 집행 시기, 개인정보·보안 심의 절차, 조달 경로 |
| 학원 (B2B2C) | 원장이 무엇으로 재계약을 판단하나, 강사가 실제로 쓰는 시간, 학부모 상담에 무엇을 보여주나 |
| 소비자 학습앱 (B2C) | 결제자(보호자)와 사용자(학생)의 동기 차이, 신학기·방학·시험 전 시즌성, 해지 사유 |
| 고등교육 | LMS 연동, 교수자 도입 동기, 학사 행정 부서의 역할, 학생 데이터 정책 |
| 기업교육 (HRD) | 교육 담당자의 성과 지표, HRIS 연동, 이수율과 실제 역량 변화의 차이 |

## 퇴사·이동 전

1. `/edpm-wiki promote`로 일반화 가능한 지식만 Brain으로 옮깁니다. 회사 계약 조건이 우선합니다.
2. 워크스페이스는 회사에 남깁니다. 후임자가 `02.wiki/index.md`와 `log.md`부터 읽으면 맥락을 이어받을 수 있게 마지막 lint와 index 정리를 합니다.
3. 개인 기기·개인 저장소에 회사 자료가 남지 않았는지 확인합니다.
