# E06 상세요구사항서

> **작성 가이드**
> - **목적**: 루트의 `PRD.md`(원점)가 정한 제품 전체를 **요구사항(REQ) 단위로 쪼개고 인수조건을 붙입니다.** 학습 목표(E05)를 달성하기 위해 제품이 무엇을 해야 하는지 정하며, 모든 REQ는 PRD 5·7절과 LO 또는 PB로 거슬러 올라가야 합니다. 범위·릴리스는 PRD를 따르고, 여기서 범위를 새로 줄이거나 늘리지 않습니다(바꾸려면 PRD 판을 올림).
> - **입력**: `PRD.md`(제품 전체·릴리스 계획·비기능), E02(이해관계자·구매/사용 여정 간극), E03(인사이트·JTBD), E05(LO·평가 증거·학습 계획), D01(연구 PoC에서 온 기능이면 4절 전환표·5절 데이터·6절 제품화 조건), E00(기기·학사일정), E04(규제 노출), [[domain/접근성]], [[domain/아동개인정보보호]], [[domain/교사참여설계]], [[domain/학사일정]]
> - **게이트**: PRD가 `review` 이상(G-PRD), E02·E03·E05가 `done`이어야 합니다. 추적 없는 REQ(LO·PB 연결 없음)는 완료할 수 없습니다. 비기능 요구사항의 아동 안전·접근성 항목은 E13의 입력이 됩니다.
> - **검토 패널 제안**: 개발 리드, 디자이너, 교사(강사) 패널, 개인정보 담당, 영업 담당
> - 예시 행은 샘플 제품 '매스핏'(중학생 수학 오답 코칭 앱, 학원 B2B2C + 학부모 결제, AI 오답 해설) 기준입니다.

## 5. 기능 요구사항

우선순위는 Must / Should / Could. 상세 기능(F-001)과 인수조건은 E09에서 정합니다.

**유형**은 운영 개선 과제와 같은 기준입니다(F01 0절). **학습**은 학습자의 학습 활동(무엇을·어떤 순서로·얼마나 스스로 생각하며)이나 평가·피드백 결과를 바꾸는 요구사항으로, LO로 추적되고 E07 학습 지표와 이어집니다. **사용성**(같은 일을 더 쉽고 빠르게)과 **운영**(관리·정산·권한·데이터·성능)은 PB·IN으로 추적하면 충분하고, E09 5절 운영·지원 기능이 됩니다. 제품 전체에 학습 유형 요구사항이 없으면 E05는 `n/a`와 사유로 둘 수 있습니다.

## 완료 체크리스트

- [ ] 모든 REQ에 유형(학습·사용성·운영)이 있고, LO, PB 또는 IN 중 하나 이상으로 추적된다 (학습 유형은 LO 필수)
- [ ] 모든 LO가 최소 1개 REQ로 연결된다 (기능 없는 성과 없음)
- [ ] 이해관계자별 가치 제안이 E02의 주요 SH를 모두 다룬다
- [ ] 범위 밖 항목과 제외 이유가 적혀 있다
- [ ] 비기능 요구사항에 접근성, 아동 안전·개인정보, 네트워크·오프라인, 기기, 교사 업무량이 모두 있다
- [ ] 출시 제약에 학사일정 기반 배포 금지 기간이 있다
- [ ] 가정에 `[가정]` 표시와 검증 방법(E16 등)이 있다
- [ ] AI 기능 REQ는 E14 대상, 아동 데이터 REQ는 E13 대상으로 표시되었다
- [ ] (교육과정 기반이면) 포함·제외 성취기준 범위가 커버리지 결과와 일치한다
