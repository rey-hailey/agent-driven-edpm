# D01 연구PoC제품화검토서

> **작성 가이드**
> - **목적**: 교육·연구 조직의 PoC, 학습 알고리즘, 교수법 실험을 **제품의 기능·프로세스·데이터 구조로 옮길 수 있는지** 판단하고, 옮긴다면 무엇이 그대로 가고 무엇이 바뀌는지 정합니다. 연구 결과를 PRD와 E06이 바로 받아 쓸 수 있는 말로 바꾸는 문서입니다.
> - **언제 쓰나**: 연구팀·교육연구소·교과 개발팀이 "효과가 있었다"는 결과를 가져왔을 때, 알고리즘(레벨 진단, 추천, 채점, 진도 규칙)을 제품에 넣자는 요청이 왔을 때, 외부 연구·논문 방법을 제품화하려 할 때.
> - **입력**: 연구 보고서·데이터·코드(비식별화 후 `01.자료실/기술/`), 연구자 인터뷰, `PRD.md`, E00, E05(있으면), `02.wiki/domain/` 관련 학습과학 페이지
> - **게이트**: E00이 `done`, PRD가 `review` 이상(G-PRD)이어야 완료합니다. 연구 결과의 수치는 연구 보고서 그대로 옮기고 출처를 답니다. LLM이 효과를 해석해 부풀리지 않습니다. 확인하지 못한 것은 `[확인 필요]`.
> - **결론**: 1절에 `제품화 진행 / 조건부 진행 / 추가 연구 / 보류` 중 하나와 이유를 씁니다. 결정은 `/edpm-decide`로 ADR에 남깁니다.
> - **다음**: 진행이면 4절 전환표가 PRD 5절 기능·E06 REQ·E12 데이터의 입력이 되고, 7절 불확실성은 V 트랙 프로토타입이나 E16 파일럿으로 검증합니다.
> - **분량**: 3~5쪽. 연구 보고서를 다시 쓰지 않습니다. 제품에 필요한 것만 옮깁니다.
> - 예시는 가상 신사업 **리딩버디**(유아 영어 리딩 앱)에서 연구팀의 "읽기 유창성 자동 측정 PoC"를 제품화하는 경우이며, 수치는 형식을 보여주는 [가정] 값입니다.

## 완료 체크리스트

- [ ] 1절 판단과 이유가 있고, 결정은 ADR로 남겼다
- [ ] 연구 수치는 연구 보고서 출처와 함께 그대로 옮겼다 (해석·과장 없음)
- [ ] 3절만 보고 개발팀이 재현할 수 있거나, 모르는 칸에 `[확인 필요]`와 확인할 사람이 있다
- [ ] 연구에서 사람이 하던 일이 제품에서 누구의 일이 되는지 4절에 있다
- [ ] 학습자 데이터의 동의 근거가 연구와 제품에서 어떻게 다른지 5절에 있다 (미성년이면 E13 연결)
- [ ] 7절 가설마다 검증 방법과 중단 기준이 있다
- [ ] 제품에서 효과를 말하는 범위가 8절에 합의되었다
- [ ] 9절 반영 위치가 PRD·E06·E12에 실제로 반영되었거나 열린 질문으로 남았다
