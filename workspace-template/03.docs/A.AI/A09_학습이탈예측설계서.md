# A09 학습이탈예측설계서

> **작성 가이드**
> - **목적**: 학습 이탈(미수료, 구독 해지, 장기 미접속)을 이벤트 데이터로 미리 예측하고, 개입 용량에 맞춰 대상자를 고르고, 개입 효과를 실험으로 확인하는 설계를 정합니다.
> - **입력**: E07 지표(M), E12 이벤트(EV)·테이블·동의 플래그, L03 진도·수료 규칙, P01 구독·환불, E13 (a)·(e) 개인정보·공정성
> - **게이트**: 실체 검증 — 예측 성능(기준선 대비)과 오탐·미탐 시 개입 비용이 적혀 있고, 집단별 성능 차이를 점검해야 `done`입니다.
> - **원칙**: 특징 추출은 SQL, 학습·평가는 코드(통계·ML)가 합니다. **LLM으로 이탈을 예측하지 않습니다.** LLM은 개입 메시지 초안 작성에만 쓸 수 있고, 그 경우 E14에 AI-ID로 등록합니다.
> - **적용 서비스 유형**: AT07 소비자 학습앱, AT09 자격증·시험대비(핵심), AT01·AT02·AT03·AT08
> - **검토 패널 (권장)**: 데이터 분석가, 운영 책임자, 학습 코치·CS, 개인정보 담당, 접근성 점검자
> - **관련 위키**: [[domain/학습이탈예측]], [[domain/AI적용기회맵]]
> - 표의 첫 행은 예시 제품 **스킬업**(성인 VOD + 라이브 강의 마켓플레이스) 기준입니다. 수치는 [가정]입니다.

| 항목 | 값 | 예시 |
|------|----|------|

## 3. 특징 (FT)

| FT-ID | 특징 | 정의 | 출처 EV (E12) | SQL | 비고 |
|-------|------|------|---------------|-----|------|
| FT-01 (예시) | 최근성 | cutoff 기준 마지막 학습 이벤트 이후 일수 | EV-0N lesson_progressed | `automation/sql/a09_features.sql` {경로} | |
| FT-02 | 빈도 | 관찰 창 내 학습일 수 | {EV} | {} | |
| FT-03 | 진도 속도 | 관찰 창 진도율 증가량 / 경과일 (L03 진도율 정의) | {EV} | {} | |
| FT-04 | 퀴즈 추세 | 관찰 창 퀴즈 점수 기울기 | {EV} | {} | 퀴즈 없으면 결측 표시 |
| FT-05 | 도움 요청 | 질문 게시·CS 문의 수 | {EV} | {} | 많으면 위험 또는 참여일 수 있음, 해석 주의 |
| FT-06 | 결제 이벤트 | 결제 실패, 할인 결제 여부 | {EV} | {} | 구독형 |

민감 속성(나이, 장애 여부, 지역)은 특징에 넣지 않고 7절 공정성 점검에만 씁니다.

```sql
-- 예시: FT-01~FT-03 (관찰 창 14일). 테이블·컬럼명은 E12·B03에 맞춰 바꿉니다.
WITH enr AS (
  SELECT enrollment_id, learner_key, started_at,
         started_at + INTERVAL '14 day' AS cutoff
  FROM enrollment WHERE status <> 'refunded' AND is_test = FALSE
),
ev AS (
  SELECT e.enrollment_id, p.occurred_at, p.progress_pct
  FROM enr e JOIN lesson_progress p ON p.enrollment_id = e.enrollment_id
   AND p.occurred_at >= e.started_at AND p.occurred_at < e.cutoff   -- 누수 방지
)
SELECT e.enrollment_id,
       EXTRACT(DAY FROM e.cutoff - MAX(ev.occurred_at))  AS ft01_recency_days,
       COUNT(DISTINCT DATE(ev.occurred_at))              AS ft02_active_days,
       COALESCE(MAX(ev.progress_pct), 0) / 14.0          AS ft03_progress_velocity
FROM enr e LEFT JOIN ev ON ev.enrollment_id = e.enrollment_id
GROUP BY e.enrollment_id, e.cutoff;
```

## 4. 기준선과 모델

| 단계 | 모델 | 설명 | 채택 조건 |
|------|------|------|-----------|
| 0 (예시) | 규칙 | "최근 7일 미접속 AND 진도율 10% 미만" | 항상 비교 기준 |
| 1 | 로지스틱 회귀 | FT 표준화, 계수로 설명 가능 | 규칙 대비 5절 지표 개선 |
| 2 | 트리 앙상블 (선택) | 비선형 관계 | 로지스틱 대비 의미 있는 개선 + 설명 수단 |

```python
# 예시 스케치 (실행 코드 아님). sklearn 사용은 선택입니다.
import pandas as pd
from sklearn.linear_model import LogisticRegression

df = pd.read_csv("05.outputs/a09_features_{YYYYMMDD}.csv")   # 3절 SQL 결과 + label
train, test = df[df.cohort_month < "2026-07"], df[df.cohort_month >= "2026-07"]  # 시간 순 분할
X = ["ft01_recency_days", "ft02_active_days", "ft03_progress_velocity"]
model = LogisticRegression(max_iter=1000).fit(train[X], train.label)
test = test.assign(score=model.predict_proba(test[X])[:, 1])
K = 200                                                  # 주간 개입 용량 [가정]
top_k = test.nlargest(K, "score")
precision_at_k, recall_at_k = top_k.label.mean(), top_k.label.sum() / test.label.sum()   # 보정은 calibration_curve로
```
