# L05 표준연동설계서

> **작성 가이드**
> - **목적**: 과정 콘텐츠·학습 기록·명단·인증을 외부 LMS·LRS·HRIS와 어떤 표준으로 주고받을지 결정합니다. SCORM 1.2/2004, xAPI·LRS, cmi5, LTI 1.3, QTI, OneRoster, SSO(SAML·OIDC), HRIS 연동을 다룹니다.
> - **입력**: L01 콘텐츠 유형·패키징, B01 시스템 구조, E12 이벤트, L03 진도·수료 정의, B2B 고객 요구(S01·S04), [[domain/SCORM과xAPI]]
> - **게이트**: L01, B01이 `done`이어야 합니다. 외부로 나가는 학습 기록·명단은 E13 개인정보 점검(제3자 제공·위탁)에 올립니다. 표준 버전·지원 범위는 공식 명세와 대조하고, 고객 LMS 지원 여부는 `[확인 필요]`로 둡니다.
> - **적용 유형**: AT02, AT08 필수 / AT01, AT03, AT09 B2B·기관 판매 시 / AT05 공교육 연동 시 / AT04, AT06, AT07, AT10 해당 시
> - **검토 패널 (권장)**: 솔루션 아키텍트, B2B 고객사 IT·HRD 담당, 보안 담당, 데이터 엔지니어
> - 표의 첫 행은 예시 서비스 **스킬업**(성인 대상 VOD + 라이브 강의 마켓플레이스, 강사 입점·수익배분, 기업 B2B 좌석 판매, 일부 사업주 환급 과정) 기준입니다.

## 1. 연동 시나리오

| 시나리오 | 주체 | 방향 | 주고받는 것 | 후보 표준 | 예시 (스킬업) |
|----------|------|------|-------------|-----------|---------------|
| 콘텐츠 납품 | 우리 → 고객 LMS | 내보내기 | 과정 패키지, 진도·점수 | SCORM, cmi5 | 고객사 자체 LMS에 CRS-01 납품 |
| 도구 실행 | 고객 LMS → 우리 | 실행·성적 반환 | 실행 컨텍스트, 성적 | LTI 1.3 | {} |
| 학습 기록 수집 | 우리 → LRS | 전송 | 학습 이벤트 | xAPI | {} |
| 명단 동기화 | HRIS·SIS → 우리 | 가져오기 | 사용자·조직·반 | OneRoster, SCIM, CSV | {} |
| 인증 | IdP → 우리 | 로그인 | 신원 | SAML 2.0, OIDC | {} |
| 수료 회신 | 우리 → HRIS | 전송 | 수료·이수 시간 | API, CSV | {} |
| 문항 교환 | 제휴사 ↔ 우리 | 양방향 | 문항 | QTI | {} |

## 2. 콘텐츠·기록 표준 결정표

| 기준 | SCORM 1.2 | SCORM 2004 | xAPI + LRS | cmi5 | LTI 1.3 |
|------|-----------|------------|------------|------|---------|
| 고객 LMS 지원 범위 | 가장 넓음 [확인 필요] | 넓음 | LRS 필요 | 지원 증가 중 [확인 필요] | LMS 대부분 |
| 콘텐츠 위치 | 고객 LMS에 업로드 | 고객 LMS | 어디든 | 어디든 (LMS가 실행) | 우리 서버 |
| 기록 범위 | 완료·점수·시간 | + 순서 규칙·상세 상호작용 | 임의 행동 문장 | xAPI + LMS 실행 규칙 | 실행 + 성적(AGS)·명단(NRPS) |
| 오프라인·모바일·라이브 | 약함 | 약함 | 강함 | 강함 | 웹 중심 |
| 우리 진도 규칙(L03) 유지 | 어려움 (LMS 규칙 따름) | 일부 | 가능 | 가능 | 가능 (우리 쪽 계산) |
| 콘텐츠 유출 위험 | 높음 (파일 전달) | 높음 | 낮음 | 중간 | 낮음 |
| 구현 비용 | 낮음 | 중간 | 중간 (LRS 운영) | 중간~높음 | 중간 |
| 적합한 경우 | 레거시 LMS 납품 | 순차 규칙 필요 납품 | 다양한 학습 행동 분석 | 신규 LMS + 상세 기록 | SaaS 도구를 LMS 안에서 |
| 우리 결정 | {채택/보류/불가} | {} | {} | {} | {} |
| 예시 (스킬업) | 납품용 채택 | 보류 | 내부 이벤트 구조만 준용 | 보류 [가정] | B2B 고객 LMS용 채택 [가정] |

판정 근거는 `02.wiki/decisions/ADR-{nnn}`에 남깁니다.

## 3. LRS·xAPI 설계

| 항목 | 결정 | 예시 |
|------|------|------|
| LRS | {자체 / 상용 / 고객 LRS로 전송} | 고객 요청 시 고객 LRS 전송 [가정] |
| 동사 어휘 | {ADL 표준 어휘 / 사용자 정의 IRI} | completed, passed, attended |
| E12 이벤트 매핑 | EV → xAPI 문장 | EV-22 lesson_completed → verb completed, object LSN-001 |
| 확장 필드 | context.extensions | course_id, rule_version |
| 식별자 | actor = 가명 계정 또는 고객 사번 매핑 | 고객 요구 시 사번, 기본 가명 [가정] |

## 서비스 유형별 메모

| 유형 | 이 문서가 달라지는 점 |

## 완료 체크리스트

- [ ] 연동 시나리오마다 방향·데이터·후보 표준이 있다
- [ ] 결정표의 "우리 결정" 행이 채워지고 ADR이 남았다
- [ ] xAPI를 쓰면 E12 이벤트 → xAPI 문장 매핑이 있다
- [ ] SSO 방식과 퇴사자 비활성 처리 방법이 정해졌다
- [ ] HRIS 연동의 주기·실패 처리가 있다
- [ ] 외부 전송 데이터가 E13 개인정보 점검에 올라갔다
- [ ] 고객 LMS 지원 여부·환급 신고 방식에 `[확인 필요]`와 담당이 있다
