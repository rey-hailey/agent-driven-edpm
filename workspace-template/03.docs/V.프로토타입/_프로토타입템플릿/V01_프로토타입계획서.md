> - **목적**: 만들기 **전에** "무엇을 알아내려고 만드는가", "어디까지 진짜로 만들고 어디부터 가짜로 둘까", "어떤 결과면 계속하고 어떤 결과면 멈출까"를 정합니다. 이 문서의 기준이 V03 판정 기준이 됩니다.
> - **입력**: `PRD.md` 9절(보여줄 정수), 연결 문서(신사업이면 N03의 HY, 운영 개선이면 F01 문제·F02 초안), E05(LO, 있으면), E10 화면 목록(있으면), E13(미성년이면), 프레임워크 `guide/11.프로토타입과MVP.md`
> - **게이트 (G-PROTO)**: P3·P4 빌드는 4절 성공·중단 기준과 6절 timebox가 확정된 뒤 시작합니다(빌드 후 기준을 바꾸면 ADR). 실제 학습자 데이터는 쓰지 않습니다. 미성년이 참여하면 7절 동의·안전 항목이 모두 처리돼야 테스트를 시작합니다.
> - **원칙**: 질문에 답할 수 있는 **가장 낮은 충실도**를 고릅니다. 코드를 쓰기 전에 종이·클릭·오즈의 마법사로 답할 수 없는지 먼저 봅니다.
> - **분량**: 한두 쪽.
> - **스킬**: `/edpm-proto plan`
> - 예시는 가상 신사업 **리딩버디**(유아 영어 리딩 앱, 만 5~9세)의 PT-01이며 수치는 [가정]입니다.

## 2. 충실도 선택

| 단계 | 형태 | 답할 수 있는 질문 | 이번 선택 |
|------|------|-------------------|-----------|
| P0 | 종이·스토리보드·low-fi 와이어프레임 | 흐름을 이해하는가, 빠진 단계는 없는가 | [ ] |
| P1 | 클릭 프로토타입 (단일 HTML, Figma) | 화면을 보고 쓸 수 있는가, 가치 제안에 반응하는가 | [ ] |
| P2 | 오즈의 마법사·컨시어지 (사람이 뒤에서 처리) | 진짜 결과를 받으면 행동이 바뀌는가 (AI·자동화를 만들기 전 수요 확인) | [ ] |
| P3 | 노코드·로우코드 (Forms·Sheets·n8n·NotebookLM) | 소규모 실제 사용에서 데이터가 쌓이는가, AI 답이 쓸 만한가(P3 노코드 점검) | [ ] |
| P4 | 코드 MVP (Claude Code로 구현, 가상 데이터, 접근 제한 배포) | 실제 사용·재방문·학습 신호가 나오는가 | [ ] |

선택 이유와 **더 낮은 단계로 답할 수 없는 이유**: {}

예시: P1 + P2. 녹음·피드백 화면은 클릭 프로토타입으로, 피드백 내용은 영어 교사가 녹음을 듣고 10분 안에 수동 작성(오즈의 마법사). 음성 AI 연동(P4)은 "아이가 피드백에 반응한다"가 확인된 뒤.
