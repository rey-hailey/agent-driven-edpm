# 06.prototypes — 프로토타입 결과물

`/edpm-proto build`가 만드는 화면·코드·운영 스크립트를 둡니다. 계획과 판정 문서는 `03.docs/V.프로토타입/`에 있고, 이 폴더는 실제로 사람이 써 보는 결과물입니다. 흐름 전체는 프레임워크 `guide/11.프로토타입과MVP.md`.

## 폴더 규칙

| 경로 | 내용 |
|------|------|
| `_starter/click-prototype.html` | P1 클릭 프로토타입 시작 파일 (빌드 도구·인터넷 없이 브라우저로 열림, 화면 이동 기록 내보내기) |
| `PT-01_{이름}/` | 프로토타입 하나당 폴더 하나. `README.md`에 실행 방법, 충실도, V01·V02 링크 |
| `PT-01_{이름}/ops/` | P2 오즈의 마법사·컨시어지 운영 스크립트 (뒤에서 처리하는 사람의 절차, 응답 템플릿, 근무표) |
| `PT-01_{이름}/app/` | P4 코드 MVP. 규모가 커지거나 개발자와 함께 작업하면 별도 저장소로 옮기고 V02에 URL을 적음 |

## 충실도별로 만드는 것

| 단계 | 만드는 것 | 도구 |
|------|-----------|------|
| P0 | 화면 흐름 스토리보드, low-fi 와이어프레임 | E10 ASCII 배치 → `sb-lowfi-pptx` |
| P1 | 클릭 프로토타입 | `_starter/click-prototype.html` 복사, `sb-lowfi-pptx`, `sb-lowfi-figma`, Figma |
| P2 | 클릭 프로토타입 + 사람이 뒤에서 처리하는 운영 스크립트 | `ops/` 폴더, 공유 시트 |
| P3 | 노코드·로우코드 흐름 | Google Forms·Sheets, n8n, NotebookLM(AI 노코드 점검 — `/edpm-ai nocode`) |
| P4 | 코드 MVP | Claude Code. 회사 스택이 없으면 Next.js + Tailwind + Supabase + Vercel |

## 지킬 것 (G-PROTO)

1. **가상 데이터만.** 실제 학습자 기록·성적·연락처를 넣지 않습니다. 가상 학생은 `학생A`처럼 이름 붙이고, 문항·콘텐츠는 공개 자료나 직접 만든 것만 씁니다.
2. **비밀값은 커밋하지 않습니다.** API 키는 `.env.local`에 두고(`.gitignore`가 막음), 키 소유자와 폐기일을 V02에 적습니다.
3. **공개 URL은 접근을 제한합니다.** 배포 미리보기 보호, 비밀번호, 초대 링크. 검색 노출을 막습니다.
4. **결제는 테스트 모드만.** 실결제 연동을 하지 않습니다.
5. **프로토타입 코드는 운영에 그대로 올리지 않습니다.** 옮길 때는 V03 이관 패키지와 B 트랙(B01 구조, B04 인프라, E13 개인정보) 검토를 거칩니다.
6. **끝나면 정리합니다.** 테스트가 끝난 배포는 내리고, 참여자 데이터는 V01에 적은 날짜에 파기합니다.
