# edpm-blueprint

서비스 유형 정의는 프레임워크의 `archetypes/` 폴더에 있습니다 (경로는 `AGENTS.md` 2절 "프레임워크 경로"). 각 파일에는 핵심 비즈니스 로직, 역할, 대표 IA·화면, 트랙별 필수·권장·해당없음 표, 지표, 규제, 시즌 캘린더, 시작 순서가 있습니다.

## detect — 유형 판정

E00(있으면)과 대화로 다음을 확인하고 1~2개 유형을 제안합니다. 혼합형이 흔합니다 (예: AT01+AT02 B2C 마켓플레이스 + 기업 좌석, AT05+AT10 코스웨어 + AI 튜터).

| 질문 | 유형 단서 |
|------|-----------|
| 누가 콘텐츠를 만드나? 외부 강사가 입점하나? | 입점·수익배분 → AT01 |
| 구매자가 기업이고 임직원이 배우나? 법정 의무교육·환급 과정이 있나? | AT02 |
| 기수제·라이브·실습·프로젝트·취업 연계인가? | AT03 |
| 실시간 수업이나 1:1 매칭이 중심인가? | AT04 |
| 학교 수업에서 교사가 쓰나? 국가 교육과정을 따르나? | AT05 |
| 학원·공부방이 고객인가? 학부모 소통이 중요한가? | AT06 |
| 개인이 앱으로 스스로 배우고 구독하나? | AT07 |
| 대학·평생교육기관·공개강좌인가? | AT08 |
| 시험 합격이 목표이고 문제은행·모의고사가 핵심인가? | AT09 |
| AI 튜터·학습 에이전트가 제품의 중심인가? | AT10 |

결과를 E00 "서비스 유형" 절에 근거와 함께 적습니다.

## apply <AT0x[,AT0y]>

1. 해당 아키타입 파일을 읽습니다. 둘 이상이면 각 산출물에 대해 더 강한 요구(필수 > 권장 > 해당없음)를 택합니다.
2. **산출물 상태 설정**: 해당없음 산출물의 frontmatter를 `status: n/a`, 사유 `아키타입 AT0x 기준`으로 바꿉니다. 이미 `draft` 이상으로 작성된 산출물은 바꾸지 않고 목록으로만 보고합니다. 변경 전 목록을 보여주고 승인받습니다.
3. **AGENTS.md** 2절 "서비스 유형", "활성 모듈"을 갱신하는 변경안을 제안합니다.
3.1 **유형 프로필 사본**: 적용한 아키타입 파일을 `02.wiki/company/서비스유형_<아키타입 파일명>`으로 복사하고, 사본 안의 `[[archetypes/` 링크를 `[[company/서비스유형_`로 바꿉니다 (프레임워크 밖에서도 위키 링크가 깨지지 않게). 이후 회사 상황에 맞게 고친 내용은 이 사본에 적습니다.
4. **위키 시드**: 아키타입이 가리키는 brain 도메인 페이지(비즈니스 로직·IA·화면·정책·AI)가 `02.wiki/domain/`에 없으면 개인 Brain이나 프레임워크 `brain-seed/domain/`에서 복사합니다.
5. **게이트 조정**: G-CAL의 시즌 캘린더 종류(학사일정 / 기업 예산·환급 심사 / 소비자 성수기), G-POLICY(유료 판매·강사 정산 여부), G-CURRIC(국가 교육과정 여부), G-SAFE(미성년 여부)를 E00에 기록합니다.
6. **시작 순서**: 아키타입의 "시작 순서"를 WBS 초안 입력으로 `/edpm-wbs`에 넘길지 묻습니다.
7. log: `## [YYYY-MM-DD] blueprint | AT0x 적용 — 필수 N, 권장 N, 해당없음 N`
