# edpm-collect

## 절차

1. **레시피 확인**: `automation/aside/recipes/`에서 인자에 맞는 레시피를 읽습니다. 인자가 없으면 레시피 목록(`automation/aside/README.md`의 표)을 보여줍니다.

2. **안전 확인** — 실행 전에 반드시 확인합니다.
   - 레시피의 `pii_risk`가 `high`이면 실행하지 않습니다.
   - 대상 URL이 학생 목록, 성적 상세, 상담 기록 등 개인정보 화면이면 실행하지 않습니다.
   - 로그인이 필요한 회사 내부 화면이면 `AGENTS.md` 2절 기밀 규칙에서 브라우저 에이전트 사용이 허용됐는지 확인합니다. 정해지지 않았으면 사람에게 묻습니다.
   - 레시피에 `{...}` 자리표시자가 남아 있으면 값을 묻습니다.

3. **실행**
   - Aside CLI가 있으면: `automation/scripts/aside-run.sh <레시피 파일>`을 실행합니다. `--dry-run`이면 Aside에 보낼 지시문만 보여줍니다.
   - Aside MCP가 연결돼 있으면 MCP 도구로 같은 지시문을 실행해도 됩니다.
   - 둘 다 없으면 레시피의 "수동 대체" 절차를 안내합니다.

4. **결과 확인**: `00.inbox/`에 생긴 파일을 열어 레시피의 "출력 형식"과 맞는지 봅니다. 브라우저 에이전트 결과는 틀릴 수 있으므로 숫자·날짜·가격은 원문 URL과 함께 있는지 확인하고, 없으면 `[확인 필요]`를 붙입니다.

5. **다음 단계**: 결과 요약을 보여주고 `/edpm-ingest`로 이어갈지 묻습니다.

6. **log**: `## [YYYY-MM-DD] collect | R03 정책공지 — N건 → 00.inbox/...`

## 정기 실행

레시피의 `schedule` 값은 권장 주기입니다. 등록 방법은 `automation/README.md`를 보세요 (Aside Routines, launchd·cron, GitHub Actions).
