# edpm-brief report

주간보고는 `/edpm-brief weekly`가 맡고, 이 스킬은 프로젝트의 시작·중간·끝과 위험 관리를 맡습니다.

## 공통 절차

1. **게이트**: `guide/02` 2.1의 전제조건을 확인합니다 (M01←E00, M03←M01, M04←M02 + 산출물 3건 이상 done, M05←M04·E17).
2. **자료 모으기** (수치는 직접 계산하지 않고 기록된 결과만 인용)
   - 산출물 현황: `03.docs/**` frontmatter의 `doc_id`, `status`, `updated`
   - 진행: `M02_WBS.csv`의 계획 대비 실적 (일정 관리 도구를 쓰면 먼저 `wbs_sync.py pull`, 요약은 `wbs_sync.py status`)
   - 활동: `02.wiki/log.md`, `02.wiki/decisions/`
   - 지표: E07에 정의된 지표의 SQL 결과 파일(`01.자료실/데이터/`) — 없으면 "측정 전"으로 적음
   - 위험: M03
3. **작성**: 해당 템플릿 구조를 따르고, 맨 앞에 "1페이지 요약"(결론, 주요 수치, 결정 요청)을 둡니다.
4. **검토**: 외부 공유본(고객사·교육청·투자자)이면 회사 기밀과 개인정보를 점검하고, 효과 주장은 E17·E19 수치만 쓰는지 확인합니다.
5. **출력 변환**: `--format docx|pdf`는 `python3 automation/scripts/edpm_export.py <md> --to docx|pdf`로 변환합니다(표지·목차·쪽 번호, 회사 양식은 `--reference 회사양식.docx`). `pptx`는 공식 `pptx` 스킬이 설치되어 있으면 그것으로 만들고, 없으면 `--to html` 또는 `--to pdf`를 제안합니다. 파일명에는 `_YYYYMMDD_HHMM`이 붙습니다(스크립트는 `05.outputs/`에 자동으로 붙여 저장).
6. **상태·log**: frontmatter 갱신, `## [YYYY-MM-DD] doc | M04 중간보고서 {초안|완료}`

## 보고서별 메모

| 보고서 | 핵심 질문 | 꼭 넣을 것 |
|--------|-----------|------------|
| M01 착수보고서 | 왜, 무엇을, 누가, 언제까지 하는가 | 활성 산출물 목록(모듈 선택 결과), RACI, 학사일정에 맞춘 마일스톤, 성공 기준(학습 성과 포함) |
| M03 위험·이슈 | 무엇이 일을 막을 수 있는가 | 에듀테크 위험 분류(학사일정, 교사 참여, 개인정보 심의, 조달, 콘텐츠 오류, AI 품질, 민원, 기기·학교망), 트리거, 대응 담당 |
| M04 중간보고서 | 계획대로 가고 있는가, 무엇을 바꿔야 하는가 | 계획 대비 실적, 지금까지 알게 된 것(위키 research/), 학습 성과 가설 상태, 결정 요청 |
| M05 완료보고서 | 목표를 이뤘는가, 무엇을 넘기는가 | 목표 대비 결과, 학습 효과 요약(E19·E17, 계산 경로), 산출물 완료율(활성 기준 80% 이상), 운영 이관, 고객 검수 확인 |
| exec | 경영진이 3분 안에 알아야 할 것 | 결론 1문장, 수치 3개, 위험 1~2개, 결정 요청 |

## M03 갱신 모드

`/edpm-brief report M03`을 다시 실행하면 위키 log와 회의록에서 새 위험·이슈 후보를 찾아 제안하고, 기존 항목의 상태 변화(해소, 확대)를 묻습니다. 점수가 높아진 위험은 주간보고 리스크 절에 올립니다.
