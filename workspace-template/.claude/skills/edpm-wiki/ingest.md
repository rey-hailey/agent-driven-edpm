# edpm-wiki ingest

원본 하나가 들어오면 위키 여러 곳이 함께 갱신됩니다. 한 번에 자료 하나씩 처리하고, 처리할 때마다 사람에게 핵심을 보고합니다. 자료가 많으면 먼저 목록과 처리 순서를 보여주고 승인을 받습니다.

## 절차

1. **대상 확인**: 인자가 없으면 `00.inbox/`의 파일 목록을 보여줍니다. URL이면 내용을 가져와 파일로 저장합니다.

2. **개인정보 확인 (G-PII)** — 다른 단계보다 먼저 합니다.
   - 실명, 전화번호, 이메일, 주소, 학번, 학교+학년+반 조합, 생년월일, 얼굴 사진, 음성 파일, 상담 내용 속 가족 정보를 찾습니다.
   - 발견하면 가명으로 바꾼 사본을 만듭니다 (`학생A`, `교사B`, `보호자C`, `OO중학교`). 바꾼 항목 목록을 사람에게 보여주고 확인받습니다.
   - 사진·음성처럼 비식별화가 어려운 자료는 넣지 않고, 사람이 요약 텍스트만 넣도록 안내합니다.
   - 비식별화 전 원본은 `00.inbox/`에서 지우고, 원본은 회사 승인 저장소에 보관하라고 안내합니다.

3. **자료실 저장**: `01.자료실/{현장|정책|시장|데이터|회의|회사|제안|콘텐츠|기술}/YYYY-MM-DD_주제.md`로 저장합니다. 저장 후 `01.자료실/_자료목록.md`에 한 줄을 추가합니다. 파일 맨 위에 출처(URL, 수집 방법, 수집일, 수집 도구)를 적습니다. 이후 이 파일은 수정하지 않습니다.

4. **읽고 논의**: 핵심 내용 3~5개를 사람에게 보고하고, 무엇을 강조할지 짧게 묻습니다. 사람이 "알아서"라고 하면 바로 진행합니다.

5. **원본 요약 페이지**: `02.wiki/research/` 또는 `02.wiki/market/`에 `type: source-summary` 페이지를 만듭니다. 인터뷰·관찰이면 인사이트를 `IN-001` 형식으로 뽑습니다.

6. **관련 페이지 갱신**: `02.wiki/index.md`를 읽고 영향받는 페이지를 찾습니다.
   - 페르소나(`learners/`), 경쟁사(`market/`), 규제(`domain/`), 회사(`company/`) 페이지에 새 사실을 출처와 함께 추가합니다.
   - 기존 내용과 충돌하면 덮어쓰지 말고 `## 상충하는 근거`에 둘 다 적고 보고합니다.
   - 새 주제면 새 페이지를 만들고 관련 페이지와 서로 링크합니다.
   - 규제·정책·가격 정보에는 `verified` 날짜를 적습니다.

7. **산출물 영향 확인**: 갱신된 위키 페이지를 `sources`로 쓰는 `03.docs/` 산출물이 있으면 "다시 볼 필요가 있는 산출물" 목록에 넣습니다. 산출물은 직접 고치지 않습니다.

8. **index·log**
   - `02.wiki/index.md`에 새 페이지를 추가하고 요약을 고칩니다.
   - `02.wiki/log.md`에 추가합니다:
     ```
     ## [YYYY-MM-DD] ingest | {자료 제목}
     - raw: 01.자료실/...
     - 갱신: [[...]], [[...]] (N개), 신규: [[...]]
     - 상충: {있으면 한 줄}
     - 다시 볼 산출물: E03, E06
     ```

9. **보고**: 갱신한 페이지 수, 새 인사이트, 상충 내용, 다시 볼 산출물, 추가로 있으면 좋을 자료를 짧게 알립니다.
