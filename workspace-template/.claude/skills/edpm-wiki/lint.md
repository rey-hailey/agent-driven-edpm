# edpm-wiki lint

점검 결과를 `05.outputs/lint_YYYY-MM-DD.md`로 저장하고 요약을 보고합니다. 자동으로 고쳐도 되는 것(index 누락, 끊긴 링크 오타)은 목록을 보여주고 승인 후 고칩니다. 내용 판단이 필요한 것은 제안만 합니다.

템플릿에 남아 있는 `예시` 행(매스핏 샘플)과 `{...}` 자리표시자 안의 링크는 끊긴 링크·ID 추적 점검에서 빼고, "미결 표시" 개수로만 셉니다.

## 절차

1. 먼저 `python3 automation/scripts/edpm_check.py report`를 실행합니다. 결정적 항목(frontmatter 형식, 전제조건·게이트, 게이트 스킵, 끊긴 링크, verified 180일 초과, 식별 정보 패턴, 종료일 지난 WP, timebox 지난 프로토타입, 재검토일 지난 결정, 반영 안 된 회의록)은 이 결과를 그대로 씁니다. 다시 세지 않습니다.
2. 아래 표에서 스크립트가 못 보는 항목(모순, 출처 없는 주장, 고립 페이지, 실체 검증, G-CAL·G-MEASURE·G-CURRIC)만 LLM으로 점검합니다.
3. 인자 `pii`면 1의 식별 정보 결과만 상세히 보고 가명 처리 방법을 제안합니다. `gates`면 게이트 관련만.

## 점검 항목

### A. 개인정보 (항상 먼저)
- `01.자료실/`, `02.wiki/`, `03.docs/`, `05.outputs/`에서 전화번호, 이메일, 주민·학번 패턴, `OO초/중/고 N학년 N반` + 이름 조합을 정규식으로 찾습니다.
- 발견하면 다른 결과보다 먼저 보고합니다. `01.자료실/`는 수정 금지이므로 사람에게 처리 방법(원본 교체)을 묻습니다.

### B. 위키
| 점검 | 방법 |
|------|------|
| 오래된 정보 | `verified`가 180일 넘은 regulation·standard·competitor 페이지 → `status: stale` 제안 |
| 출처 없는 주장 | 출처 링크가 없는 문단, `sources: []`인 페이지 |
| 모순 | 같은 대상(경쟁사 가격, 법 조항, 지표 정의)에 대해 다른 값을 쓴 페이지 쌍 |
| 고립 페이지 | 들어오는 링크가 없는 페이지 |
| 끊긴 링크 | 존재하지 않는 `[[...]]` |
| index 불일치 | index에 없는 페이지, index에만 있는 페이지 |
| 빈자리 | 여러 페이지에서 언급되지만 자기 페이지가 없는 개념·경쟁사·이해관계자 |
| 조사 제안 | 위키에 근거가 부족한 질문 3~5개와 모을 자료 (Aside 레시피 포함) |

### C. 산출물
| 점검 | 방법 |
|------|------|
| 진행 현황 | E00~E20 frontmatter `status` 표 (n/a 사유 포함) |
| 프로토타입 | `V.프로토타입/프로토타입목록.csv`: timebox(종료일)가 지난 계획·진행 프로토타입, 결정이 비어 있는 V03, V01 기준 없이 시작된 P3·P4 빌드 (G-PROTO) |
| WBS 동기화 | 일정 관리 도구를 쓰는데 `M02_WBS.csv` `이슈` 열이 빈 WP, 종료일 지난 미완료 WP (`wbs_sync.py status`) |
| 게이트 위반 | 전제조건이 done이 아닌데 done인 산출물, G-LEARN·G-SAFE·G-AI·G-EVIDENCE·G-CAL·G-POLICY·G-CURRIC 위반 |
| 업무 모드 | 모드 F: 백로그에서 `진행` 상태인데 과제 폴더가 없는 FI, F02 영향 점검 미처리(G-IMPACT), 출시 후 30일 넘게 F04가 없는 과제(G-MEASURE). 모드 N: N04 결정 없이 확장 산출물(E18) 진행(G-STAGE), 가설에 중단 기준 없음 |
| 서비스 유형 정합성 | E00의 서비스 유형 대비 필수 산출물이 n/a로 돼 있거나, 해당없음 산출물을 작성 중인 경우 (`/edpm-start blueprint check` 제안) |
| 정책 정합성 | P01 환불 기준·S07 정산의 환불 차감·P05 CS 스크립트·결제 화면(E10) 문구가 서로 다른 경우 (`/edpm-doc policy sync`) |
| 게이트 스킵 | `gate_skip`이 있는 산출물과 사유 |
| ID 추적 | LO → REQ → F → SCR / EV → M 연결. 어떤 F에도 연결되지 않은 LO, 어떤 LO에도 연결되지 않은 F ("운영·지원" 분류 제외) |
| 근거 신선도 | `sources`의 위키 페이지가 산출물 `updated` 이후 갱신됨 → 다시 볼 산출물 |
| 미결 표시 | `[가정]`, `[확인 필요]`, `{...}` 남은 개수 (산출물별) |
| 계산 경로 | E07·E17·E19·M04·M05·S03의 수치에 스크립트·쿼리 경로가 없으면 경고 |
| 트랙 정합성 | M02 WBS 상태와 산출물 status 불일치, S02 효과 주장이 E19·E17에 없는 수치를 인용, A06 결과 파일 없음, B07 실행 기록 없음 |
| 교육과정 (KG 사용 시) | `kg_query.py coverage`로 매핑 CSV의 없는 코드 0건 확인, 산출물에 "필수 선수"로 쓴 관계가 KG에서 candidate인지 대조, 산출물의 KG 릴리스가 `sources.lock.json`과 다른지, `kg_sync.sh --check`로 원천 갱신 여부, 학부모·학생 문구의 금지 표현(뒤처짐·부족·미달·선행학습·불안·격차) |
| 자료실 | `_자료목록.md`에 없는 파일, 위키에서 한 번도 인용되지 않은 자료 (`/edpm-wiki library catalog` 제안) |

## log

`## [YYYY-MM-DD] lint | 개인정보 N, 위키 N, 산출물 N건`과 저장 경로를 추가합니다.
