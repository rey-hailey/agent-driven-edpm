# edpm-wiki research — 질문 하나로 출처 달린 리서치

리서치는 PRD의 근거입니다 (리서치가 먼저, PRD에 담는다). 이 명령은 웹에서 출처를 모아 **자료실에 원본 요약으로 남기고**, 위키에 종합하고, N01·E04·PRD 2절이 받아 쓸 수 있게 넘깁니다. 기억이나 추측으로 시장 규모·가격·정책을 쓰지 않습니다.

## 1. 질문 다듬기

- 사용자의 질문을 **결정에 쓰일 하위 질문 3~6개**로 나눕니다. 예: "유아 영어 리딩 앱 시장" → 대상 인구와 지출, 주요 경쟁 서비스와 가격, 학부모가 고르는 기준, 관련 규제(아동 개인정보·광고), 최근 2년의 변화.
- 이미 아는 것은 묻지 않습니다: `02.wiki/index.md`와 `market/`·`research/`·`domain/`을 먼저 읽고, 위키에 있는 것은 출처와 확인 날짜만 다시 봅니다.
- 하위 질문 목록과 "이 리서치로 정할 것"(예: N01 1절 기회 가설, E04 경쟁 표)을 보여주고 시작합니다.

## 2. 찾기

- 하위 질문마다 검색어를 2~3개(한국어·영어) 만들어 웹 검색을 합니다. 유력한 결과는 페이지를 직접 읽습니다. 검색 결과 요약만 보고 쓰지 않습니다.
- 출처를 등급으로 나눕니다.

| 등급 | 예 | 쓰는 법 |
|------|----|---------|
| 1차 | 정부·공공 통계, 법령·고시, 기관 원문, 학술 논문, 회사 공식 공시·가격표 | 수치·규정의 근거 |
| 2차 | 언론 기사, 시장조사 보고서 요약, 업계 리포트 | 1차를 찾는 단서, 맥락 |
| 3차 | 블로그, 마케팅 페이지, 커뮤니티 글 | 사용자 목소리·사례로만, 수치 근거로 쓰지 않음 |

- 수치는 **1차 출처가 둘 이상이거나 1차 하나**일 때만 사실로 씁니다. 그렇지 않으면 `[확인 필요]`. 출처끼리 다르면 둘 다 남깁니다.
- 접근할 수 없는 유료 보고서는 요약 기사만 인용하고 그렇게 적습니다.
- 학생·개인 정보가 담긴 페이지는 수집하지 않습니다.

## 3. 자료실에 남기기 (원본 요약)

출처마다 `01.자료실/시장/`(정책·규제면 `정책/`, 연구면 `현장/`이 아니라 `기술/` 또는 `시장/`)에 새 파일로 저장합니다. 자료실은 추가만 합니다.

파일명: `YYYY-MM-DD_research_<주제>_<NN>.md`

```markdown
---
type: source
source_url: https://…
publisher: {기관·매체}
published: YYYY-MM-DD        # 모르면 비움
accessed: YYYY-MM-DD
grade: 1차 | 2차 | 3차
question: {하위 질문}
---

# {출처 제목}

## 핵심 내용 (원문 요약, 인용은 짧게)
- …

## 이 리서치에 쓰는 부분
- …
```

`_자료목록.md`에 한 줄씩 추가합니다 (`/edpm-wiki library catalog`와 같은 형식).

## 4. 위키에 종합

- 하위 질문별 답을 `02.wiki/market/`(시장·경쟁·가격) 또는 `02.wiki/research/`(사용자·행동) 페이지로 씁니다. 기존 페이지가 있으면 갱신합니다.
- 문장마다 출처를 답니다: `([[01.자료실/시장/2026-11-03_research_유아영어_02]])`. 출처 없는 문장은 쓰지 않거나 `[가정]`.
- `## 상충하는 근거` 절에 서로 다른 수치·주장을 둘 다 적습니다.
- `verified: YYYY-MM-DD`를 적습니다 (가격·규제는 180일 뒤 `/edpm-wiki lint`가 다시 보라고 알림).
- `02.wiki/index.md`와 `log.md`(`## [YYYY-MM-DD] research | <질문> — 출처 N건(1차 n), 위키 n쪽`)를 갱신합니다.

## 5. 넘기기

결과를 한 장으로 보여줍니다.

| 하위 질문 | 답 (한두 문장) | 근거 등급 | 남은 확인 |
|-----------|----------------|-----------|-----------|

그리고 어디에 쓸지 제안합니다: N01 사업기회 1~4절, E04 시장·정책 분석의 경쟁·가격 표, PRD 2절 "왜 이 문제·왜 지금", E03 현장 리서치에서 직접 확인할 질문(웹으로 답이 안 되는 것 — 인터뷰로). 리서치는 PRD보다 먼저 써도 됩니다 (G-PRD 예외 문서의 입력).

## 원칙

- 리서치는 결정에 필요한 만큼만. 하위 질문마다 출처 3~5개면 충분합니다. 끝없이 넓히지 않습니다.
- 웹에서 얻은 것은 "시장이 말하는 것"입니다. 우리 사용자가 실제로 그런지는 인터뷰·데이터(E03, `/edpm-metrics`)로 확인합니다.
- 경쟁사 서비스명은 공개 정보만, 출처와 함께. 회사 내부 자료와 섞지 않습니다.
