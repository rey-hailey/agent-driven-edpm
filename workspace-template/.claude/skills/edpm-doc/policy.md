# edpm-doc policy

## 원칙

- **법률 자문이 아닙니다.** 법령·고시의 구체 수치(철회 기간, 반환 비율, 세율)는 공식 원문(국가법령정보센터 law.go.kr, 공정거래위원회 고시 등)을 확인해 출처 URL·확인일을 적고, 확인 전에는 `[확인 필요]`로 둡니다. 최종본은 법무 검토를 받습니다.
- **정책은 계산 가능해야 합니다.** 환불·정산·진도 기준은 표나 스크립트로 재현할 수 있게 씁니다 (실체 검증).
- **정책은 화면·약관·CS·데이터에 모두 반영돼야 끝납니다.** 문서만 있고 결제 화면 안내와 다르면 분쟁이 납니다.

## legal-check <P0x>

1. 문서의 `[확인 필요]`와 법령 근거 표를 모읍니다.
2. 항목마다 공식 원문을 찾아 확인합니다 (웹 검색·가져오기 가능할 때). 찾은 조문·고시 번호, URL, 확인일을 표에 채우고, 찾지 못한 것은 `[확인 필요]`로 남깁니다.
3. 결과를 `05.outputs/legal_check_P0x_YYYYMMDD.md`로 저장하고, 법무에게 넘길 질문 목록을 만듭니다.
4. 확인한 일반 법령 정보는 `02.wiki/domain/` 해당 페이지에도 `verified` 날짜와 함께 반영합니다 (회사 고유 판단은 `company/`).

## sync <P0x> — 반영 점검

| 반영처 | 확인 |
|--------|------|
| 이용약관·환불 안내 | 문서와 문구·수치 일치 |
| 결제·구매 화면 (E10) | 청약철회 제한 고지, 환불 기준 노출 위치 |
| 데이터 (E12) | 정책 판단에 필요한 이벤트(진행률, 다운로드, 수강 시작일)가 수집되는가 |
| 정산 (S07) | 환불·쿠폰이 강사 정산에 어떻게 반영되는가 |
| CS 스크립트 (P05) | 상담원이 같은 기준으로 답하는가 |
| 강사 계약 (P02) | 환불 차감·권리 조항 일치 |

불일치 목록을 보고하고 고칠 산출물을 제안합니다.

## calc-refund

P01의 환불 규칙을 `automation/scripts/P01_환불계산.py`(없으면 P01의 예시 코드로 생성)로 만들어, 대표 사례(결제 직후, 1강 수강 후, 진행률 30%·60%, 기간 절반 경과, 쿠폰 적용, 번들 일부 수강)를 계산한 표를 P01에 붙입니다. 법령 기준 수치가 `[확인 필요]`면 결과에도 표시합니다.
