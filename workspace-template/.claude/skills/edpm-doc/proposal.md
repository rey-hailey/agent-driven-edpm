# edpm-doc proposal

## analyze <RFP 파일> → S01

1. RFP 파일(PDF·HWP 변환본·DOCX)을 `01.자료실/제안/`에 두고 읽습니다. HWP는 PDF나 텍스트로 변환해 달라고 요청합니다.
2. 기본 정보(발주기관, 사업명, 예산, 기간, 제출일, 계약 방식, 제출 서류)를 뽑습니다.
3. **요구사항 추출표**: 원문 조항·페이지마다 요구를 RFP-001로 뽑고 유형(기능/성능/보안/개인정보/교육내용/운영/산출물)을 붙입니다. 각 요구를 우리 산출물(E06 REQ, E09 F, E13, B 트랙)에 연결하고 충족도(충족/부분/개발필요/불가)를 매깁니다. 추출 누락을 줄이려고 "~하여야 한다", "~할 것", "~을 제출" 같은 표현을 기계적으로 한 번 더 훑습니다.
4. **평가항목 대응표**: 평가 기준과 배점을 EVAL-01로 정리하고, 항목마다 우리 강점 근거(위키·E19·사례)와 담당 장을 정합니다.
5. 질의 목록(모호한 요구, 데이터 제공 범위, 개인정보 처리 위탁 여부)을 만듭니다.
6. 결과를 `03.docs/S.사업/S01_RFP분석서.md`에 씁니다.

## gonogo

S01을 바탕으로 적합도, 필수 요건 충족 여부, 수주 가능성(경쟁사·평가 구조), 수익성(S03 초안), 일정 부담(M02와 겹침), 리스크를 표로 점수화하고 권고를 냅니다. 결정은 사람이 하고, 결정은 ADR로 남깁니다.

## write → S02

1. 게이트: E04, E06, S01(RFP 제안일 때) 확인.
2. 평가항목 순서와 배점에 맞춰 장 구성을 정합니다 (배점 높은 항목에 분량 배분).
3. 교육과정 연계 장은 `kg_query.py export --map 03.docs/3.설계/E11_교육과정매핑.csv`(정합표)와 `coverage` 결과를 넣고 출처 고지를 부록에 둡니다. "공식 인증·공식 연계" 표현은 쓰지 않습니다.
4. 장마다 근거 산출물에서 내용을 가져옵니다: 현장 문제(E01·E03), 학습 성과(E05), 솔루션(E06·E09·E10), 안전·개인정보(E13), AI 활용 고지·가드레일(E14), 수행 일정(M02), 운영·연수(E18), 가격(S03).
5. **효과 주장 규칙**: 성과 수치는 E19·E17 또는 공개 출처만 인용하고, 증거 수준과 한계를 함께 씁니다. 근거 없는 "OO% 향상"은 쓰지 않습니다.
6. RFP 요구 ↔ 제안서 위치 매핑표를 부록으로 만듭니다 (누락 방지).

## price → S03

세그먼트별 가격 모델을 정하고, 원가(LLM API 학습자당 비용, 콘텐츠, 인프라, 지원 인력)를 스크립트나 표 계산으로 산출해 견적표를 만듭니다. 계산식이 재현 가능해야 합니다. 부가세·조달 수수료 등 확인이 필요한 항목은 `[확인 필요]`로 둡니다.

## deck

S02를 발표 자료로 변환합니다. `pptx` 스킬을 쓰고, 평가위원 발표 시간(예: 15분)에 맞춰 장표 수를 정하고, 장표마다 발표자 노트를 넣습니다. 파일명 `제안발표_YYYYMMDD_HHMM.pptx`.

## check — 제출 전 점검

| 점검 | 방법 |
|------|------|
| 요구 누락 | S01의 RFP-ID가 모두 S02 매핑표에 있는가 |
| 필수 서류 | 제출 서류 체크리스트 완료 여부 |
| 분량·형식 | RFP의 쪽수 제한, 글꼴, 파일 형식 |
| 수치 근거 | S02의 모든 수치에 출처가 있는가, 가격이 S03과 일치하는가 |
| 개인정보·기밀 | 실명·연락처, 다른 고객사 이름·단가 노출 여부 |
| 용어 일관성 | 제품명·기능명이 장마다 같은가 |

결과를 `05.outputs/proposal_check_YYYYMMDD_HHMM.md`로 저장합니다. 필요한 첨부 자료는 `/edpm-wiki library bundle 제안`으로 묶습니다.
