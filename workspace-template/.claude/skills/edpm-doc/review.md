# edpm-doc review

## 원칙

- 패널은 위키의 페르소나(`02.wiki/learners/`)와 현장 인사이트(`02.wiki/research/`)를 근거로 말합니다. 근거가 없는 비평은 `[추측]`으로 표시합니다.
- 결과 맨 위에 "이 검토는 실제 사용자 검증이 아닙니다. 중요한 지적은 E16 검증계획에 넣어 현장에서 확인하세요."라고 적습니다.
- 칭찬은 생략하고, 문제와 개선안만 적습니다.

## 기본 패널

| 패널 | 보는 것 | 기본 대상 산출물 |
|------|---------|------------------|
| 학습자 (해당 연령) | 이해되는가, 지루하지 않은가, 막혔을 때 어떻게 되는가 | E08, E10, E14 |
| 교사 | 수업 시간에 실제로 쓸 수 있는가, 업무가 늘지 않는가, 성취기준과 맞는가, 학생 관리가 되는가 | E05, E06, E08, E09, E11, E14, E18 |
| 보호자 | 아이에게 안전한가, 효과를 어떻게 알 수 있는가, 돈값을 하는가, 화면 시간 | E06, E13, E18, E19 |
| 학교 관리자·교육청 담당 | 도입 절차, 예산 항목, 보안·개인정보 심의, 교사 연수 부담, 공정성 | E06, E13, E18 |
| 학원 원장 | 재등록·성적 향상 증거, 강사 운영 부담, 학부모 상담 자료 | E06, E07, E18 |
| 학습과학자 | 학습 목표와 활동·평가의 정렬, 인지부하, 피드백 설계, 효과 측정의 타당성 | E05, E07, E08, E16, E19 |
| 성인 학습자 (직장인·취준생) | 시간 대비 효과, 수료·자격 가치, 환불·수강 기간, 모바일 학습 | L01, L03, P01, E10 |
| 강사·튜터 | 제작 부담, 정산 투명성, 권리 조항, 학습자 질문 응대 부담 | L02, S07, P02, P06 |
| 기업 교육 담당자 (HRD) | 배정·이수 관리, 보고서, 법정 의무교육·환급 요건, 예산 | L03, L05, P01, P03, S03 |
| 개인정보·안전 검토자 | 최소 수집, 동의, 보관·파기, 외부 AI 전송, 아동 안전, 접근성 | E12, E13, E14 |

`--panel`이 없으면 위 표에서 대상 산출물에 해당하는 패널을 고릅니다 (3~4명).

## 절차

1. 대상 산출물과 그 전제 산출물, 관련 위키 페이지를 읽습니다.
2. 패널별로 독립적으로 비평합니다 (서로의 의견을 보지 않게 서브에이전트로 나누면 더 좋음).
3. 결과를 합칩니다:

   | # | 패널 | 지적 | 근거 | 심각도 (출시 차단/높음/보통/낮음) | 개선안 | 반영 위치 (ID) |
   |---|------|------|------|-----|------|------|

4. 패널 사이에 충돌하는 요구(예: 교사는 상세 리포트, 보호자는 간단 요약)를 따로 정리합니다.
5. 실제 현장에서 확인해야 할 질문을 E16 검증 항목 후보로 뽑습니다.
6. `05.outputs/review_Exx_YYYY-MM-DD.md`로 저장하고, 산출물 frontmatter `reviewers`에 패널을 추가합니다.
7. log: `## [YYYY-MM-DD] review | Exx — 출시 차단 N, 높음 N`
