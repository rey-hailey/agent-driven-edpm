# edpm-meeting

회의록은 `04.ops/회의록/YYYY-MM-DD_회의명.md` (템플릿 `_template.md`). 외부 참석자(교사·학부모·학생·원장)는 실명 대신 가명(`교사A`, `OO학원 원장`)으로 적고, 녹취 원문은 워크스페이스에 넣지 않습니다 (AGENTS.md 7절).

## prep <회의명> [날짜]

회의 전 한 장 요약을 `04.ops/회의록/YYYY-MM-DD_회의명_준비.md`로 만듭니다.
1. 목적을 "이 회의가 끝나면 무엇이 정해지나"로 씁니다. 정할 것이 없으면 회의 대신 문서 공유를 제안합니다.
2. 안건마다 관련 산출물·ID·수치(스크립트 결과만)와 열린 질문, 선택지 초안을 붙입니다. 결정 사항이 되돌리기 어려우면 `/edpm-decide new`로 ADR 초안을 먼저 만들지 묻습니다.
3. 외부 이해관계자 회의(교사 패널, 원장, 학부모 간담회, 기관 담당자)면: 질문 목록(유도하지 않는 열린 질문), 보여줄 프로토타입·화면, 동의·개인정보 안내, 시간 배분(교사는 수업 사이 30분 이내).
4. 시즌 확인: 시험 기간·학기 초·입학설명회 등과 겹치면 경고 ([[domain/학사일정]]).

## notes <메모 파일|붙여넣기>

회의 후 메모·채팅·녹취 요약을 받아 회의록 템플릿으로 정리합니다.
1. 참석자 → 2절 (외부는 가명 + SH-ID), 논의 → 3절 (관련 ID 연결), 결정 → 4절, 할 일 → 5절, 근거가 될 발언·관찰 → 6절 위키 반영 항목.
2. **결정 분류**: 되돌리기 어려운 결정은 `/edpm-decide new`로 ADR 작성을 제안하고 4절에 링크. 경미한 결정은 "경미하여 생략".
3. **액션 아이템**: 담당·기한이 없으면 묻습니다. WBS가 있으면 `/edpm-wbs`에 WP로 넣을지, 기능 요청이면 `/edpm-feature intake`로 백로그에 넣을지 제안합니다.
4. 실명·연락처가 섞여 있으면 저장 전에 가명으로 바꿉니다 (훅이 자료실·위키 저장을 막습니다).
5. frontmatter `ingest: pending`으로 저장합니다.

## ingest [회의록 파일]

`ingest: pending`인 회의록(없으면 `edpm_check.py json`의 `meetings_pending`)을 대상으로 6절 "위키 반영 항목"을 `/edpm-ingest`로 처리합니다. 인사이트는 `research/IN-xxx`, 회사 사정은 `company/`, 이해관계자 변화는 E02에 반영. 처리 후 `ingest: done`, log `## [YYYY-MM-DD] ingest | 회의록 YYYY-MM-DD 회의명`.

## actions

모든 회의록 5절의 액션 아이템을 모아 기한 지난 것, 이번 주 것, 담당별로 표로 보여줍니다. 완료된 항목은 회의록에서 상태를 `완료`로 바꿀지 묻습니다. `/edpm-weekly`가 이 표를 씁니다.
