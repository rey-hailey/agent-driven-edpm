# edpm-library

`01.자료실/`은 비식별화된 원본을 분류해 보관하는 곳입니다. 자료를 넣는 일은 `/edpm-ingest`가 하고, 이 스킬은 보관된 자료를 **찾고, 정리하고, 꺼내 쓰는** 일을 합니다. 원본 파일은 수정하지 않습니다.

## 자료실 분류

| 폴더 | 담는 자료 |
|------|-----------|
| 현장/ | 인터뷰, 수업·학원 관찰, 앱 리뷰, 커뮤니티 VOC, 파일럿 피드백 |
| 정책/ | 법령, 교육부·교육청 공지, 교육과정 문서, 가이드라인 |
| 시장/ | 경쟁사 자료, 가격, 시장 보고서, 입찰 공고 |
| 데이터/ | 지표 export(집계), 실험·파일럿 데이터(가명), 테스트·평가 결과 |
| 회의/ | 회의록 원본 |
| 회사/ | 회사 소개서, 전략, 조직도, 계약·SOW 요약 |
| 제안/ | 제안요청서(RFP), 과거 제안서, 평가표, 질의응답 |
| 콘텐츠/ | 교육과정 성취기준 표, 교재·문항 레퍼런스, 저작권 이용허락 문서 |
| 기술/ | 개발 문서 요약, 인프라 자료, 외부 API 문서, 보안 인증 자료 |

## 하위 명령

### catalog — 목록 재생성
1. 모든 분류 폴더의 파일을 읽어 맨 위 출처 정보(제목, 수집일, 출처, 수집 도구)를 모읍니다.
2. `01.자료실/_자료목록.md`를 다시 씁니다: 분류별 표 `| 파일 | 제목 | 수집일 | 출처 | 위키 반영 | 사용 산출물 |`.
   - "위키 반영"은 `02.wiki/`에서 이 파일을 출처로 인용한 페이지 수
   - "사용 산출물"은 `03.docs/`에서 이 파일을 인용한 산출물 ID
3. 위키에서 한 번도 인용되지 않은 자료는 "미반영"으로 표시하고 `/edpm-ingest` 재처리를 제안합니다.

### find <키워드>
파일명·본문을 검색해 결과를 `| 파일 | 분류 | 수집일 | 일치 부분(한 줄) |`로 보여줍니다. 관련 위키 페이지도 함께 알려줍니다.

### stale — 오래된 자료 점검
정책·시장·제안 자료 중 수집일이 180일 넘은 것, 같은 주제의 새 자료가 들어와 대체된 것을 보고합니다. 원본은 지우지 않고, 목록에 "대체됨: 새 파일" 표시만 합니다.

### bundle <목적> — 공유 번들
제안서 첨부, 경영진 보고, 외주사 전달처럼 자료를 묶어 보내야 할 때 씁니다.
1. 목적에 맞는 자료 후보를 고르고 목록을 보여줍니다.
2. 사람이 승인한 파일만 `05.outputs/bundle_<목적>_YYYYMMDD_HHMM/`에 복사하고 `목록.md`(파일·출처·용도)를 함께 만듭니다.
3. 외부로 나가는 번들이면 개인정보 패턴과 회사 기밀 표시(`company/` 인용, 단가·매출)를 한 번 더 검사하고 결과를 보고합니다.

### nlm-sync — NotebookLM 동기화 (선택)
NotebookLM은 기준 저장소가 아니라 공유·청취용입니다. 경영진·영업팀이 질문하거나 오디오 요약으로 들을 자료만 올립니다.
1. `AGENTS.md`의 기밀 규칙에서 외부 서비스 업로드가 허용되는지 확인합니다. 정해지지 않았으면 묻습니다.
2. 올릴 대상을 정합니다: 기본은 `status: done` 산출물과 `02.wiki/domain/`. 학생 데이터·회사 기밀이 담긴 파일은 제외합니다.
3. NotebookLM MCP(`notebook_list`, `source_add`)나 `nlm` CLI가 있으면 사용합니다. 노트북 ID는 `AGENTS.md` 2절이나 `.env`에서 읽습니다. 없으면 수동 업로드 목록을 만들어 줍니다.
4. 올린 목록을 `01.자료실/_자료목록.md` 끝 "NotebookLM 동기화" 절에 날짜와 함께 남깁니다.
