# edpm-start

처음 쓰는 PM이 길을 잃지 않게 하는 안내 스킬입니다. 설명은 짧게, 바로 첫 단계로 이어갑니다.

## 1. 지금 상태 확인

`python3 automation/scripts/edpm_check.py phase`를 실행합니다.

- **0 시작**(E00 없음)이면 2절로.
- 그 밖이면 "지금 단계: … / 다음: …"을 그대로 보여주고, 다음 명령을 바로 실행할지 묻습니다. 사용자가 다른 일을 원하면 3절 표에서 맞는 흐름을 찾습니다.

## 2. 처음이면: 하려는 일 묻기

한 번에 하나만 묻습니다. 선택지를 보여주고 고르게 합니다.

**Q1. 어떤 일을 하시나요?**

| 선택 | 의미 | 업무 모드 |
|------|------|-----------|
| 새 서비스·신사업을 시작한다 | 아직 없는 제품을 만든다 | N |
| 운영 중인 서비스를 개선한다 | 이미 있는 서비스의 PM | F |
| 둘 다 | | NF |

**Q2. 이미 정리된 기획서·PRD·RFP가 있나요?**
- 있으면: 파일을 `00.inbox/`에 넣게 하고 `/edpm-init` 후 `/edpm-prd import <파일>`로 PRD로 정리합니다.
- 없으면: `/edpm-init` 인터뷰 후 `/edpm-prd`로 처음부터 씁니다.

**Q2-1. 회사에 정해진 문서 양식이 있나요?** (PRD·기획서·요구사항정의서·보고서 등)
- 먼저 알려줍니다: **이 프레임워크가 만드는 산출물·SQL·정책 초안·도메인 지식은 모두 출발점(템플릿)입니다.** 예시 행은 가상이고, 회사 기준에 맞춰 쓰거나 옮겨야 합니다.
- 양식이 있으면: `/edpm-template import <파일>`로 md로 구조화 → `map`으로 산출물과 짝지음. 방식 A(회사 양식 구조로 작성) 또는 B(EdPM으로 쓰고 회사 양식으로 옮겨 냄)를 고릅니다.
- 없으면: EdPM 템플릿을 그대로 씁니다. 나중에 양식이 생기면 그때 연결합니다.

**Q3. 제품은 누가 만드나요?** (`AGENTS.md` 2절 "개발 체계")

| 선택 | PM이 하는 일 |
|------|--------------|
| 개발팀이 있다 | PRD → 상세 요구사항 → 스펙 → 프로토타입(PRD의 정수 시연) → 개발팀에 이관. 제품 코드는 개발팀 몫 |
| 개발자 없이 직접 만든다 (바이브코딩) | 같은 문서를 거친 뒤 스펙의 작업 단위로 PM이 LLM과 구현 (`src/`) |

## 3. 흐름 보여주기

답에 맞는 한 장을 보여줍니다. 공통 뼈대는 하나입니다: **PRD가 원점, 프로토타입은 PRD의 정수, 코드는 스펙 승인 후.**

```
시작 ─► /edpm-init ─► /edpm-prd (제품 전체) ─► 착수·근거 ─► 상세 요구사항(E06) ─► 스펙(E09)
                                                                  ├─► 프로토타입: PRD 9절의 정수 (/edpm-proto)
                                                                  └─► 개발팀: /edpm-handoff dev  |  바이브코딩: /edpm-spec build
```

| 하려는 일 | 착수·근거 단계 | 그 뒤 |
|-----------|----------------|-------|
| 신사업 (N) | `/edpm-venture opportunity`(N01), `/edpm-report M01` | E06 → E09 → `/edpm-proto` → N02 투자심의 → N03 → N04 |
| 운영 개선 (F) | `/edpm-feature baseline`(F00), `/edpm-report M01` | 과제마다 F01 → F02(= 기능 단위 스펙) → F03 → F04 |
| 기획서 있음 | `/edpm-prd import` | 위 둘 중 해당 흐름 |
| 직접 구현 | 위와 같음 | E09 승인 후 `/edpm-spec build T-xx` |

매일 할 일은 세션을 열 때 뜨는 상황판과 `/edpm-brief`가 알려줍니다. 막히면 "지금 뭐 해야 해?"라고 물으면 됩니다.

## 4. 바로 시작

"지금 `/edpm-init`을 시작할까요?"처럼 첫 명령 하나를 제안하고, 동의하면 그 스킬의 절차로 넘어갑니다. 답한 모드·개발 체계는 init 인터뷰에서 다시 묻지 않도록 넘깁니다.

## 원칙

- 프레임워크 순서를 건너뛰지 않습니다. 사용자가 "바로 코드부터"를 원하면 PRD·스펙이 왜 먼저인지 한 줄로 말하고, 그래도 원하면 프로토타입(`06.prototypes/`, V01 필요)으로 안내합니다. 제품 코드(`src/`)는 훅이 스펙 승인 전에는 막습니다.
- 설명은 표 한 장 이내. 길게 강의하지 않고 다음 행동으로 잇습니다.
