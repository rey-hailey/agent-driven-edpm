# edpm-start init

새 회사·제품 워크스페이스를 시작합니다. 한 번만 실행하며, 이미 `03.docs/0.온보딩/E00_회사사업프로필.md`의 status가 `done`이면 갱신 모드로 동작합니다(바뀐 항목만 묻기).

## 절차

1. **환경 확인**
   - 현재 폴더에 `AGENTS.md`, `02.wiki/`, `03.docs/`가 있는지 확인합니다. 없으면 프레임워크의 `workspace-template/`을 복사하라고 안내하고 멈춥니다.
   - `CLAUDE.md`가 없으면 `@AGENTS.md` 한 줄로 만듭니다.
   - git 저장소가 아니면 `git init`을 제안합니다.

2. **회사 프로필 인터뷰** (한 번에 3~4개씩, 모르는 것은 `[확인 필요]`로 두고 넘어감)
   - 회사·제품 이름, 한 줄 설명
   - **업무 모드**: 새 서비스·신사업을 시작하나(N), 이미 운영 중인 서비스의 PM인가(F), 둘 다인가 (`/edpm-start`에서 이미 답했으면 묻지 않음)
   - **개발 체계**: 개발팀이 있나(PM은 스펙까지 만들고 이관), 개발자 없이 PM이 LLM과 직접 만드나(바이브코딩) → `AGENTS.md` 2절 "개발 체계"
   - 이미 정리된 기획서·PRD·RFP가 있나 (있으면 9단계에서 `/edpm-prd import`)
   - **회사 문서 양식**이 정해져 있나 (PRD·기획서·요구사항·보고서 등). 있으면 "EdPM 산출물은 템플릿에서 출발한 초안이며, 회사 양식을 md로 구조화해 그 구조로 쓰거나(방식 A) EdPM 산출물을 회사 양식으로 옮겨 낼(방식 B) 수 있다"고 안내하고 `/edpm-template import`로 양식을 받습니다. 회사 DB가 있으면 지표 SQL은 기본 스키마 예시이므로 `/edpm-metrics connect`에서 맞춘다고 함께 안내합니다
   - 서비스 유형: 무엇을 누구에게 어떻게 제공하나 (→ `/edpm-start blueprint detect`로 AT01~AT15 판정)
   - 사업 유형: K-12 공교육(B2G·B2S) / 학원(B2B2C) / 소비자(B2C) / 고등교육 / 기업교육 (복수 가능)
   - 학습자 연령대와 미성년 포함 여부
   - 사용자·구매자·결제자·의사결정자가 각각 누구인지
   - 수익 모델, 주요 판매 시기
   - AI 기능 유무와 계획
   - 콘텐츠·문항을 직접 만드는지
   - 학교·LMS·HRIS 연동 여부
   - 이번 일의 형태: 제품 개발 / 고객사 구축 / 정부·교육청 과제 / 영업 지원 (관리·사업 트랙 범위 결정)
   - 회사 개발 문서 표준이 있는지 (없거나 PM이 MVP를 직접 만들면 구현 트랙 사용)
   - RFP 대응·제안 영업을 하는지
   - 국가 교육과정(2022 개정) 기반 제품인지, 대상 학교급·과목·학년군 (예이면 교육과정 지식그래프 사용)
   - 회사 도구 (이슈 관리, 문서, 메신저, 분석 도구)
   - 일정 관리 도구: 팀과 WBS를 어디서 공유하나 (기본 GitHub 비공개 저장소 / 스프레드시트 / Notion / Jira / Linear) → `AGENTS.md` 2절과 `automation/wbs.json`, GitHub면 `/edpm-wbs setup` 안내
   - 프로토타입을 직접 만들 때 쓸 스택 (회사 스택이 있으면 그것, 없으면 기본 Next.js + Tailwind + Supabase + Vercel) → `AGENTS.md` 2절
   - 기밀 규칙 (학생 데이터 외부 전송, 브라우저 에이전트 사용 허용 여부)
   - 내 역할과 범위, 첫 90일 기대치

3. **E00 작성**: `03.docs/0.온보딩/E00_회사사업프로필.md` 템플릿을 채웁니다. 모듈 선택 표는 `guide/02.산출물체인과게이트.md` 3절의 규칙을 따르고, 판단 근거를 적습니다.

3.0 **업무 모드 적용**: 모드 N이면 `/edpm-doc venture plan`으로 단계별 문서 구성을, 모드 F면 `/edpm-doc feature baseline`(F00)과 개선 백로그를 안내합니다. 모드 F에서는 F00이 대체하는 E01~E07을 n/a로 둡니다. 모드 N이 아니면 N01~N04를, 모드 F가 아니면 F00·과제 템플릿을 n/a로 둡니다.

3.1 **서비스 유형 적용**: `/edpm-start blueprint apply <AT0x>`로 유형별 필수·권장·해당없음을 반영합니다. 아래 4단계는 유형 적용으로 정해지지 않은 나머지에만 씁니다.

4. **해당없는 산출물 표시**: 활성화되지 않은 모듈의 산출물(E11~E14, E18, B01~B07, A00~A09, S01~S07, L01~L06, P01~P06) frontmatter를 `status: n/a`로 바꾸고 사유를 한 줄 적습니다. 관리 트랙(M01~M05)은 기본 활성입니다. AI 트랙은 `/edpm-ai type` 판정 전까지 미정으로 둡니다.

5. **위키 시드**
   - 개인 Brain 경로(인자, 기본 `~/EdTech-Brain`)가 있으면 `domain/` 페이지를 `02.wiki/domain/`으로 복사합니다. 이미 있는 파일은 덮어쓰지 않고 목록을 보고합니다.
   - Brain이 없으면 프레임워크의 `brain-seed/domain/`을 씁니다.
   - 사업 유형과 관계없는 페이지는 복사하되 index에서 "참고"로 분류합니다.
   - `02.wiki/company/회사개요.md`를 E00 요약으로 만듭니다.

6. **AGENTS.md 회사 컨텍스트**: 2절 표를 채운 변경안을 보여주고, 승인받은 뒤 반영합니다.

6.1 **교육과정 지식그래프** (국가 교육과정 기반이면): `/edpm-curriculum setup`으로 KG를 받아 빌드하고, E00 "교육과정 지식그래프 연결" 절을 채웁니다. 대상 학년이 올해 2015 개정을 적용받으면 알립니다.

7. **index·log 갱신**: `02.wiki/index.md`를 다시 만들고 `log.md`에 `## [YYYY-MM-DD] init | {회사명} 워크스페이스 초기화`를 추가합니다.

8. **다음 단계 안내**
   - 첫 주에 모을 자료 목록과 자료실 위치 (회사 소개서 → 회사/, 제품 데모 계정·개발 문서 → 기술/, 최근 VOC → 현장/, 지표 → 데이터/, 과거 제안서·RFP → 제안/, 교육과정·교재 → 콘텐츠/, 학사·영업 캘린더 → 회사/)
   - 쓸 만한 Aside 레시피 (`automation/aside/recipes/`)
   - **다음 산출물은 PRD입니다.** 모든 산출물·프로토타입·코드는 루트 `PRD.md`에서 출발합니다. 이어서 `/edpm-prd`(기존 기획서가 있으면 `/edpm-prd import <파일>`)를 바로 시작할지 묻습니다.
   - PRD가 `review`가 되면: M01 착수보고서(`/edpm-brief report M01`)와 P1 묶음 (E01, E02, E04) → E06 상세 요구사항 → E09 스펙.
   - `python3 automation/scripts/edpm_check.py phase`로 지금 단계를 보여줍니다.

## 주의

- 인터뷰 답변에 학생·고객 실명이 나오면 가명으로 바꿔 적습니다.
- 회사 기밀 수치는 `02.wiki/company/`에만 적고, `domain/`에는 쓰지 않습니다.
