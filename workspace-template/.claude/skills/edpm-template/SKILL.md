# edpm-template

**EdPM 산출물은 템플릿에서 출발한 초안입니다.** 회사에 문서 양식이 있으면 이 스킬로 맞춥니다. 폴더: `templates/회사양식/` (README에 두 방식 설명).

| 방식 | 의미 |
|------|------|
| A. 회사 양식 적용 | 산출물을 처음부터 회사 양식의 절 구조로 씁니다. EdPM 필수 항목은 끝에 "EdPM 필수 항목" 절로 남깁니다 |
| B. 회사 양식으로 옮기기 | EdPM 템플릿 구조로 쓴 산출물을 원본으로 두고, 회사 양식 출력본을 `05.outputs/`에 만듭니다 |

## 원칙

1. **EdPM 산출물이 원본.** frontmatter(`doc_id`, `status`, `requires`, `updated`, `gate_skip`)와 게이트·추적이 보는 항목을 지우지 않습니다. 회사 양식에 없으면 방식 A에서는 "EdPM 필수 항목" 절로, 방식 B에서는 원본에 그대로.
2. **새 사실을 만들지 않습니다.** 회사 양식에만 있는 칸(결재, 문서 번호, 보안 등급)은 비워 두고 사람에게 묻습니다.
3. 회사 양식 파일에는 빈 양식만. 실제 고객·학생 정보가 들어 있으면 지우고 넣습니다 (G-PII).

## import <파일>

회사 양식(docx·pptx·pdf·hwp를 PDF로 바꾼 것, 사내 위키 내보내기, 붙여넣은 목차)을 읽어 `templates/회사양식/<문서명>.md`로 구조화합니다.
- 절 제목과 순서, 표의 열, 각 절의 작성 지침(양식에 적힌 안내 문구), 필수·선택 표시, 결재·보안·문서 번호 같은 머리 항목
- 원본 파일은 `/edpm-wiki ingest`로 `01.자료실/회사/`에 보관합니다
- 끝나면 `map`으로 이어갑니다

## map

`templates/회사양식/`의 양식마다 EdPM 산출물을 짝지어 `양식매핑.md`를 채웁니다.
1. 이름·목적으로 후보를 제안합니다 (예: 서비스기획서 → PRD, 요구사항정의서 → E06, 기능정의서 → E09, 착수보고서 → M01, 주간업무보고 → 04.ops 주간보고).
2. 짝마다 절 대응표를 만듭니다: 회사 양식 절 ↔ EdPM 절. **회사 양식에 없는 EdPM 필수 항목**(게이트·추적 대상)과 **회사 양식에만 있는 항목**을 각각 적습니다.
3. 방식(A/B)을 사용자가 고릅니다. 기본 추천: 회사가 그 양식을 결재·공유의 공식 문서로 쓰면 A, 참고용이면 B.
4. 하나의 회사 문서가 여러 EdPM 산출물을 합친 것이면(예: 기획서 = PRD + E06 일부) 그렇게 적고 방식 B를 권합니다.

## apply <ID>

| 방식 | 하는 일 |
|------|---------|
| A | `/edpm-doc <ID>`가 작성할 때 이 매핑을 읽어 회사 양식 절 순서로 쓰고, EdPM 필수 항목은 끝 절로. frontmatter는 유지. 이미 EdPM 구조로 쓴 문서를 A로 바꾸려면 내용을 옮기되 원본 백업을 남기지 않고 git 이력에 맡깁니다 |
| B | 원본 산출물을 읽어 회사 양식 구조로 옮긴 출력본 `05.outputs/회사양식_<ID>_YYYYMMDD_HHMM.md`를 만들고, `--format docx|pptx`면 문서 스킬로 변환. 원본에서 바뀐 내용은 다음 apply 때 다시 옮깁니다(출력본을 직접 고치지 않음) |

옮길 때 회사 양식의 작성 지침과 맞지 않는 내용(예: 양식은 "기대 효과 수치 필수"인데 원본에 측정 근거 없음)은 `[확인 필요]`로 표시하고 목록으로 보여줍니다. 효과 수치는 `/edpm-metrics` 결과만 씁니다.

## list

등록된 회사 양식, 매핑된 EdPM 산출물, 방식, 마지막 apply 시각.
