# edpm-content

## S04 / S05

`/edpm-doc`과 같은 게이트·근거 규칙으로 작성합니다. S04는 E02(이해관계자)·E06(요구)과 `[[domain/세그먼트별의사결정구조]]`를, S05는 E04(시장)·학사일정을 근거로 합니다.

## make <콘텐츠 유형> [대상]

| 유형 | 대상 | 근거 산출물 | 형식 메모 |
|------|------|-------------|-----------|
| 학부모 안내문 | 보호자 | E06, E13(수집 항목·동의), E18 | 가정통신문처럼 A4 1장, 쉬운 말, 개인정보 처리 안내 포함 |
| 교사 수업 활용 가이드 | 교사 | E08(학습 흐름), E10, E05 | 차시 흐름 예시(도입·전개·정리), 교사 개입 지점, 성취기준 연결 |
| 교사 연수 자료 | 교사 | E08, E10, E18 | 슬라이드 + 실습 과제, 30분·60분 버전 |
| 원장 대상 소개서 | 학원 원장 | E06, E07(M-4x), E19 | 재등록·학부모 상담에 주는 가치, 운영 부담 |
| 기관 소개서 | 학교·교육청 | E06, E13, E19, S02 | 도입 절차, 보안·개인정보, 연수·지원 |
| 블로그·학습법 칼럼 | 보호자·학습자 | `02.wiki/domain/` 학습과학 페이지 | 학습법 근거를 쉽게 설명, 제품 홍보는 끝에 짧게 |
| 앱스토어 문구 | 보호자 | E06, E10 | 기능을 과장 없이, 연령 등급·개인정보 문구 확인 |
| 데모 대본 | 영업 | S04, E10 | 7분·15분 버전, 역할 순서(학생 → 교사 → 보호자) |
| 예비 중1·고1 안내 | 보호자·학생 | `kg_query.py gaps --subject <과목>` (신규 개념·쉬운 설명 검토본), E06 | 학교급이 바뀌며 달라지는 점과 이어지는 점 중심, 금지 표현 점검 필수 |
| FAQ | 전체 | E13, E18, CS 문의(위키 research/) | 개인정보·가격·효과·기기 질문 우선 |

절차:
1. 근거 산출물과 위키 페이지를 읽습니다. 근거가 없으면 무엇이 필요한지 먼저 알립니다.
2. 대상에 맞는 말투로 씁니다 (학생: 짧고 쉬운 문장 / 교사: 수업 용어 / 보호자: 안심과 구체적 근거 / 기관: 절차와 책임).
3. `05.outputs/content_<유형>_YYYYMMDD_HHMM.md`로 저장하고, 필요하면 `docx`·`pptx`·`pdf` 스킬로 변환합니다.
4. 바로 아래 `check`를 실행합니다.

## calendar

S05의 시즌 캘린더(신학기, 시험 전, 방학)와 학사일정을 기준으로 앞으로 8주 콘텐츠 일정을 표로 만듭니다: 주차, 주제, 대상, 형식, 채널, 근거 산출물, 담당.

## check <파일> — 게시 전 점검

| 점검 | 기준 |
|------|------|
| 효과 주장 | 수치·"향상" 표현마다 E19·E17 또는 공개 출처가 있는가. 없으면 삭제하거나 정성 표현으로 |
| 과장 | "100%", "최고", "보장" 같은 단정 표현 |
| 전환기 표현 | 전환기 데이터를 쓸 때 개인의 '격차·뒤처짐·부족·미달', '선행학습', 불안 조성 표현이 없는가 (KG 전환기 데이터는 문서상 연계 지표) |
| 아동 대상 표현 | 아동에게 직접 구매를 권하는 문구, 불안 마케팅 [확인 필요: 아동 대상 광고 규정] |
| 개인정보 | 실제 학생·교사 이름·사진·후기 사용 시 동의 여부 |
| AI 표시 | AI 생성 콘텐츠·이미지 표시가 필요한가 (E13 d9) |
| 사실 일치 | 기능·가격·요금제가 E06·S03과 같은가 |

결과를 파일 끝 `## 게시 전 점검`에 남깁니다.
