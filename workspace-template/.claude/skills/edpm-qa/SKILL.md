# edpm-qa

학습 효과·교사 파일럿 검증은 E16·E17이 맡고, 이 스킬은 **제품이 명세대로 안전하게 동작하는가**를 확인합니다.

## plan → B06

1. 게이트: E09, E10 확인.
2. E09의 Given/When/Then 인수조건마다 TC-001을 만듭니다. 기능 하나에 정상·경계·오류 케이스를 최소 1개씩.
3. 역할별로 나눕니다: 학습자 / 교사 / 보호자 / 기관 관리자 / 운영자. 권한 위반 케이스(교사가 다른 반 학생을 볼 수 있는가, 보호자가 다른 아이 리포트를 볼 수 있는가)를 반드시 넣습니다.
4. 에듀테크 예외 상황을 추가합니다: 전학·반 변경, 학기 종료와 데이터 이월, 공용 기기 로그아웃, 보호자 동의 철회, 만 14세 생일 경과, 학교망 차단·저속, 시험 기간 기능 제한(있다면).
5. 비기능: 접근성(키보드, 대비, 대체 텍스트, 확대), 학기 초 동시 접속 부하, 개인정보(로그·URL·응답에 식별 정보 노출 여부), 저사양 기기 호환성.
6. 각 TC에 자동화 여부를 표시하고 `03.docs/B.구현/B06_테스트시나리오.md`에 씁니다. 표 도구가 필요하면 CSV(`05.outputs/tc_YYYYMMDD_HHMM.csv`)도 만듭니다.

테스트 데이터는 가상·가명 계정만 씁니다.

## run

| 방식 | 언제 | 방법 |
|------|------|------|
| `--auto` | 웹 화면 E2E가 반복될 때 | `webapp-testing` 스킬(Playwright)로 TC를 코드화해 실행. 테스트 코드는 회사 저장소 규칙에 따르고 경로를 B07에 기록. AI 챗봇·튜터는 답 품질을 `/edpm-eval`(`ai_eval.py`, 골든셋·시나리오셋)로 채점하고, 화면 E2E(질의 입력·응답 표시·스크린샷)는 같은 `webapp-testing`으로 실행 |
| `--aside` | 배포 직후 역할별 빠른 확인 | Aside 레시피 R05(스모크), R06(접근성)을 `/edpm-collect`로 실행 |
| `--manual` | 사람이 봐야 하는 항목 (교육적 흐름, 문구, 연령 적합성) | TC 체크리스트를 `05.outputs/qa_manual_YYYYMMDD.md`로 만들어 결과를 기입받음 |

실행 결과 원본(로그, 스크린샷 목록, 체크리스트)은 `01.자료실/데이터/qa_YYYYMMDD_*`로 보관합니다.

## defects

실패한 TC에서 결함 DF-001을 만듭니다: 심각도(출시 차단/높음/보통/낮음), 관련 F-ID·TC, 재현 절차, 기대·실제 결과, 증거 위치. 회사 이슈 트래커로 옮길 CSV나 `gh issue create` 초안을 만들고, 실제 생성은 승인 후 합니다. 개인정보 노출·권한 위반은 기본 심각도를 "출시 차단"으로 둡니다.

## report → B07

실행 요약(우선순위별 통과/실패/차단), 결함 현황, TC 커버리지, 접근성·성능·개인정보 점검 결과, 출시 권고를 씁니다. 실체 검증: 실행 기록 경로가 있어야 `done`이 됩니다. 출시 차단 결함이 남아 있으면 E15 릴리즈 판단에 보고합니다.
